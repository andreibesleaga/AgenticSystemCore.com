1. Terms of the specification (spec/00 §0.2)

  • Bundle — one directory tree of Markdown items plus exactly one agsc.config.json; the unit of publication and of conformance. (AGSC-00-04)
  • Item — one .md file with YAML frontmatter whose type is one of concept, episode, procedure, lesson, cluster, gate. "Item" is a term of this specification only; no common superclass exists in the ontology (§05). A published item is one that is neither draft nor held back by the releases switchboard (AGSC-01-20); a listed item is a published item that is not retired. A retired item is published — it keeps its page, its per-item copies, its place in the graph exports (AGSC-11-22) and its resource on the local tool server (AGSC-09-14b) — and is not listed: it leaves search.json, /llms.txt, /llms-full.txt, /chunks.jsonl, the skill packs, agsc-counts, the index pages that list items (a type's, a tag's, a cluster's members, the home page and the search page), every composition selection and what the page tools see (AGSC-09-16). A rule that names "the published set (AGSC-06-30)" means the listed set. The local tool server of AGSC-09-13 is not a published surface: it reads the author's own Bundle, draft and held-back items included. (Amended 2026-10-02 for 1.0.0: "published" had these two extents and no definition.) (Amended 2026-10-06 for 1.0.0: the index pages are named among what a retired item leaves; until 1.0.0-rc.6 the reference engine also dropped its page, its per-item copies and its graph entry, against AGSC-11-22.) (Amended 2026-10-10 for 1.0.0: the lists of what a retired item keeps and leaves did not name the tool server's resources, /llms-full.txt or the page tools, and the local tool server, which reads drafts, was not set apart from the published surfaces) (AGSC-00-05)
  • Concept (with a kind qualifier), Episode, Procedure, Lesson, Cluster, Gate are the six item types. Link, Source, Proposal, Review, Bundle, Harness complete the ubiquitous language; Proposal and Review have no file (they are a forge pull request and its verified[] evidence), Source is an inline sources[] entry, and a Harness is generated output only. The rules also use the terms below, each defined once here; none of them is a type, a schema key or an ontology term. A mode is a way of using one Bundle: no mode adds a type, a key or a term, and a conformance claim names a Level (§10), never a mode. (AGSC-00-06)
  • Mode 0 — the auto-wiki: Markdown items built into a site with a graph, search, the agent-facing text files and a discovery document, with no model anywhere (§6). The agent lane of AGSC-00-19 is optional in every mode. (AGSC-00-06)
  • Mode 1 — distributed agentic memory: agents read a node through the local tool server or the page tools (§9) and change it only by Proposals that a person ratifies (§8); nodes federate on the client side (§11). (AGSC-00-06)
  • Mode 2 — live specifications and engineering memory: Concepts of kind principle, decision, spec, task and term, with gates and episodes, joined by the five Mode-2 Links implements, verifies, covers, blocked-by and decided-by (AGSC-03-01), and read as boards in project mode (§10.5). (AGSC-00-06)
  • Mode 3 — the evolving skills wiki: Procedures exported as one skill pack per cluster (§7.4), and lessons kept as the record of failures. (AGSC-00-06)
  • Mode 4 — runnable knowledge: a composition of Concepts yields a Harness (§7). (AGSC-00-06)
  • Mode 5 — the live board of AGSC-00-19 and §10.6. (AGSC-00-06)
  • Persona — one of the people and agents the requirements document describes, numbered P0 to P15 (docs/PRD.md §1). A rule that names a persona names a reader a node serves; it binds no persona. (AGSC-00-06)
  • Forge — the service that hosts the Bundle's git repository and runs its pull requests, rulesets and continuous integration. The reference distribution ships a forge shim for GitHub only (AGSC-08-12, AGSC-00-20). (AGSC-00-06)
  • Content branch — the branch of the Bundle's repository that a node is built and published from. Continuous integration never commits to it, except for the channel:auto merge of AGSC-08-26 (AGSC-08-02), and the tool server hands its changes to it as Proposals and never writes to it (AGSC-09-14b). (AGSC-00-06)
  • Namespace document site — the one origin that the w3id redirects of AGSC-06-06 resolve to, https://agenticsystemcore.com/. It serves this specification's vocabulary, JSON-LD context and schemas under /ns/ and its pages under /specs/; a content node does not serve those routes (AGSC-06-01). (AGSC-00-06)
  • Launch pipeline — the ci and review lanes and everything they call; AGSC-08-27 keeps every model call out of it. (AGSC-00-06)
  • refs[] — on an Episode (AGSC-02-14), an optional list of distinct http: or https: URLs of what the occurrence concerns, such as a pull request, an issue or a run log. It is kept as authored; it makes no Link, and no rule derives anything from it at 1.0. (AGSC-00-06)
  • Private names — urn:agsc: (the source forms of AGSC-02-10 and AGSC-08-28) and memory: (the alias of AGSC-05-04…05-04b) are names private to this specification: the URN namespace agsc is not registered under RFC 8141 and the URI scheme memory is not registered under RFC 7595. Each is never dereferenced over a network and means only what the rule that uses it says. (AGSC-00-06)
  • NOW is generated context, never an item and never hand-edited. (AGSC-00-07)
  • Card, page, deck and note are UI or import vocabulary; they MUST NOT appear as a type, a schema key or an ontology term. (AGSC-00-08)
  • Agent lane and live board complete the language for Mode 5. An agent lane is the OPTIONAL, configured capability by which a model-driven or programmatic agent creates, edits, reviews and updates items non-deterministically — always as Proposals, never as writes (AGSC-01-36, AGSC-08-28…30). A live board is a Bundle used as the shared working memory and pull-based task board of people and agents, local or remote: work is pulled by whoever claims a task, at most max_claims at a time, until the board is done (AGSC-10-16…18). The name says what it is — a board that is live, shared and always current; its operating discipline is Kanban's pull with a work-in-progress limit, and the blackboard architectural pattern (Hayes-Roth 1985, Nii 1986 — docs/RELATED-WORK.md) is its lineage. Neither adds a type, an item key or an ontology term; both are realised entirely with the objects §0.2 already names. (AGSC-00-19)
  • Declared scope by version. The whole of this specification's scope is named here with the version at which each part becomes normative, so that a reader of any version sees the whole and a conforming tool never claims more than its version specifies. (AGSC-00-20)

2. The fourteen Link keys (AGSC-03-01)

related · broader · narrower · uses · requires · excludes · derived-from · contradicts · supersedes · implements · verifies · covers · blocked-by · decided-by

Of the core nine, uses, requires, excludes, contradicts and supersedes carry composition semantics (spec/03 §3.5); related, broader, narrower and derived-from never change a composition (AGSC-03-18), and the Mode-2 five (implements, verifies, covers, blocked-by, decided-by) are navigational and provenance edges. Inverses are computed, never authored (spec/03 §3.2).

4. Boundary vocabulary (spec/11)

  • Surface — an agent-facing entry a node serves and declares: llms-txt, chunks, mcp, webmcp, a2a-card, solid, responder (AGSC-11-16).
  • Access class — what a reader needs before invoking a surface: none, consent, credential (AGSC-11-16).
  • Visibility — public or restricted (AGSC-11-20); the discovery document is readable at both.
  • Contribute mode — pr, channel or form (AGSC-11-14): where a proposal from anyone goes.
  • Peer — another node named by its canonical well-known URL (AGSC-11-06); checked mutually, never fetched at build.
  • Walk — a client-side traversal of peers bounded by hop_limit, fan_out and max_requests (AGSC-11-10).
  • Origin marking — every peer-derived result carries trust: untrusted and the peer Bundle IRI (AGSC-11-11).
  • Tombstone — the state of a node that stopped publishing: a valid link set with agsc-tombstone (AGSC-11-23).
  • Retired — an item status that keeps the IRI, the page, the per-item copies and the graph entry, and leaves the indexes, the agent text files, the chunks, the skill packs and every selection (AGSC-11-22, AGSC-00-05).
  • Plugin contract — declare · pin · inherit · prove (AGSC-11-16…19).
