Scenarios

SummaryThe behaviour of the system written as scenarios, one feature file per persona, in the Given/When/Then form of behaviour-driven development. Each scenario names the requirement it proves.

Each feature file listed below has a page of its own and is a frozen artefact of the project's requirements phase, published here for the specification version this site publishes. The scenarios are written so that every step is executable: a concrete command, a route, a tool call or a file, never "the system behaves correctly". Tags of the form @PRD-nnn link a scenario to a row of the requirements page; a few steps name rules of the specification.

The scenarios describe the reference engine and the content site at general availability. Where a scenario names a surface that this Level-0 site does not serve as a page, the status page says what is live today: the local tool server (agsc mcp) is not a page of this site; the combiner page and the skill packs are.

P10 port implementer: one scenario writes a Level-0 node without the engine and judges it with the shipped checker alone; a second runs the Python checker package over the same tests/vectors/ as the engine's conform and compares the two reports vector by vector; a third reads the reference engine's own Level-3 report. The second one runs wherever that package's checkout sits beside the engine and a Python 3.9+ interpreter exists, and is reported as skipped, with the reason, where it does not (its pending file under tests/acceptance/pending/ is of class conditional, and tests/acceptance/steps/_python-package.js probes for the checkout and the interpreter). The shared vectors themselves remain the port's full acceptance (spec/09-conformance).

The feature files

  • persona-0-dropin.feature: Drop-in user — plain Markdown becomes a live ontologic wiki
  • persona-a-reader.feature: Human reader finds a pattern with evidence
  • persona-b-contributor.feature: Human contributor fixes a page and passes a hard review gate
  • persona-c-agent-mcp.feature: Agent reader queries structured knowledge without scraping
  • persona-d-agent-proposer.feature: Agent proposer contributes a change humans ratify
  • persona-e-architect.feature: Architect turns Concepts into a starting architecture
  • persona-f-integrator.feature: Integrator installs this knowledge into my agent
  • persona-g-team.feature: Project team keeps its agent-built specs governed
  • persona-h-memory.feature: Agent uses a node as external auditable memory
  • persona-i-maintainer.feature: Maintainer-as-operator keeps the site green with zero maintenance
  • persona-j-standards.feature: Standards implementer adopts the discovery format on their own site
  • persona-k-live-board.feature: Self-driving team — agents and people finish a project's tasks on one live board
  • persona-l-port-implementer.feature: Port implementer proves a second implementation conforms
  • persona-m-security-reviewer.feature: Security reviewer audits a node and its engine from evidence they can re-run
  • persona-n-researcher.feature: Researcher measures a node offline and cites exactly what was measured
  • persona-o-restricted.feature: Restricted publisher tells the world the node exists while its content stays gated
