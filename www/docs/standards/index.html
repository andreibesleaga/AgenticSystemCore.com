Related work

1. One sentence

Agent discovery finds who can act; knowledge discovery finds what is known. Every mechanism in the agent-discovery space catalogued below discovers an actor or an endpoint — an agent, a tool server, a service. This specification discovers a described, integrity-checked body of knowledge: a static Bundle of Markdown items with a typed graph, a discovery document that is an RFC 9264 link set, and digests on every artefact it points at. The two are complementary, and the survey that catalogues the former (draft-jimenez-dawn-discovery-landscape-00, 3 July 2026) never mentions RFC 9264 link sets and names no mechanism for the latter.

3. The agent-discovery mechanisms, and why none of them is this

The DAWN landscape survey (Jimenez, Feng, Arkko, Kühlewind, Kandoi — Ericsson; draft-jimenez-dawn-discovery-landscape-00, 3 July 2026) catalogues the field. Its own scope statement is discovery of "entities (agents, tools, services) and … their capabilities". The mechanisms, with this specification's reading of each:

None of these discovers an integrity-checked knowledge bundle with a typed graph, and none uses an RFC 9264 link set. Two further mechanisms discover a single context file — draft-arsentev-llm-context-discovery-00 (2026-09-11; well-known suffix and link relation llm-context, both requested from IANA, pointing at a publisher-curated file such as /llms.txt) and llms.txt v2 itself (2026-08-10; rel="describedby" to the file) — and one discovers agentic resources (Agentic Resource Discovery, below). None of those three carries digests over a set of artefacts, a typed graph, or a link set. One further neighbour does carry a digest per artefact in a well-known index — Cloudflare's Agent Skills Discovery draft (§4) — for Agent Skills only, with no link set, no graph and no registration request. That narrower gap is the one this specification fills, with registered building blocks rather than a new media type. No further link relation: the discovery link is the registered describedby with type="application/linkset+json", the profile URI carries the refinement, and the Internet-Draft requests one registration (the suffix) and records the fields of the profile URI, whose registration is to be requested separately. The link set can in turn point at any of these neighbours through related-system links (AGSC-06-35).

5. What is new here, stated as properties

1. A knowledge base is discoverable by a path built from standard mechanisms (a well-known URI whose registration is to be requested, the registered link relation describedby, and a profile URI whose registration is to be requested), with RFC 9530 digests on every artefact, and no new media type. 2. Every machine artefact is byte-deterministic across implementations (AGSC-04-24), which no wiki, catalogue or memory protocol above claims. 3. Federation is static and client-side — nodes never call nodes — with a bounded walk, a mutual-conformance check and cross-node citation instead of cross-node links (spec/11 §11.3). 4. Every agent surface is a declared plugin under one contract — declare, pin, inherit, prove (spec/11 §11.4) — so an external draft moving does not move the core. 5. The agent-retrieval chunk export (AGSC-06-26…31) gives agents stable, citable, pre-split units with provenance, without embeddings.

These are property claims about the specification's text and vectors, not performance claims.
