Requirements: notes

SummaryThe notes the requirements document appends after its requirements: how later rows read beside the frozen ones, and what holds at each version.

The second page of the requirements, rendered as the document stands in the engine repository.

The compatibility section and the content version

Two capabilities added at 1.0.0-rc.6 add no requirement id: both are discharged by requirements this document already carries.

A compatibility and plugin section (spec/00 §0.6, AGSC-00-21…25). It states in one place what a tool does with a construct this specification does not define, what survives a round trip through lint --fix, export --markdown, an adapter and an import, what a tool may never originate, the closed list of eight plugin kinds with what each may read, may emit and may never do, and three names reserved to 1.1 — weights (weighted Links), routing (model-routing declarations) and executable (an executable Harness with its optimisation step). It serves PRD-002 (the format a reader must accept), PRD-026 (lossless export and import) and PRD-055 (Levels and platform adoption), and it mints no error code: every fault it names takes a code the registry already holds.

A content version (spec/04 §4.9, AGSC-04-25), bundle_version: one short, human-readable name for the state a build published or a consumer saved, derived from the git history and the build instant, never authored and never counted by the engine. It serves PRD-008 (version and changelog agreement) and PRD-024 (the discovery document's bundle facts), and it is what a citation, an imported item and a reader of /now/ need and cannot get from the bundle hash, which says only whether two retrievals carry the same bytes and never what the publisher calls them. import records prov.source_version and prov.source_hash on every item it writes (PRD-042, provenance on every item) and refuses a source whose spec_version MAJOR it does not implement unless the adapter's own --allow-newer flag is passed; a source of a newer MINOR of the same MAJOR is imported with a warning (AGSC-01-22).

PRD-044 at 1.0

Note to PRD-044. The row names a weekly refresh --auto that re-checks staleness and external links. At 1.0 there is no --auto flag (AGSC-09-09's closed flag list does not name one; refresh takes --agent <name> with --dry-run), and no lane of the reference engine reaches the network: its network port refuses every call with AGSC-E905. So at 1.0 staleness is reported offline — the NOW page of every build lists the items whose stale_after has passed — and no external link is fetched. The row's other promises stand: at most one issue, never a commit.

Notes to further rows (the rows above stay as written)

Note to PRD-037 and PRD-049. The six runtime renderings of a Harness (AGSC-07-18: gabbe, kaiban-distributed, crewai, langgraph, adk-msaf, n8n) and the forge shims for forges other than GitHub (PRD-049) ship at 1.1. At 1.0 the emitter names are registered and refused with the registry's code (AGSC-E203), and the GitHub shim is the one forge shim; Amendment 6's "v1.x reads as v1.0" does not reach these two rows.

Note to PRD-047 and NFR-10. The REUSE layout is not adopted at 1.0. The licences are stated by LICENSE, LICENSE-CONTENT, NOTICE, the license field of package.json and the SPDX header of every browser script; "REUSE green" is not claimed. A REUSE layout is a 1.1 item. (Amended for 1.1.0: adopted — REUSE.toml and LICENSES/ at the root, reuse lint compliant with REUSE 3.3; docs/ENGINEERING.md §7.) (Note of 2026-11-11: "every browser script" excludes the vendored query engine of /query/, third-party code served with its upstream bytes and no SPDX header; docs/COMPLIANCE-CROSSWALK.md.)

Note to PRD-026. The acceptance "Bundle opens as an Obsidian vault" is read as: the content directory is plain Markdown files with relative links and YAML frontmatter, which any vault-style editor opens; no test asserts a particular editor. JSON-LD and JSONL are export-only at 1.0 (export --jsonld, export --jsonl); the round trip the row names is Markdown/OKF.

Note to NFR-12, in plain words. The system carries no framing that presents a node as an ordered reading or as a supplement to another publication, and no whole-corpus PDF/EPUB emitter (AGSC-06-03, AGSC-08-17). The parenthesis in the row names a list held outside every repository; a reader needs only the two rules.

Note to §1, persona P10. features/persona-l-port-implementer.feature names the port implementer in two scenarios: a Level-0 node written without the engine passes the shipped checker, and the Python checker distribution runs the shared vector set beside the engine's conform and the two reports are compared case by case. That distribution's own test suite runs the shared vector set over seven of the nineteen areas natively and reports the rest as not run by that package (AGSC-09-02, AGSC-10-15).

Note to PRD-009 (what init writes at 1.0). In an empty folder agsc init writes four files — agsc.config.json, content/index.md, .gitignore and .env.example — and takes no flags of its own. It writes no example Concepts, no type folders and no forge workflow; a Gate's workflow is compiled by ci into dist/forge/ (AGSC-08-12), not by init. ci passes only after the publisher adds .well-known/security.txt with a Contact: line and commits once or sets SOURCE_DATE_EPOCH, the three steps init prints on its way out (AGSC-02-94, AGSC-06-36, AGSC-04-09). Example content and a scaffolded workflow are not in the declared scope of any version (AGSC-00-20), so they are not planned; the row's acceptance "ci passes unedited" does not hold at 1.0.

Note to PRD-056 (channels at 1.0). What exists at 1.0 is the specification of channels (AGSC-01-30 to AGSC-01-33, AGSC-08-26), the channels[] configuration keys and the channel-adapter plugin kind (AGSC-00-24). No channel adapter ships, there is no refresh --ingest option and no reference stub, and the engine's channel-adapter hook covers carrying a Proposal to a review lane, not ingest (docs/PLUGINS.md §1). The ask half is the ask tool of the local tool server and the page tools (AGSC-09-13, AGSC-09-16), which returns the best-matching items with their addresses and calls no model. The ingest stub and the first adapters are not in the declared scope of any version (AGSC-00-20), so they are not planned.

Note to the scope cells that Amendment 6 reads as v1.0. Amendment 6's sentence "scope cells reading v1.x/should above READ AS v1.0" does not reach these cells, which stay as follows:

  • PRD-022, RDF/XML: not emitted at 1.x; build.rdfxml is reserved to 1.1 and refused at 1.0 with AGSC-E004 (AGSC-05-06, AGSC-01-18, AGSC-00-20).
  • PRD-026, "Mem0/Letta/Zep/CSV": no adapter of those names ships (export --to csv and --to mem0 are AGSC-E203); memories reach Mem0, Letta and Zep through the COGX archive that Cognee reads (export --to cogx, docs/CONNECTORS.md). Direct adapters and CSV are not planned for a version. Added 2026-11-09: settled on 9 November 2026: the direct adapters for Mem0, Letta, Zep and CSV, and for Basic Memory and Claude Code's memory files, ship in 1.1 as capabilities of the reference distribution under AGSC-01-26a (a MAY), and AGSC-00-20 is amended the same day. Until they are in the tree the two sentences above describe the engine; no rule and no case changes. Added 2026-11-09, later the same day: they are in the tree, stated as PRD-070: the six adapters write and read files only and reach no network (AGSC-00-24), so a person moves the files to and from Mem0, Letta and Zep with each tool's own client.
  • PRD-033, "Cursor/Copilot/Gemini/Codex/GABBE" and the <site> argument: skills install writes the three trees .agents/skills, .claude/skills and .github/skills from the local Bundle (AGSC-07-21) and refuses a URL with AGSC-E003; GABBE is reached by export --to gabbe. Other install trees and installing from a site are not planned for a version.
  • PRD-048, "PyPI/GHCR/Homebrew/Nix": the engine is published on npm only. The PyPI package agentic-system-core is the independent Python checker, not the engine. No container image, Homebrew formula or Nix package is planned for a version.
  • PRD-041, "LLM review: v1.0": the optional review lane is specified (AGSC-08-27) and off by default; no model client ships with the reference engine, so review is lint-only.
  • PRD-010, "/conformance/: v1.x": the public conformance page is a 1.1 item (AGSC-00-20).

Note to PRD-011 and PRD-052 (/about/). The reference engine emits the fixed route set except the routes a node authors or that no rule pins: /about/ is authored and conditional (AGSC-06-01, AGSC-06-24), and build names it among its skipped routes ("this page is authored, not derived"); /specs/ is the specification site's. A node that publishes /about/ carries the per-persona Quickstart of PRD-052 there, as the main site does; a node that emits no /about/, such as the demonstration node, has no Quickstart page; the engine's guides (docs/guides/) give the same paths.

Notes to other statements that no longer match what was delivered.

  • §4 (non-goals), "bench is the v1.0.1 gate … the only verb off the GA path": bench is not a verb (agsc bench is AGSC-E001); the benchmark kit is the program tools/bench with bench/measure.js, and AGSC-00-20 makes it normative at 1.1.
  • §4, "No functional PyPI wrapper (v1.x)": the non-goal stands for the engine. The working PyPI package is the independent Python checker (PRD-054), not a wrapper of the engine.
  • The Goal line, PRD-021 and PRD-013: the patterns of the retired site are not published on agenticsystemcore.com. A selection of 22 pattern Concepts in 20 Clusters is published on the demonstration node, patterns.agenticsystemcore.com; the counts "153 cards", "66 render, 87 dark" and "153 compile" describe the retired site's corpus, which import --from old-site converts.
  • PRD-053, the scope note: adoption is part of plain init, which takes no flags, and a host's configuration is written by agsc-host emit <profile>; init --adopt and init --host cloudflare are unknown options (AGSC-E002).
  • PRD-053, "≤3 commands … ci green": two steps come between init and a passing ci — the security contact .well-known/security.txt and one commit (or SOURCE_DATE_EPOCH), as the note to PRD-009 says; README.md and docs/USE-CASES.md (L5) give the full path.
  • PRD-045, restore-from-zero: the clone-and-rebuild half holds (ci builds twice and compares the bytes; a fresh clone plus ci reproduces www/). The per-release archive deposit is the Zenodo record of the software, one version per GitHub release (concept DOI 10.5281/zenodo.23233817; on 2026-11-11 it holds v1.0.0-rc.7, 1.0.0 and 1.0.1); the specification archive and the paper are the separate record 10.5281/zenodo.23052709, with deposits for 1.0.0-rc.6 and 1.0.0. A release with no deposit is kept by its tag. A git mirror and a weekly attested snapshot are not in place at 1.0.0; they are planned for later, with no version fixed.
  • PRD-062, "ETag equal to the artefact digest": AGSC-11-05 requires an ETag on every public artefact and fixes its value only where the writer sets it; a static host sets its own entity tags, so a reader takes integrity from the digest of the discovery document (AGSC-06-08), never from an ETag.

Note to Amendment 9: why the Node floor is 22.13.0. Node 22.12.0 prints a warning on standard error whenever the engine requires one of its ES-module libraries, and a warning there breaks the MCP server's clean-stderr contract; 22.13.0 is the first 22.x release that prints it only on request. The development gates (the linter) need 22.13.0 as well. package.json, the CI matrix and a test that keeps the two equal carry the floor.

Notes at 1.0.0 (2026-10-10)

The rows, the amendments and the notes above stay as they were written. These notes say how some of them read at 1.0.0; where one of them and an earlier note differ, the note here governs.

Note on the capabilities planned for 1.1. Eleven capabilities of the reference distribution are planned for 1.1 (AGSC-00-20):

1. an ingest stub and channel adapters (PRD-056); 2. init writing example Concepts, type folders and a forge workflow, with the options init --forge and init --host (PRD-009, PRD-053); 3. direct memory adapters for Mem0, Letta, Zep and CSV (PRD-026); 4. installing skill packs into other agents' install trees, and installing them from a published site (PRD-033); 5. distribution through GHCR, Homebrew and Nix, and a PyPI wrapper of the engine (PRD-048, §4); 6. a git mirror and a weekly attested snapshot of a node (PRD-045); 7. a model client for the review lane (PRD-041); 8. narrate, a model-written narration of a composition, run on the reader's own key (§4 rules out a server-side one); 9. memory adapters for Basic Memory and for Claude Code's memory files; 10. running the engine's library on Deno, Bun and Cloudflare Workers; 11. a model adapter for the agent lane (PRD-063).

They are capabilities of the reference distribution, not parts of the format: no version requires a tool to ship them, and no conformance claim depends on them. They wait for 1.1 because each one adds behaviour, and 1.0.0 adds no behaviour beyond a defect fix. So where a note above says of one of them "not planned", "not in the declared scope of any version", "not planned for a version" or "planned for later, with no version fixed", or that no container image, Homebrew formula or Nix package "is planned for a version", read "planned for 1.1". §4's "No functional PyPI wrapper" and the note that keeps that non-goal for the engine read the same way: at 1.0 the PyPI package is the independent Python checker, and a wrapper of the engine is planned for 1.1.

(Reconciliation, 2026-11-11, for 1.1.0: AGSC-00-20 as amended for 1.1.0 governs. The direct memory adapters (items 3 and 9) ship in 1.1 as capabilities of the reference distribution under AGSC-01-26a; the other nine, and the model-adapter plugin kind named below, are planned for a later MINOR, so wherever this document says "planned for 1.1" of one of them, read "planned for a later MINOR".)

Note to PRD-063 (a live run of an agent lane at 1.0). The Mode 5 note above says that the engine implements the agent lane, "channels, refresh" included. At 1.0 the reference engine ships no model adapter and no channel adapter: refresh --agent <name> runs only with --dry-run, which writes the Proposal the lane would open, with the Episode of the run, and calls no model; without --dry-run the verb refuses. A live run is made by an agent outside the engine — Claude Code, a script — as a client of the local tool server (agsc mcp) or of the page tools, under the rules of the lane it runs as (AGSC-08-28 allows both routes); the gating lanes stay model-free. The model adapter for the agent lane is planned for 1.1 (the note above). A model-adapter plugin kind beside the eight of AGSC-00-24 is a candidate for 1.1, since a new plugin kind is a change of the specification.

Note to PRD-027 and §4 (memory:// at 1.0). The row's "not resolve it", its acceptance "Alias-only; no resolver", its version cell "(resolver: v2)" and §4's "memory:// = documented alias only" read as follows at 1.0: the command line and the local tool server resolve memory://<bundle-id>/<slug> to the item when <bundle-id> is the Bundle's own bundle.id, and refuse another Bundle's id with AGSC-E309 (AGSC-05-04b; the cases graph-0005 and cli-0015). The alias is never dereferenced over the network and never emitted as an RDF subject (AGSC-05-04), and the https:// IRI may always be used instead (the note to PRD-027 above).

Note to NFR-03 (the coverage bar at 1.0). The bar that continuous integration enforces on src/ is higher than the row's 99 % of lines: lines 99.9 %, functions 99 % and branches 93 %, the thresholds of npm run test:coverage, which runs inside a check every pull request must pass (test (ubuntu-latest, Node 24)). CONTRIBUTING.md states the same three figures. The row's "no requirement without a test" is checked by node tools/requirements-matrix --check. Read "coverage ≥99%" in §5's definition of done the same way.

Note to §5, the definition of done at 1.0.0.

  • Item (1), "persona walkthroughs (a)–(j)", reads as one walkthrough for each persona of §1 and §1.1: the feature files persona-0 and persona-a to persona-o under features/ (P0 to P15), which the acceptance runner executes, a scenario that needs a forge, a model or an outside service being listed as pending with its reason; with them, the six mode walks of tests/e2e/modes/ and the runs of the guides and the demos (tests/docs/).
  • Item (2): the coverage figure reads as the note to NFR-03 says.
  • Item (4), the benchmark kit run on real data with its results and datasheet on Zenodo, is 1.1 work, when AGSC-00-20 makes the kit normative. At 1.0.0 the measurement half runs (bench/measure.js, recorded in docs/MEASUREMENTS.md), and the kit's study belongs to the tools/bench program. Item 1 of "Resolved at review", "published benchmarks are a v1.0.1 gate within 30 days of launch", reads "published benchmarks are 1.1 work"; there is no bench verb and no 1.0.1 gate.
  • Item (6), "a DOI for each release": the software's Zenodo record (concept DOI 10.5281/zenodo.23233817) gets a version for each GitHub release, as the note to PRD-045 says. The Internet-Draft is an individual Internet-Draft.

Note to §1, persona P10 (the areas at 1.0.0; 2026-10-11). The note to persona P10 above says that the Python checker distribution runs "seven of the nineteen areas". At 1.0.0 the shared vector set has twenty populated areas, the export area having been added; the Python checker distribution runs the same seven of them natively and reports the other thirteen as not run by that package.

Note to §1, persona P10 (1.1; 2026-11-11). At 1.1 the Python checker runs the same seven areas natively, at the parity of the 1.1 engine. It does not check the domain layer (PRD-076): the cases of the layer in those areas are reported not run, with that reason. A port implementer whose node uses the layer proves it with the engine's conform or with a runner of their own.
