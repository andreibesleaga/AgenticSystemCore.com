AGSC-09 — Conformance: classes, vectors, error codes, CLI contract

SummaryHow a claim is made and checked: classes and Levels, the vector format, the command-line contract, the error-code registry and the independent validators.

Status of this document

Specification 1.1.0, released and tagged on 2026-11-13. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

Part 1 of 3, 9.1 to 9.3. This section is published in three parts so that each page stays within the budget of AGSC-06-21; a rule's link names the part that carries it. Part 2 carries 9.3 (continued) to 9.4; Part 3 carries 9.4 (continued) to 9.9.

In plain language

Classes and claims. Reader, writer, full engine; a claim names the class, the version and the vectors passed.

Vectors. One JSON file per test case under tests/vectors/<area>/, with an input, an expected result and the rule it proves. Twenty-five areas exist; a required vector that is skipped counts as a failure. Withdrawn vectors are kept for history and never run.

The CLI. Sixteen verbs, a JSON envelope on every result, exit codes with fixed meaning, no stray output on the tool channel. The local tool server exposes exactly ten tools.

Error codes. AGSC-E<nnn> in blocks by area (0xx CLI, 1xx parse, 2xx schema and boundary configuration, 3xx links, 4xx lint, 5xx provenance and adoption, 6xx canonicalization and determinism, 7xx ledger, 8xx composition, 9xx I/O and federation), registered once each; every code used has a registry row that names the rule that raises it.

Validators. A reference distribution ships standalone validators for the spec text, schemas, ontology, vectors, discovery file, features and diagrams, plus four generators — eleven command contracts in all (AGSC-09-90) — so that an independent party can check every normative artefact.

This box explains; the rules below decide. New to the notation? See how to read the specification.

9.1 Classes and claims

  • AGSC-09-01 The claim, in full. A conformance claim MUST state each of the following, and this rule is the one complete list: (a) the implementation and its version; (b) exactly one Level — AGSC-10-01 is the single statement of the class-to-Level mapping and AGSC-10-15 of the vector set a Level runs, and the class names of AGSC-00-09…11 are the Levels' names and nothing more; (c) the full spec_version whose vectors were run, a release candidate named as such; (d) the vector set: the areas run, listed in the fixed order of AGSC-10-15, how many of their cases ran and how many passed, and every required case that failed or was skipped, by id (AGSC-09-02, AGSC-10-15); (e) the Unicode version of the runtime (AGSC-04-22); (f) for a published node at Level 2 or 3, the deployment profile it emitted (AGSC-06-01); (g) every surface the node declares, each with the cases or the validator run that prove it (AGSC-11-19); (h) which checker implementation ran the cases, when the claimant did not run them with its own (AGSC-10-01). AGSC-00-12, AGSC-04-22, AGSC-06-01, AGSC-10-01 and AGSC-11-19 each require some of these elements and point here; where they differ, this rule settles it. The machine-readable claim checked by conform-0001 carries (b), (c), (e) and the areas passed as level, spec_version, unicode_version and vectors_passed; the report of AGSC-09-03 carries (a), (c) and every case's result; the published sentence carries the rest (docs/CONFORMANCE-STATEMENTS.md gives its wording). (Amended 2026-10-02 for 1.0.0: until 1.0.0-rc.6 this rule named the Level, the spec_version MAJOR.MINOR and the vector set, while four other rules each added an element; MAJOR.MINOR alone hid which set of a release candidate ran. No element is new.) (Amended 2026-10-29 for 1.1.0: the areas of a claim are listed in the fixed order of AGSC-10-15; no element is new) [PRD-010]
  • AGSC-09-02 A conformance run MUST execute every required vector of the declared areas and MUST report pass, fail or skip per vector id. A skip counts as a failure for a required vector — with one exception: a vector whose requires_surface names no surface the claimant declares (AGSC-09-04) is reported as pass, with a detail saying it was skipped because the surface is not declared. (Amended 2026-10-02 for 1.0.0: the two rules said "a failure" and "passed" for that case without saying which status is reported.) From 1.1 conform reports each required case that failed or was skipped as one finding AGSC-E005 with severity error, naming the case, and a withdrawn case, which counts for nothing (AGSC-00-16), as none, so that the exit code of the verb is 1 exactly when a finding exists; 1.0 reported the finding with the code of an unknown verb (AGSC-E001), which says nothing about a case. Vector conform-0006. (Amended 2026-10-29 for 1.1.0: a dedicated code names a failed or skipped case; the statuses and the counting are unchanged) [design]
  • AGSC-09-03 (reference distribution) A conformance-report.json MUST be producible by agsc conform as {impl, version, spec_version, class, results:[{id, status, got?}], summary}, and a node MAY publish it at /conformance/ together with a table of third-party claims. A published claim is the claimant's own assertion; this specification defines no arbitration. A claimant MAY additionally publish a rule-coverage matrix: for every rule id of this specification, the machine verifications that cite it — a vector's rule, a test, an acceptance scenario, a checker — or a stated reason why the rule is verified by review alone. The reference distribution MUST publish one, so that a reader can see which of this specification's rules are proved by the suite and which are not, without running it. No Level requires the matrix, and a published matrix is the claimant's own assertion, exactly as a published conformance report is. (Rationale: the matrix lets a reader tell a rule proved by a vector from a rule nobody checks; the obligation is named and the artefact is not, so no file name or byte is pinned.) (Amended 2026-10-10 for 1.0.0: marked (reference distribution) for the obligation on the reference distribution to publish a rule-coverage matrix) [design]

9.2 Vector format

  • AGSC-09-04 A vector is one JSON file under tests/vectors/<area>/ containing one object with members id, area, rule, level, description, input, OPTIONAL options, OPTIONAL reason (REQUIRED when level is withdrawn: why the case was withdrawn and which vector supersedes it), OPTIONAL superseded_by (the id of the vector that supersedes a withdrawn one, so that a machine follows the chain without reading prose; carried by every withdrawn vector that has a successor), OPTIONAL note (editorial provenance of an unreleased vector; never read by a conformance run), OPTIONAL requires_surface (an array of agsc-surface names: a vector that a claimant's node does not declare any of is skipped and counts as passed, so a Level-2 writer is never held to a Level-3 surface), and expected. Areas are frontmatter/, slug/, links/, jcs/, graph/, lint/, cli/, plus bundle/, prov/, ledger/, compose/, build/, discovery/, adopt/, import/, export/, skills/, adapters/, channels/, harness/, run/, conform/, and boundary/, chunks/, boards/ — twenty-five, and no others. webmcp/ is not an area: AGSC-09-16 is proved by cli/cli-0026, so a permanently empty declared area would be a false promise. adapters/, channels/ and harness/ are declared here so that the milestones that populate them need no spec_version change. (Amended 2026-10-29 for 1.1.0: the case that proves AGSC-09-16 is cli-0026, the successor of cli-0003, which is withdrawn because the tool server lists ten tools; no area is added) [design]
  • AGSC-09-05 rule MUST cite one rule id of this specification. level is required, optional or withdrawn (AGSC-00-16); a withdrawn vector MUST NOT be counted for or against any conformance claim, MUST carry reason, and MUST have expected reduced to {"withdrawn": true} so that a superseded expectation can never be read as normative. A negative vector's expected MUST carry the member error whose value is an AGSC-E<nnn> code, never a message; it MAY additionally carry severity, exit, stdout, line, cycle, chain or parents, and a vector asserting several outcomes MAY nest an error member inside a named sub-object (graph-0005) or list them as AGSC-09-11 finding objects under findings[] or results[], each carrying code (the same AGSC-E<nnn> value) and severity. Where an expected output carries the implementation's own version — the version member of an envelope (AGSC-09-11), as in cli-0002 — the value in the test case stands for the version of the tool under test, which a runner substitutes before comparing; options.version names the value the case was written with. A case's id prefix is its area's, except frontmatter-0030 and frontmatter-0031, which keep the longer prefix because an id is never renamed. (Amended 2026-10-02 for 1.0.0: how a port compares a version it does not share, and the two longer ids, were not said) [design]
  • AGSC-09-06 Vector files MUST be UTF-8, LF-terminated, NFC — except an input string whose non-NFC form is the subject of the case (jcs-0005, lint-0022), which a port MUST NOT normalise on load — I-JSON, with object members in JCS order (§04); they MAY be pretty-printed for review. They MUST be consumable without executing any code from this repository, so that a port in any language can run them directly. [NFR-02]

9.3 CLI contract

  • AGSC-09-07 The verb set is exactly sixteen: init, lint, build, verify, ci, export, import, compose, propose, review, refresh, skills, mcp, run, trace, conform. run and trace MUST be opt-in and disabled by default (AGSC-01-18 run.enabled, default false); conform executes the vector set of a declared Level (AGSC-10-01) and writes the AGSC-09-03 report. Any other verb MUST exit 2 with AGSC-E001. This rule binds the command-line interface of a full engine (the class of AGSC-10-01); a distribution that is not a full engine MAY ship a command of the same name that forwards the sixteen verbs to an engine and adds the command contracts of AGSC-09-90 as further verbs, and it MUST forward every other verb or refuse it with AGSC-E001 and exit 2. An implementation MAY ship further commands of other names beside the engine's command — for example one that puts a build on a host — provided none of them changes an artefact of AGSC-04-24 or a route of AGSC-06-01. What each verb takes, besides the flags of AGSC-09-09, and does is the table below; a positional argument it does not list is AGSC-E002 (AGSC-09-09), and a slug argument also accepts the forms of AGSC-05-04b. help is not a verb: agsc help is AGSC-E001 like any word outside the sixteen, and the text a person asks for with it is what the flag --help prints (AGSC-09-09), so the verb set stays closed. (Amended 2026-10-02 for 1.0.0: the table added; until then the positional arguments of most verbs, the sub-commands of skills, what review does and the six compose --emit names were stated nowhere or only in passing.) (Amended 2026-10-29 for 1.1.0: the table names the flags and the tool count that 1.1 adds, and says that help is the flag --help and not a seventeenth verb; the sixteen verbs are unchanged) [PRD-001]

  • AGSC-09-08 Exit codes: 0 success; 1 findings, a failed gate or a non-reproducible build; 2 usage error — an unknown verb (AGSC-E001, AGSC-09-07), an unknown flag (AGSC-E002, AGSC-09-09), a missing required argument (AGSC-E003), or invalid configuration, including a malformed SOURCE_DATE_EPOCH (AGSC-E603), which is an environment/configuration fault and never a finding; and a git history too shallow to derive the ledger (AGSC-E703, AGSC-08-20a), the other environment fault, which is reported as a finding and still exits 2. Invalid configuration is a configuration the tool cannot run against: a configuration file whose top level is not a JSON object, a configuration name it does not know or that is reserved to a later version, a spec_version MAJOR it does not implement, or a run or trace invocation while run.enabled is false (AGSC-E004, whose registry row lists every case); and a malformed SOURCE_DATE_EPOCH (AGSC-E603). A configuration value that breaks its key's schema is a finding (AGSC-E204 for a pattern or length bound, or the more specific code of the precedence in §9.4) and exits 1, as does a configuration file that is not well-formed JSON. (Amended 2026-10-06 for 1.0.0: AGSC-08-20a and the registry already gave AGSC-E703 exit 2; this rule did not list it, and the reference engine exited 1.) (Amended 2026-10-12 for 1.0.0: the rule did not say which configuration faults are invalid configuration; they are the faults of AGSC-E004, a configuration file that is not a JSON object and run and trace while run.enabled is false among them, and the malformed SOURCE_DATE_EPOCH of AGSC-E603; a configuration value that breaks its key's schema is a finding with exit 1, as the registry and the reference engine already have it. No behaviour changes.) [PRD-007]

  • AGSC-09-09 Global flags --json, --quiet, --plain, --no-input, --version, --help MUST be honoured, as MUST NO_COLOR and AGSC_* environment variables; a flag outside this list and outside the verb flags below is AGSC-E002 with exit 2 (AGSC-09-08), and so is a positional argument a verb does not define. Precedence is flags > environment > project configuration > user configuration; the environment includes the .env file of AGSC-01-37, read after the process environment, and every scalar configuration key has an AGSC_* name there.

    --help MUST print the verb set of AGSC-09-07 and this flag list to stdout and exit 0; with a verb, it MUST print that verb's flags. It is the one flag that is not a diagnostic, and it is a flag rather than a verb so that AGSC-09-07's sixteen stay sixteen. Its output names each of the sixteen verbs and each global flag, and for a verb each flag that verb takes; the wording is unspecified, only the names are asserted (vector cli-0036).

    Verb flags. lint additionally takes --fix, which applies exactly the normalisations AGSC-04-19 admits and nothing else (AGSC-04-14, AGSC-04-20, AGSC-03-12); an engine that does not implement it MUST reject the flag with AGSC-E002 rather than accept it and do nothing. The other verb flags this specification already obliges, each named by the rule beside it, are verify --ledger (AGSC-09-14), export --markdown|--okf|--jsonld|--jsonl|--steer [--target <name>[,<name>…]]|--to <adapter> — one comma-separated list of registry names, never a repeated flag, because this list types every verb flag as taking one value (AGSC-01-26…28, AGSC-01-26a), import --from <adapter> with --dry-run, which reports the plan and writes nothing (AGSC-01-26a), compose --from <slug> and compose --emit <target> (AGSC-07-24, AGSC-07-18), compose --out <dir> — the directory the seven file kinds of AGSC-07-12 are written into, defaulting to that rule's own dist/harness/<name>/ so that a conforming invocation needs no flag, and whose value MUST NOT reach any emitted byte (AGSC-07-13) — compose --zip, skills --zip and export --zip — each writing the files that invocation produced as ONE archive, beside the directory that holds them and never inside it, so that a reader may take a multi-file result in one download; the archive's bytes are AGSC-07-13a's, and it is a packaging and never a file of the Harness (AGSC-07-12) nor an input to any build (AGSC-01-16) — refresh --agent <name> with --dry-run (AGSC-08-28(f)), refresh --task <slug>, the declared lane task to run (AGSC-08-28(c)), run --dry-run (AGSC-09-94), build --level <n> and ci --level <n>, the Level a build emits (AGSC-10-02, AGSC-10-04; default 2), conform --level <n>, the Level whose vector set runs (AGSC-10-01; default 3) — on all three verbs <n> is one of 0, 1, 2 and 3, and any other value is refused before anything runs as AGSC-E003, exit 2 (Amended 2026-10-06 for 1.0.0: build and ci ignored any other value, and --level -1 built a site) — and conform --to <path>, where the AGSC-09-03 report is written (default dist/conformance-report.json) — compose --out and conform --to take a path relative to the Bundle root, and an absolute path, or one that leaves the root, is refused with AGSC-E902 before anything is written, as AGSC-01-16 and AGSC-01-35 refuse such a path elsewhere; and mcp takes one OPTIONAL positional <path>, the Bundle root it serves, defaulting to the working directory, so that an assistant with no working-directory setting can start it without a shell. propose --task-state <state> with --at <date>, which prepares the board move of AGSC-10-17 exactly as the propose tool does (AGSC-09-14b), is OPTIONAL: an engine that does not implement it rejects both with AGSC-E002. From 1.1 a verb takes these further flags, each OPTIONAL and each rejected with AGSC-E002 by an engine that does not implement it: lint --suggest (AGSC-05-35); export --skos and export --closure, each one export of its own, so that the rule "one export per run" of AGSC-09-07 holds (AGSC-05-36, AGSC-05-37); export --manifest, which adds the manifest of AGSC-09-17 to the export of the run; compose --brief (AGSC-07-25); compose --narrate <agent>, one value, the name of an agents[] entry (AGSC-07-28), which without --brief is AGSC-E003; and, for mcp, --http <port>, one decimal port from 0 to 65535 (0 lets the system choose, and the server reports the port it has on standard error), and --bind <address>, one loopback address, which without --http is AGSC-E003 (AGSC-09-18). (init takes no --adopt flag: adoption happens whenever init meets plain Markdown and needs no flag.) (Rationale for compose --out: AGSC-07-12 fixes the only legal location, so without the flag no operator could build a Harness into a scratch directory and no test could assert the emission without writing into the Bundle.) (Rationale for the three --zip flags: a "download all" archive sits beside the per-file links and the command line produces the identical archive; they are verb flags and not adapter flags because compose and skills have no adapter selector at all, an adapter flag belongs to one adapter, and --zip means the same thing for every export form.) No other flag exists at 1.0 on any verb, and none exists at 1.1 beyond those this rule names, except that a memory adapter selected by export --to <adapter> or import --from <adapter> MAY define further flags of its own (AGSC-01-26a): they belong to that adapter's documented contract and not to this specification, they MUST NOT change the meaning of a flag named above, and an engine that does not ship the adapter rejects them with AGSC-E002 (Rationale: an adapter is a MAY whose flags cannot be enumerated here; the reference old-site adapter, for example, takes --selection, --corrections and --attach-diagrams); --allow-newer, which AGSC-01-22 names, is one such flag. --peer belongs to tools/validate-wellknown, not to a verb; --level and --dev on that tool are the tool's own (AGSC-09-93, AGSC-10-12, AGSC-11-07). User configuration is the OPTIONAL file $XDG_CONFIG_HOME/agsc/config.json (else ~/.config/agsc/config.json) of the person running the tool: it lies outside every Bundle, is never published, and is not the second configuration file AGSC-01-17 forbids, which is a second file in the Bundle. (Amended 2026-10-02 for 1.0.0: --dev and "user configuration" were used without being stated here) (Amended 2026-10-10 for 1.0.0: an absolute or escaping compose --out or conform --to is refused with AGSC-E902; the reference engine already refused it, and this rule did not say so) (Amended 2026-10-29 for 1.1.0: the flags lint --suggest, export --skos, export --closure, export --manifest, compose --brief, compose --narrate, mcp --http and mcp --bind are added; each is optional and a 1.0 engine rejects it with AGSC-E002, so no valid invocation of 1.0 changes; --help is the one way to ask for the verb list and is not replaced by a verb) [PRD-007]

  • AGSC-09-10 Data goes to stdout; diagnostics go to stderr. Under --json, stdout MUST carry exactly one JCS-canonical envelope and stderr MUST carry one JSON object per line, one per finding — with one addition: ci first writes one {"override": "<NAME>"} object per configuration override in effect, the names AGSC-01-37 requires it to print (Amended 2026-10-02 for 1.0.0: the addition was made by the reference engine and not stated) — except where exit 2 is reached before a verb is resolved (an unknown verb or an unknown flag, AGSC-E001/AGSC-E002: there is no verb to name in verb; and a malformed SOURCE_DATE_EPOCH, AGSC-E603, which is read before the verb is resolved), or where an internal fault has no registered code, in which case stdout carries nothing and the fault is reported on stderr alone. findings[] in the envelope, and the stderr lines, MUST be ordered by (file, line, col, code) compared code-point-wise, so that a byte comparison of the output is stable however the lint phases were scheduled. (Amended 2026-10-10 for 1.0.0: a malformed SOURCE_DATE_EPOCH is named among the faults answered before a verb is resolved; the reference engine already answered it so, and the case cli-0021 pins its exit and code) [design]
  • AGSC-09-11 The envelope shape is the JSON object below. [PRD-003, PRD-007]
{ "counts": { "error": 0, "warn": 0 },
  "findings": [],
  "schema": "agsc.diagnostics.v1",
  "spec_version": "1.0.0",
  "status": "pass",
  "verb": "lint",
  "version": "0.1.0" }

A finding is { "code": "AGSC-E301", "col": 1, "file": "content/concepts/a.md", "line": 12, "message": "…", "severity": "error", "slug": "a" }. status ∈ pass|fail; severity ∈ error|warn — the literal is warn, never warning. Every finding carries code, col, file, line, message and severity: a finding about a whole file carries line 1 and col 1, and a finding about no file carries file as the empty string, which sorts before every path under the order of AGSC-09-10. It carries slug only when the finding is about one item and key only when it is about one configuration or frontmatter key, and it can carry further members that name what it is about (path, port, agent, …). (Amended 2026-10-10 for 1.0.0: which members every finding carries, which it carries only when they apply, and where a finding with no file sorts were not said) [PRD-003, PRD-007]

  • AGSC-09-12 --json is REQUIRED on every verb at 1.0 except mcp, whose standard output is the protocol itself (AGSC-09-13), and MUST emit the AGSC-09-11 envelope; the lint and ci envelopes additionally carry findings[] ordered per AGSC-09-10. Under --json a verb's data is the files it writes — the build output, the Harness of compose (whose harness.jsonld carries the verdict), the report of conform, the files of propose — and the human notes that name them are not printed, so that standard error carries finding objects only (AGSC-09-10). (Amended 2026-10-02 for 1.0.0: mcp exempted, and where a verb's data goes under --json stated; until then the reference engine also printed its notes on standard error in that mode.) [PRD-007]

    The bound on search and ask. A search answer carries at most 100 hits: when more than 100 items match, hits holds the first 100 in the order of the ranking — one point for each distinct token of the query that the item's tokens contain (AGSC-06-23), highest score first, equal scores by slug in code-point order — and the body gains the member total, the number of matching items, a safe integer; when 100 or fewer match, total is absent and the answer has the bytes of 1.0. An ask answer cites at most 100 item IRIs in citations[], the first in that order. Both transports MUST return the same value (AGSC-09-16), and a responder (AGSC-09-14a) is bound alike. The required cases cli-0007 and cli-0008 stay valid, because the bound adds no member to an answer under it.

    The citation record of a chunk. The body of read carries chunks, an array with one object for each chunk of the item (AGSC-06-26…06-30), in the order of AGSC-06-29, and [] for an item that has none, a draft or a retired item among them. A record has exactly the members algorithm (the string sha-256), bundle_version (the content version of AGSC-04-25), coverage (the string text: the digest covers the UTF-8 bytes of the chunk's text, AGSC-06-29), digest, id, iri (the item IRI), item (the slug), license, license_url (only where the node has one, AGSC-06-44), ordinal, section and terms, each with the value the chunk line of AGSC-06-29 carries for it; the time at which the client retrieved the chunk is the client's to add and is not in the record. The record is everything a client needs to cite one chunk and to check its text before it hands it to a model (AGSC-06-44). Vector cli-0028.

    The three further tools. brief returns the content of brief.json for the selection, composed over the listed set and with the host's build instant and content version, and writes nothing; an argument that is not an array is AGSC-E201 (AGSC-09-13a). explain names an edge by a key, a source and a target: key is one of the fourteen keys of AGSC-03-01 or one of their computed inverse names (anything else is AGSC-E203), source and target are slugs (a slug that names no item is AGSC-E301); the answer has holds true when that edge is authored or is a reading of AGSC-05-33, with because the steps of AGSC-05-33 (for an authored edge the one step {"from": [[<source>, <key>, <target>]], "rule": "authored"}), and holds false with because [] when it is not — a relation that does not hold is an answer and not an error. check returns the Link warnings AGSC-E313, AGSC-E314, AGSC-E315 and AGSC-E316 (AGSC-03-23…03-26) about the items of the selection, each as the finding of AGSC-09-11 without col, file, line and message, ordered by (slug, code, key, target) by code point; the member selection repeats the slugs checked, in code-point order. None of the three tools writes (AGSC-08-18). Vector cli-0026.

    The domain parts. For an item that states a key of AGSC-02-25, a hit of search and the body of read carry a member domain, an object with the members context (the context of the item, AGSC-08-32), role, type and warrant that the item has, and the items entries of brief carry it as AGSC-07-25 says; for an item that states none, no answer has the member, so an answer about it has the bytes it has on a node without the layer. Vector cli-0037.

    Annotations and order. The list of tools is ordered by name in code-point order, and each tool carries the annotations that AGSC-09-19 and AGSC-11-18 require. (Amended 2026-10-29 for 1.1.0: the bound, the citation record, the three tools, the domain parts and the order are added, for the reasons the vectors give) (Amended 2026-11-11 for 1.1.0: for check, the members of a finding are {code, key, severity, slug, target} and, for AGSC-E314, also with, the second key of the pair, so that two findings of one pair differ and the order of (slug, code, key, target) is completed by with in code-point order; a selection that is not an array is AGSC-E201, and a slug that names no item is AGSC-E301, in the error envelope of AGSC-09-13a. A clarification: no result changes.) [PRD-023]

  • AGSC-09-13a Tool error envelope. A tool that cannot fulfil a call MUST return the AGSC-08-18 envelope with type: "error", trust: "untrusted", license as usual, and body = the JSON object { "code": "AGSC-E<nnn>", "message": "…" }; source names the tool. It MUST NOT signal a domain fault as a JSON-RPC transport error — those are reserved for protocol faults (bad method, malformed params, a tool name the server does not serve, AGSC-09-19) — and the MCP result that carries the envelope sets isError to true for an envelope whose type is error and to false for any other, so that a client reading only MCP's own flag sees the fault (AGSC-09-19). The shape is identical on the stdio and WebMCP transports, which is what makes the byte-identity of AGSC-09-16 hold for failing calls as well as succeeding ones. A call that omits an argument the tool's inputSchema marks REQUIRED is AGSC-E003, returned in this envelope; an empty string is supplied, not missing. A call that supplies an argument of another JSON type than the one the tool's inputSchema states for it (a string, an array or an object) is AGSC-E201, returned in this envelope (cli-0039), as MCP asks a server to validate tool inputs. A compose call whose selection is not an array — the table of AGSC-09-13 gives it as an array of slugs — is AGSC-E201, returned in this envelope; an empty array is supplied, and its verdict is the verdict of the empty selection. (Amended 2026-10-06 for 1.0.0: both transports read a selection that was not an array as the empty selection and answered valid: true.) message text is unspecified so that ports may localise it, and only code is asserted (AGSC-09-05). cli/cli-0004 is its vector. (Amended 2026-10-29 for 1.1.0: the result that carries an error envelope also carries MCP's isError: true, and a tool name the server does not serve is a JSON-RPC error, as MCP defines both in revision 2025-11-25 and in revision 2026-07-28 alike; for a fault that stays a tool error the envelope, its code and its members are unchanged, and an unknown tool name no longer gets the envelope with AGSC-E001 — a named exception of AGSC-00-14) (Amended 2026-11-10 for 1.1.0: arguments are checked against the types the published inputSchema states; until this note search with an object query answered with no hit and ask with a number answered, on both transports, and 1.0.1 did the same) [PRD-023, PRD-051, AGSC-08-18, AGSC-09-11]

  • AGSC-09-14a A Channel responder (ask) answers questions from its own Bundle when served locally — through the local MCP tools search read links, which read that Bundle as AGSC-09-13 says, drafts included — and from the published exports on a page or wherever it reads a node it does not hold (a Level-1 reader over search.json/graph.jsonld/pages/*.md, which carry the listed set of AGSC-09-16). Its result MUST be the AGSC-08-18 envelope — {source, trust: "untrusted", license, type, body} — with exactly one added top-level member, citations[], an array of item IRIs; body is the answer text itself, and MUST be exactly no answer in this memory when nothing matches — that is, when no item the responder reads shares a token of the AGSC-06-23 tokenizer with the question (that tokenizer has no stop-word list and drops only tokens shorter than two code points). Every other answer MUST cite ≥1 item IRI in citations[] and embeds the Content Use Terms line in body; the no-answer result carries an empty citations[]. (citations[] is therefore a sixth envelope member and body a string, never an object, so that body can be exactly the fixed string; cli-0007 pins the bytes for a matching and a non-matching question.) A responder MAY use an LLM only under the spend cap, and one that does MUST record its spend by emitting a remember(kind: episode) Proposal carrying usage — otherwise its spend never reaches the NOW rollup (AGSC-08-25) and the cap is unenforceable. A responder cites at most 100 item IRIs (AGSC-09-13). Responders are plugins; none is required for conformance at any Level. (Amended 2026-10-29 for 1.1.0: the bound of AGSC-09-13 on the number of citations is stated here too) (Amended 2026-10-10 for 1.0.0: "the stop words the tokenizer drops" contradicted AGSC-06-23, which has no stop-word list; the empty citations[] of the no-answer result, which cli-0007 pins, was not said, and "every answer" read as including it) (Amended 2026-10-10 for 1.0.0: the responder was said to use only the published exports, while the local tool server and the required case cli-0008 answer from the author's own Bundle, drafts included; the two places it answers from are said; nothing a node emits changes) [PRD-056]
  • AGSC-09-14b The tool set is AGSC-09-13's and WebMCP mirrors it under AGSC-09-16. remember({kind, title, body, at?, actor?, agent?, model?, operator?, origin?, outcome?, severity?, sources?, cluster?, about?, usage?}) — exactly the arguments of the AGSC-09-13 table — MUST synthesize a conforming item (AGSC-02) — usage being the OPTIONAL {model, tokens_in, tokens_out, cost_usd, estimate} object of AGSC-02-14, REQUIRED when the caller is an LLM responder (AGSC-09-14a) or an agent lane (AGSC-08-28(d)) and carried onto the synthesized episode verbatim, because AGSC-09-14a obliges a responder to record its spend through this call and AGSC-08-25's cap is otherwise unenforceable for responders; on an episode, usage.tokens_in and usage.tokens_out are each a safe integer — an integer from −(2^53 − 1) to 2^53 − 1, outside which RFC 7493 §2.2 says a receiver cannot be expected to treat an integer as an exact value — usage.cost_usd a finite number, usage.estimate a boolean and usage.model one line, and a usage outside these bounds is refused with AGSC-E201, a bound stricter than the schema's plain integer: type from kind; slug from the title per the AGSC-02-91 slugifier with -2, -3, … collisions; at (an instant, REQUIRED for episode) supplies started — a clock is never read (AGSC-04-11); outcome defaults to partial, and severity defaults to info for a lesson, the one kind whose schema branch carries it; a call that declares no at for an episode is AGSC-E003, like one that declares no actor; a concept gets kind: explainer; actor is the client's declared agent actor string (AGSC-02-09), REQUIRED when kind is episode — a call that declares none is AGSC-E003, because that item's schema branch requires it; remember accepts the kinds concept, episode, lesson, procedure and task, and refuses gate with AGSC-E203, because a Gate's Level is a governance decision that a tool call may not invent, and every other kind with AGSC-E203 too (Amended 2026-10-06 for 1.0.0: both transports filed an unknown kind as a concept); prov.operator = the client's declared human operator, prov.agent/prov.model = the client's declared identity, and prov.origin: ai-generated unless the client asserts human — so a call that declares an operator but neither agent nor model, and does not assert origin: human, returns an item that AGSC-08-01 refuses in lint with AGSC-E202 for each missing member; at 1.0 the call reports no finding for it, and a client supplies both or asserts origin: human. It hands the item to the Proposal path (AGSC-08) under the client's channel publish mode (AGSC-01-31, default hitl) and MUST NOT write to the content branch. The server MUST also expose every published item (AGSC-00-05) as an MCP resource (text/markdown) — a retired item included and a draft or held-back item never; its text is the item's per-item copy /pages/<slug>.md (AGSC-05-07) — and graph.jsonld and llms.txt, and one prompt "answer from this memory with citations": the resource URI of an item is memory://<bundle-id>/<slug> (AGSC-05-04b); graph.jsonld is memory://<bundle-id>/graph.jsonld with application/ld+json and llms.txt is memory://<bundle-id>/llms.txt with text/plain; the list is ordered by URI in code-point order (AGSC-04-12); the prompt's name is answer-from-this-memory-with-citations, its title and description are answer from this memory with citations, and it takes exactly one REQUIRED argument, question; a resource URI or prompt name that does not exist is a JSON-RPC error, not the AGSC-09-13a envelope, which governs tools alone. propose MAY take task_state (one of the nine of AGSC-02-99) and at, and then returns the prepared board move of AGSC-10-17 — a patch that sets task_state and, when at is given, modified, and nothing else; remember MAY take kind: task (a concept of kind: task in TASK_STATE_SUBMITTED), cluster (the cluster it is filed in) and about (one related Link) — an about that names no item the server can see is refused with AGSC-E301, the code a related Link to no item carries in lint (AGSC-03-02), so that the item it returns stays conforming (Amended 2026-10-06 for 1.0.0: the Link was written and the next lint refused the item). A client-supplied sources[] entry MUST be validated before the item is synthesized: resource MUST match the AGSC-02-10 grammar (https?://… or urn:agsc:channel:<name>:<source_id>) and MUST NOT carry any other scheme. An entry that fails MUST be dropped with the warning AGSC-E506, which is the one code reported for it, never rejected as an error — remember is a total function like adoption (AGSC-02-90); a kept entry carries its resource and its id and no other member. A call that declares no operator is refused with AGSC-E003 on the local server, unless it declares an enabled lane's agent, whose entry supplies prov.operator (AGSC-01-36, AGSC-08-28(b)); the page tools, which have no identity to declare, return the item with prov.operator absent and say so with AGSC-E506, and the Proposal path refuses it until a person supplies one (Rationale: an item without an operator is not the conforming item this rule promises). (Amended 2026-10-10 for 1.0.0: the signature named fewer arguments than the AGSC-09-13 table, without agent, model, operator and origin; the safe-integer bound both transports apply to usage was unstated; a failing sources[] entry was given two codes, and the sentence said its other members were truncated and normalised, where both transports keep resource and id only) (Amended 2026-10-10 for 1.0.0: the resources were every item, and then only a published item named with AGSC-06-30, which AGSC-00-05 reads as the listed set, while the reference engine exposes every published item, a retired one included; the set and the bytes of an item's resource are said; nothing a node emits changes) (Amended 2026-10-12 for 1.0.0: the item this rule promises conforms to the schema, and the agent/model condition of AGSC-08-01 is a lint check the schema cannot express, so a call with an operator alone under the default origin returned an item that lint refused; the sentence now says so. No behaviour changes; reporting it in the call is listed for 1.1 in AGSC-00-20.) [PRD-023, PRD-056]
  • AGSC-09-16 WebMCP. Where a browser exposes document.modelContext, the /compose/ and item pages MUST register the same ten tools as AGSC-09-13 through document.modelContext.registerTool(), with identical names, identical argument names and results equal as values to the local MCP server's for the same input and Bundle — the same members, in the same order, with the same contents; what crosses the browser boundary is whatever serialisation the user agent applies to that value, which this specification does not constrain (the WebMCP draft has executeTool() resolve to the stringified result of the tool's execution, so those bytes are not this specification's to fix) — one tool contract, two transports (cli-0026 compares the two manifests). The Bundle a page serves is the listed set (AGSC-00-05), the projection of AGSC-06-30 that search.json carries: an item that is not listed — a draft, a retired or a release-gated item — is not visible to a page tool, and a page tool MUST answer AGSC-E301 for it, exactly as the local server answers for a slug that does not exist, while the local server, which reads the author's own Bundle (AGSC-09-13), answers it (Rationale: a page can read only what the node lists, so on any Bundle holding a draft, a retired or a release-gated item the two transports could not otherwise agree). The equality of this rule's first sentence therefore holds for every call on a Bundle whose items are all listed; on a Bundle that holds other items, the local server's answers may also name them or carry the Links to them that a page's copies leave out (AGSC-05-07), and cli-0008 pins a read of one listed and one draft item. Besides those items, the one input on which the two transports MUST differ is a remember call that declares no operator: the local server refuses it with AGSC-E003 and a page tool, which has no identity to declare, returns the item with prov.operator absent and AGSC-E506 (AGSC-09-14b); cli-0026 compares the manifests, not that answer. Registration MUST be feature-detected: with no document.modelContext the page MUST work unchanged in plain JavaScript, and no tool may require a network call, a key or a server. On the WebMCP transport propose and remember are local-only: they MUST return the Proposal payload to the caller and MUST NOT perform any network write, MUST NOT read or honour channels[].publish, and the auto mode of AGSC-01-31 is unavailable to this transport — a browser page holds no configuration authority and no forge identity (AGSC-08-04, AGSC-08-26(f)). Equality as values with the stdio transport (this rule's first sentence) — the same members, in the same order, with the same contents — is asserted over the returned payload, not over any side effect. (Amended 2026-10-10 for 1.0.0: the page's item set was called the published projection, which AGSC-00-05 reads as the listed set; it is named the listed set, the local server's answer for an item a page cannot see is said, and so is where the equality of the two transports holds; nothing a node emits changes) (Amended 2026-10-29 for 1.1.0: the three tools brief, explain and check are registered too, answering over the listed set and writing nothing, the bound of AGSC-09-13 applies on this transport as on the other, and the case that compares the manifests is cli-0026, the successor of cli-0003) (Amended 2026-11-11 for 1.1.0: the context of a domain part is read by a page as by the local server: the context of an item whose primary cluster is a declared context cannot be known from the published routes, so the build writes the declared cluster slugs, and the slugs of the listed items whose stated context is withheld (AGSC-07-25), into the two page scripts. A clarification: no answer changes.) [PRD-051, AGSC-09-13]
  • AGSC-09-17 Digest fields. The digest fields of RFC 9530 (https://www.rfc-editor.org/rfc/rfc9530.html, read 2026-10-29) are used in two places and in no other, and the algorithm is sha-256 in both (RFC 9530 §5 lists it as Active). (a) The export manifest. export --manifest (AGSC-09-09) adds to the export root (AGSC-01-26) the file export-manifest.json, beside the files that export writes: one JSON object in JCS form (AGSC-04-04) followed by one LF, with exactly the members bundle_hash (the lowercase-hex SHA-256 of the graph.nq of the same build, the value of agsc-bundle-hash, AGSC-06-08), bundle_version (AGSC-04-25), files (one object {content_digest, path} for each file of the export other than the manifest, ordered by path by code point, path relative to the export root), item_count (the number of published items, AGSC-06-30), items_digest (the lowercase-hex SHA-256 of the JCS form of the array of the item IRIs of those items in code-point order) and spec_version. content_digest is written as the value of a Content-Digest field, sha-256=:<base64>: over the file's bytes, in the standard base64 alphabet with padding; RFC 9530 defines the field for the content of a message and the manifest borrows its value syntax for the bytes of a file, so no header is involved. A run without --manifest writes no manifest and its files are those of 1.0 (export-0001, export-0002). import of a folder that holds a manifest recomputes each digest, the count and items_digest and reports a difference as the warning AGSC-E506; it imports as it would without one. (b) The served Repr-Digest. A writer MAY send Repr-Digest: sha-256=:<base64>: for a machine artefact only on a response served without a content coding, as AGSC-06-17 says, and MUST NOT write a Content-Digest field into _headers: under Content-Encoding the bytes of the message, and with them the digest, are not known to a static _headers file. Vectors export-0003 and export-0004. (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: the manifest is new and optional, and the two limits on the header fields restate AGSC-06-17) (Amended 2026-11-11 for 1.1.0: the value form sha-256=:<base64>: is also borrowed by the content_digest of a chunk (AGSC-06-29) and by the member of agsc-chunk-set (AGSC-06-44); "in two places" counts the places where the digest fields of RFC 9530 are used, the manifest and the served Repr-Digest, and not these two borrowings of the value form. A clarification: no emitted byte changes.) [design]

  • AGSC-09-18 Streamable HTTP transport. mcp --http <port> (AGSC-09-09) serves the ten tools of AGSC-09-13 over the Streamable HTTP transport of MCP revision 2026-07-28 (https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http, read 2026-10-29), instead of standard input and output. It is the server the stdio form starts: the same Bundle, the same tools, the same envelopes (trust is untrusted on every result, AGSC-08-18), the same floor (AGSC-11-18) and the rules of AGSC-09-19 for results. It is read-only: it writes no file and sends no message, and propose and remember return their Proposal payload as they do on the WebMCP transport (AGSC-09-16), so dist/proposal/ is never written by it. The server:

    1. binds only to a loopback address: 127.0.0.1, or the address --bind names, which MUST be in 127.0.0.0/8 or be ::1; any other value is AGSC-E003 with exit 2 and nothing is started. A deployment on another address — the public hosting of the tool server — is outside this version; 2. serves one endpoint, the path /mcp, which accepts POST only; a GET or a DELETE on it is HTTP 405 and any other path HTTP 404; 3. validates the Origin header of every request against DNS rebinding: a request that has an Origin whose host is none of 127.0.0.1, localhost, [::1] and the address --bind names is answered with HTTP 403 and no tool is run, and so is a request whose Host header (port ignored) names any other host than those, hosts being compared ASCII case-insensitively, since a name re-pointed at the loopback address still arrives with its own name; a request with no Origin is admitted, because a client that is not a browser sends none; 4. requires on every POST the headers MCP-Protocol-Version and Mcp-Method and, for tools/call, resources/read and prompts/get only, also Mcp-Name. A header that is missing, or whose value differs from io.modelcontextprotocol/protocolVersion of the request's _meta or from the request's method and params.name or params.uri, is HTTP 400 with the JSON-RPC error -32020; a request whose _meta lacks io.modelcontextprotocol/protocolVersion or io.modelcontextprotocol/clientCapabilities is HTTP 400 with the error -32602 (MCP revision 2026-07-28, basic/index, "Request Metadata", read 2026-10-29); a revision other than 2026-07-28 — the one revision this transport speaks, so that a client of 2025-11-25, which opens with initialize and a session, is refused — is HTTP 400 with the error -32022 whose data is {"requested": <the value>, "supported": ["2026-07-28"]}; a method the server does not implement is HTTP 404 with the error -32601; 5. answers each request with one application/json object and never with a stream, accepts a notification with HTTP 202 and no body, mints no Mcp-Session-Id and ignores one a client sends.

    The server reads the Bundle as it is on disk (AGSC-09-13) and is for its author's own agents. Vectors cli-0029, cli-0030 and cli-0031; cli-0031 is the refusal vector (a foreign Origin, a name that is not loopback in Host, a method other than POST, a bind address that is not loopback, and a write attempted through propose). (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: the transport is optional, a 1.0 engine rejects its flags with AGSC-E002) [design]
