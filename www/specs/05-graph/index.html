AGSC-05 — Graph: IRIs, RDF views, SKOS, PROV

SummaryHow items become a graph with web addresses, the three RDF views, the ontology and its alignment to SKOS, PROV-O and Dublin Core, and the byte-level pins.

Status of this document

Specification 1.0.0-rc.7, a release candidate tagged on 2026-10-08. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

In plain language

Every item is a node with a web address (<site>/concepts/<slug>/), and every link is an edge. The Bundle is exported as JSON-LD, Turtle and N-Quads — one graph, three syntaxes — plus one file per item; those are the four RDF views, and RDF/XML is not emitted at 1.x (AGSC-05-06).

The vocabulary. A small OWL 2 RL ontology (ontology/agsc.ttl, CC0) with 12 classes and 40 properties, aligned to SKOS (concepts and clusters), PROV-O (episodes, procedures, gates, reviews, sources) and Dublin Core. There is deliberately no common Item class.

No inference at build. Everything a consumer might expect from reasoning — inverses, cluster nesting — is written out explicitly, so what you read is what was emitted.

Byte pins. Literals take exactly one of three forms (language-tagged, typed, plain), N-Quads escaping is fixed, and because the graph has no blank nodes its canonical form is just a sort.

Attachments, ports and citations. Attachments are nodes with a SHA-256; ports and task states are datatype properties; a citation of another node becomes rdfs:seeAlso plus asc:peerOrigin.

This box explains; the rules below decide. New to the notation? See how to read the specification.

5.1 Identifiers

  • AGSC-05-01 An item IRI MUST be <site.base>/<type-plural>/<slug>/ — an HTTPS site URL with a trailing slash. [design]
  • AGSC-05-02 Vocabulary IRIs MUST use the persistent hash namespace https://w3id.org/agentic-system-core/ns#. The site domain MUST NOT appear in a vocabulary IRI. The namespace is a constant of this specification and is not configurable: ns{base,version} in agsc.config.json (AGSC-01-18) is retained for forward compatibility only, no conforming tool reads a value other than the default, and a Bundle MUST NOT vary it. [design]
  • AGSC-05-03 The Bundle IRI is <site.base>/. Cluster IRIs follow AGSC-05-01 with <type-plural> = clusters. [design]
  • AGSC-05-04 memory://<bundle>/<slug> is a documented alias of the item IRI. An implementation MUST NOT emit it as an RDF subject and MUST NOT dereference it over the network; it is resolved locally, and only for this Bundle's own bundle.id, exactly as AGSC-05-04b specifies. No node is ever required to emit or render memory:// (AGSC-05-04a); an implementation at Level 2 or above MUST resolve it as AGSC-05-04b says (graph-0005; the tool server: cli-0015). (Amended 2026-10-02 for 1.0.0: until 1.0.0-rc.6 this rule said that an implementer at any Level "may skip AGSC-05-04a, AGSC-05-04b and AGSC-10-08 without affecting a claim", while two required cases tested the resolution; the cases decide.) [PRD-027]
  • AGSC-05-04a The HTTPS item IRI (AGSC-05-01) is the canonical identifier and MAY ALWAYS be used instead of memory:// — wherever an implementation documents or accepts memory://<bundle>/<slug> — exports, foreign-node mappings, prose and rendered output — the https:// form MUST be equally accepted and the two MUST be treated as the same identifier. Link values remain slugs (AGSC-03-02), and neither form is ever written as one; a tool or command-line argument that names an item accepts both forms and resolves them to the slug before any other rule runs, as AGSC-05-04b says (AGSC-08-18). Emitting or rendering memory:// is optional, never a requirement. (Amended 2026-10-02 for 1.0.0: until 1.0.0-rc.6 this rule said neither form "is ever accepted as an argument, only ever rendered", against AGSC-05-04b.) [PRD-027]
  • AGSC-05-04b agsc mcp tools and the CLI MUST resolve memory://<bundle-id>/<slug> to the item when <bundle-id> equals this Bundle's bundle.id: the alias is accepted wherever a slug argument is accepted, normalized to the slug before any other rule runs, and never dereferenced over the network (AGSC-05-04 still forbids emitting it as an RDF subject). When <bundle-id> names another Bundle the argument MUST be refused with AGSC-E309 — "foreign bundle: use the https:// IRI" — because a node has no registry of other nodes' ids. Frontmatter Link values remain slugs (AGSC-03-02). [PRD-027, AGSC-05-04a]
  • AGSC-05-05 If an item carries iri, it MUST equal the computed IRI; a mismatch is AGSC-E204. [design]

5.2 The four RDF views

  • AGSC-05-06 A writer MUST emit graph.jsonld, graph.nq, graph.ttl and per-item pages/<slug>.{jsonld,md}; graph.rdf (RDF/XML) is NOT emitted at 1.x and build.rdfxml is RESERVED (one blank-node-free graph needs no fourth syntax). All views express the same triples. [PRD-022]
  • AGSC-05-07 pages/<slug>.md MUST be a byte-identical copy of the lint-normalized source file, with one derived change: a Link target naming an item AGSC-06-30 excludes is removed from the frontmatter array and a key emptied by that removal is omitted, as AGSC-06-29 does for a chunk record (Rationale: a held-back item is on no public surface, and this page is one; export --markdown, the publisher's own byte-preserving copy under AGSC-01-26, is not). [design]
  • AGSC-05-08 The RDF dataset MUST be blank-node-free: every node has an IRI. Blank nodes in an export are error AGSC-E605. [design]
  • AGSC-05-09 graph.jsonld MUST carry as its @context the specification's persistent versioned context URL — https://w3id.org/agentic-system-core/ns/<ontology-version>/context.jsonld, <ontology-version> being the owl:versionIRI version of AGSC-05-25 (1.0.0-draft.1 until spec_version reaches 1.0.0, then 1.0.0 — AGSC-05-25) — declare "@version": 1.1, mark every term @protected, and sort nodes by @id and properties per AGSC-04-05. The URL is a constant of this specification, resolvable by every reader at every Level, so a Level-0 graph.jsonld is expandable without the node serving a context of its own; a Level ≥ 2 writer additionally serves a byte-identical copy at /ns/context.jsonld and at /ns/<ontology-version>/context.jsonld (AGSC-06-32, AGSC-06-06) and MAY name either of those instead. Released context files are immutable; new terms require a new file. Shape of the file. (Amended 2026-10-02 for 1.0.0: the shape below is what conforming writers emit; it was not written down, so two writers could differ and both claim this rule.) The document is a JSON object with exactly two members: @context, one string, the URL above; and @graph, an array holding one node object per subject of the dataset of graph.nq (AGSC-05-06), in code-point order of @id. A node object has @id; @type, the context's term name for the node's class (one string — every node has one class, AGSC-05-12); and one member per other predicate of that subject, named by the context's term for the predicate, or by the predicate IRI where the context has none. Each value takes the most compact form its term definition allows: an IRI is a bare string where the term's @type is @id, otherwise {"@id": …}; a language-tagged literal is {"@language": …, "@value": …}; a literal whose datatype is the term's @type or xsd:string is its bare lexical form; any other literal is {"@type": …, "@value": …}. A member's values are ordered by the code points of their IRI or lexical form, without repeats, and a member with one value carries that value, never a one-element array. At Level 2 and above the bytes are JCS (AGSC-04-04) followed by one LF. The per-item file /pages/<slug>.jsonld (AGSC-06-02) has the same shape and the same @context, and holds exactly the Bundle node, the item's node and the item's own #source-<n>, #review-<n> and #attachment-<n> nodes, each identical to its node in graph.jsonld — so every triple whose subject is the item is present, its Links, their computed inverses and its mentions included (AGSC-05-06); a triple whose subject is another node, such as a cluster's skos:member, is in that node's file only. Test case graph-0028 states both files whole. [design]

  • AGSC-05-10 graph.ttl MUST follow the stable-Turtle profile, every byte of which is fixed here (Rationale: AGSC-04-24 claims cross-implementation byte-identity for this file.):

    (a) The @prefix block is exactly, in this order, one line each and nothing else:

    @prefix asc: <https://w3id.org/agentic-system-core/ns#> .
@prefix dcterms: <http://purl.org/dc/terms/> .
@prefix prov: <http://www.w3.org/ns/prov#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix schema: <https://schema.org/> .
@prefix skos: <http://www.w3.org/2004/02/skos/core#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

    written @prefix <pfx>: <IRI> . with exactly one space after each token, the prefixes in code-point order of the prefix name. A prefix whose vocabulary the graph does not use is still emitted, so the block is a constant of this specification; owl: and rdf: are never declared (no triple this specification emits needs either — rdf:type is written a).

    (b) Layout. Exactly one blank line separates the prefix block from the first subject block, and each subject block from the next. The file ends with exactly one LF (AGSC-04-07) and carries no other blank line, no comment, no @base and no PREFIX/BASE (SPARQL-style) directive.

    (c) Order. Subject blocks are ordered by subject IRI code points; within a block, predicates by predicate IRI code points — the IRI, never its prefixed name, so skos:prefLabel (http://…) precedes asc:status (https://…); within a predicate, objects by the code points of their written Turtle form.

    (d) Serialisation. A subject block is <subject-form> <clause> for the first predicate, then one further line per predicate, each indented by exactly four spaces; clauses are separated by ; followed by a single LF, and the block ends with .. Several objects of one predicate are written on that predicate's clause, separated by ,. a is written for rdf:type; every other predicate and every IRI whose namespace is in (a) and whose local part is a legal PN_LOCAL is written as a prefixed name, and every other IRI between < and >.

    (e) Literals. Explicit datatypes except xsd:string and language-tagged literals, per AGSC-05-31; lexical forms and escaping per AGSC-05-32.

    graph.ttl MUST be isomorphic to graph.nq. Vector graph-0026 pins a complete file. [design]

  • AGSC-05-11 Emission is one-way. An implementation MUST NOT claim to be a JSON-LD processor, an RDF parser or a SHACL engine on the strength of these outputs. [design]

5.3 Class and property mapping

  • AGSC-05-12 Items MUST be typed per ontology/agsc.ttl: concept → asc:Concept (⊑ skos:Concept), lesson → asc:Lesson (⊑ asc:Concept), episode → asc:Episode (⊑ prov:Activity), procedure → asc:Procedure (⊑ prov:Plan), cluster → asc:Cluster (⊑ skos:Collection), gate → asc:Gate (⊑ prov:Plan). The Bundle is asc:Bundle (⊑ skos:ConceptScheme). [design]
  • AGSC-05-13 There is no common superclass for items; an asc:Item class MUST NOT be emitted. An Activity is not an Entity, and the union would fail OntoClean while answering no competency question. [design]
  • AGSC-05-14 Each sources[] entry MUST be instantiated as an asc:Source (⊑ prov:Entity) whose IRI is <item-IRI>#source-<n>, <n> being the 1-based index of the entry in authored sources[] order — a fragment IRI, exactly like a Review (AGSC-05-15), so that no URL-to-IRI escaping question arises and a urn:agsc:channel:… resource works unchanged. It carries dcterms:source = the resource string, dcterms:title, dcterms:creator and dcterms:date from title, author and year where present, plus asc:verifiedOn and asc:grade where present; dcterms:bibliographicCitation is NOT emitted, because no composition rule for it could be reproduced by a port. asc:verifiedOn is xsd:dateTime (the OWL 2 datatype map has no xsd:date, AGSC-05-22): a verified date YYYY-MM-DD MUST be rendered as the midnight instant YYYY-MM-DDT00:00:00Z. The item MUST additionally carry <item> asc:source <item-IRI>#source-<n> for each entry, so the Source is reachable from its item (AGSC-05-23: relied-upon relations are materialized, never entailed). [design]
  • AGSC-05-15 verified[] MUST be instantiated as an asc:Review (⊑ prov:Activity) whose IRI is <item-IRI>#review-<n>, <n> being the 1-based index of the entry in authored verified[] order — Reviews therefore have IRIs and never become blank nodes (AGSC-05-08). The actor and instant MUST be emitted as the datatype properties asc:verifiedBy (the by string) and asc:verifiedAt (the at instant); prov:wasAssociatedWith MUST NOT be used, because by is an actor string and not an IRI, and prov:wasAssociatedWith is an object property whose range is prov:Agent. The item MUST additionally carry <item> asc:review <item-IRI>#review-<n> for each entry (AGSC-05-23). Proposals come only from the derived git log, and a Proposal's IRI is the forge pull-request URL. [design]
  • AGSC-05-16 The fourteen Link keys MUST map exactly as tabulated in §03 — the nine core keys to SKOS, DCTerms, PROV and asc: as listed there, and the five Mode-2 keys to asc:implements, asc:verifies, asc:covers, asc:blockedBy and asc:decidedBy with the computed inverses asc:implementedBy, asc:isVerifiedBy, asc:coveredBy, asc:blocks and asc:decides (asc:isVerifiedBy is the Link inverse; the datatype property asc:verifiedBy of AGSC-05-15 is a Review actor and unrelated). Inline links map to asc:mentions. [design]

5.4 SKOS integrity

  • AGSC-05-17 Every Concept MUST carry skos:inScheme the Bundle, exactly one skos:prefLabel per language tag, and skos:altLabel for each alias. [SKOS S14]
  • AGSC-05-18 Cluster membership MUST be emitted as <cluster> skos:member <item> from the item's clusters[]. [design]
  • AGSC-05-19 Cluster nesting rule. broader on a type: cluster file is a nesting statement and MUST be exported as <parent> skos:member <child> — a nested skos:Collection. skos:broader on a Collection is forbidden: its domain and range are skos:Concept (S19/S20), which is disjoint with skos:Collection (S37), so the triple would entail a contradiction and fail every SKOS validator. [design]
  • AGSC-05-20 broader/narrower between Concepts MUST be exported as skos:broader/skos:narrower. A Collection MUST NOT appear in any semantic relation (skos:broader, skos:narrower, skos:related). [design]
  • AGSC-05-21 The machine-checkable qSKOS subset MUST be linted: cyclic hierarchies, overlapping labels, orphan concepts, missing in-links, missing definitions, undefined resources. Overlapping labels — two published items of one type whose title values are equal after NFC and case folding — are the warning AGSC-E416; the other five checks take the codes their own rules name. [design]

5.5 Profile and reasoning

  • AGSC-05-22 ontology/agsc.ttl MUST stay inside OWL 2 RL. Constructs outside RL MUST be rejected by lint. (This rule and AGSC-05-28 govern the vocabulary terms the ontology declares, and not the annotation properties on the ontology node itself that AGSC-05-25 requires.) [design]
  • AGSC-05-23 No reasoner runs at build. Relied-upon entailments — inverses and cluster nesting — MUST be materialized explicitly; integrity comes from JSON Schema and generated SHACL shapes. (At 1.x integrity comes from the JSON Schemas alone: no shapes are generated, and the lane of AGSC-05-24 is a 1.1 item named in AGSC-00-20.) [design]
  • AGSC-05-24 SHACL shapes MUST be generated from schema/item.schema.json, never hand-edited, and run in a development lane; without that lane the "validated by SHACL" claim MUST be dropped. (This distribution has no such lane at 1.x, so the claim is dropped — no document of it says "validated by SHACL" — and the lane is a 1.1 item, AGSC-00-20; the first sentence binds whoever builds it.) [design]
  • AGSC-05-25 The ontology MUST declare owl:versionIRI per release and MUST mark retired terms owl:deprecated true with dcterms:isReplacedBy instead of deleting them. Until spec_version reaches 1.0.0, and while the vocabulary's terms are those published with specification 1.0.0-rc.6, owl:versionIRI MUST name the pre-release path (https://w3id.org/agentic-system-core/ns/1.0.0-draft.1) and owl:versionInfo MUST equal that string; the .htaccess version rule already accepts a SemVer pre-release suffix. The vocabulary version 1.0.0-draft.1 is frozen as published with specification 1.0.0-rc.6: its versioned copy under /ns/1.0.0-draft.1/ — the ontology and its JSON-LD context — is immutable like every versioned copy (AGSC-06-06) and stays served after 1.0.0, and a term added or changed later goes into the file of a new version, never into this copy. From spec_version 1.0.0 on, the vocabulary version is 1.0.0 — owl:versionIRI https://w3id.org/agentic-system-core/ns/1.0.0, owl:versionInfo "1.0.0", its immutable copy under /ns/1.0.0/ — and it changes only when a term is added or changed, to the version of the specification that ships that change; a later specification version that changes no term keeps it, and AGSC-05-09 then names the same context URL. (Amended 2026-10-02 for 1.0.0: the rule said what the version is before 1.0.0 and not after.) The ontology node MUST also carry the metadata a vocabulary registry indexes: rdf:type voaf:Vocabulary beside owl:Ontology, vann:preferredNamespacePrefix "asc", vann:preferredNamespaceUri <https://w3id.org/agentic-system-core/ns#>, the namespace every asc: term is in, dcterms:creator, dcterms:publisher, and dcterms:issued and dcterms:modified as xsd:date values — issued the date of the first tagged release that carried the vocabulary and modified the date of the release that ships the file, both derived from the release and never read from a clock. (Rationale: these are the properties a registry such as LOV reads to index a vocabulary. The two prefixes they need are declared in ontology/agsc.ttl alone, which no rule's fixed prefix block pins — AGSC-05-10 pins the prefix block of the emitted graph.ttl, a different file — so they change no emitted byte.) [design]

5.6 Frontmatter → property mapping

  • AGSC-05-26 Every datatype property this specification emits — every asc: property, and the DCTerms and schema.org literal properties named in the table — MUST be emitted from exactly the frontmatter or configuration key named here, on exactly the subject named here, with exactly this datatype — so that graph.ttl, graph.nq and the per-item JSON-LD are reproducible from spec/ plus the Bundle alone (AGSC-00-01, NFR-02). A key absent from an item emits no triple, and no property is ever inferred or invented — including status: the default stable of AGSC-02-23 is a reading default, and asc:status is emitted only when status is authored, so an adopted file adds no triple it did not write. prov.agent and prov.agreement are deliberately not exported: agent is a build-time severity and merge-guard discriminator (AGSC-08-13, AGSC-08-26(d)) rather than a published fact, and agreement is a contribution-agreement identifier carried by the DCO-Plus trailer (AGSC-08-06). Adding asc:agent would require a property no §5.3/§5.6 rule emits, which AGSC-05-28 forbids. schema:license and schema:usageInfo are the two properties this specification emits from configuration rather than from an item key: both are constants of the build, both are literals (a LicenseRef- or SPDX identifier is text, not an IRI), and both appear on the Bundle node and on every item node so that pages/<slug>.jsonld and the export --jsonl line of AGSC-01-27 carry the licence without a second fetch.   • AGSC-05-26a asc:uses, asc:excludes and asc:contradicts MUST NOT be given a super-property, a domain or a range. skos:related is a sub-property of skos:semanticRelation, whose domain and range are skos:Concept (SKOS S19/S20), so asc:uses ⊑ skos:related would still entail that a Procedure, Episode or Gate carrying uses is a skos:Concept, and that a Cluster carrying it is both a skos:Collection and a skos:Concept — the S37 contradiction. Dropping the sub-property axiom removes the entailment at its source; AGSC-05-20's prohibition on Collections in semantic relations stands. [design]
  • AGSC-05-27 title, description and aliases map to skos:prefLabel, skos:definition and skos:altLabel (AGSC-05-17); date/modified to dcterms:created/dcterms:modified; clusters[] to skos:member (AGSC-05-18); the fourteen Link keys and inline links per AGSC-05-16 — an inline Markdown link between two items of the Bundle produces exactly one asc:mentions triple from the referring item to the referenced one, whatever the number of inline references between them, and the triple has no computed inverse. Object properties come only from these keys: asc:uses, asc:usedBy, asc:excludes, asc:contradicts, asc:mentions, the ten Mode-2 properties of AGSC-05-16, and the two reachability edges asc:source and asc:review of AGSC-05-14/05-15, which come only from sources[] and verified[] (proved by graph-0024), plus asc:hasAttachment (AGSC-05-29) and asc:peerOrigin (AGSC-11-12). [design]
  • AGSC-05-28 A property that no rule of §5.3, §5.6, §5.7 or §11 emits MUST NOT ship in ontology/agsc.ttl (classes may be declared without a 1.0 emission: asc:Harness and asc:Proposal are reserved — a Harness is not RDF, AGSC-07-12, and a Proposal has an IRI rule but no 1.0 triples): before 1.0.0 it is deleted, and after 1.0.0 it is marked owl:deprecated true per AGSC-05-25. The ontology declares no asc:verdict — a Review's verdict lives in the forge, not in a file (AGSC-08-03) — and holds 12 classes and 40 properties, as tools/count-artifacts reports, among them the ten Mode-2 properties of AGSC-05-16 and the two item-reachability properties asc:source/asc:review of AGSC-05-14/05-15, proved by graph-0023 and graph-0024. (This rule governs the vocabulary terms the ontology declares; the annotation properties on the ontology node that AGSC-05-25 requires are not terms of this vocabulary and are not emitted by any rule, which is not a fault under this rule.) [NFR-02]

5.7 Attachments and ports in the graph

  • AGSC-05-29 Each attachments[] entry MUST be instantiated as an asc:Attachment (⊑ prov:Entity) whose IRI is <item-IRI>#attachment-<n>, <n> the 1-based index in authored order — a fragment IRI, blank-node-free (AGSC-05-08) — linked from the item by asc:hasAttachment, carrying dcterms:format = media_type, asc:sha256 = the lowercase-hex SHA-256 of the file bytes at build, dcterms:title = alt, dcterms:license = the resolved licence identifier, and dcterms:source = the relative path. [PRD-059]
  • AGSC-05-30 produces[] and consumes[] map to the datatype properties asc:produces and asc:consumes (xsd:string, one triple per name, on the item); task_state maps to asc:taskState (xsd:string); verdict_digest is not exported. These rows extend the AGSC-05-26 table; AGSC-05-28 (which names §5.7 and §11) is satisfied because each property has exactly one emitting rule. [design]

5.8 Literal datatypes and N-Quads escaping (the two pins that make --peer meaningful)

  • AGSC-05-31 Literal form. Every literal this specification emits takes exactly one of three forms and no other: (a) a language-tagged literal, used only for skos:prefLabel, skos:altLabel and skos:definition, whose tag is the item's lang (default en, AGSC-01-13) lower-cased, and which MUST NOT also carry a datatype; (b) a typed literal carrying the datatype named for that property in the AGSC-05-26 table or in AGSC-05-30; (c) a plain literal, which is xsd:string — every property whose AGSC-05-26/05-30 datatype is xsd:string takes this form and never form (b); every DCTerms, PROV and schema.org literal this specification emits takes form (c) — schema:license and schema:usageInfo among them (AGSC-05-26) — except dcterms:created/dcterms:modified, which take form (b) with the xsd:dateTime the AGSC-05-26 table names for date/modified — and MUST be written without an explicit ^^xsd:string in Turtle and with ^^<http://www.w3.org/2001/XMLSchema#string> in N-Quads, per the RDF 1.1 rule that a plain literal is an xsd:string. A producer MUST NOT invent a datatype, MUST NOT emit rdf:langString explicitly, and MUST NOT emit an empty language tag. Booleans are xsd:boolean true/false; integers are xsd:integer with no leading +, no leading zeros and no exponent; instants are xsd:dateTime rendered by AGSC-04-10. [AGSC-10-12]
  • AGSC-05-32 N-Quads escaping. In graph.nq a literal's lexical form is written with exactly these escapes and no others: \\ for U+005C, \" for U+0022, \n for U+000A, \r for U+000D, \t for U+0009, and \u00XX (four lowercase hex digits) for every other character below U+0020. Every character at or above U+0020, other than " and \, is written as itself in UTF-8 — \uXXXX and \UXXXXXXXX MUST NOT be used for characters a producer could write directly, so that two producers emit the same bytes. IRIs are written between < and > with the same control-character escaping and no percent-re-encoding (AGSC-11-12). Lines end with . and a single LF and are sorted by their serialized bytes (AGSC-04-13). graph.ttl uses the same lexical forms inside its own syntax. Vector graph-0012. [design]
