AGSC-05 — Graph: IRIs, RDF views, SKOS, PROV

SummaryHow items become a graph with web addresses, the three RDF views, the ontology and its alignment to SKOS, PROV-O and Dublin Core, and the byte-level pins.

Status of this document

Specification 1.1.0, released and tagged on 2026-11-13. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

Part 2 of 2, 5.7 to 5.10. This section is published in two parts so that each page stays within the budget of AGSC-06-21; a rule's link names the part that carries it. Part 1 carries 5.1 to 5.6.

In plain language

Every item is a node with a web address (<site>/concepts/<slug>/), and every link is an edge. The Bundle is exported as JSON-LD, Turtle and N-Quads — one graph, three syntaxes — plus one file per item; those are the four RDF views, and RDF/XML is not emitted at 1.x (AGSC-05-06).

The vocabulary. A small OWL 2 RL ontology (ontology/agsc.ttl, CC0) with 12 classes and 41 properties, aligned to SKOS (concepts and clusters), PROV-O (episodes, procedures, gates, reviews, sources) and Dublin Core. There is deliberately no common Item class.

No inference at build. Everything a consumer might expect from reasoning — inverses, cluster nesting — is written out explicitly, so what you read is what was emitted.

Byte pins. Literals take exactly one of three forms (language-tagged, typed, plain), N-Quads escaping is fixed, and because the graph has no blank nodes its canonical form is just a sort.

Attachments, ports and citations. Attachments are nodes with a SHA-256; ports and task states are datatype properties; a citation of another node becomes rdfs:seeAlso plus asc:peerOrigin.

This box explains; the rules below decide. New to the notation? See how to read the specification.

5.7 Attachments and ports in the graph

5.8 Literal datatypes and N-Quads escaping (the two pins that make --peer meaningful)

  • AGSC-05-31 Literal form. Every literal this specification emits takes exactly one of three forms and no other: (a) a language-tagged literal, used only for skos:prefLabel, skos:altLabel and skos:definition, whose tag is the item's lang (default i18n.default, else en, AGSC-01-13) lower-cased, and which MUST NOT also carry a datatype; (b) a typed literal carrying the datatype named for that property in the AGSC-05-26 table or in AGSC-05-30; (c) a plain literal, which is xsd:string — every property whose AGSC-05-26/05-30 datatype is xsd:string takes this form and never form (b); every DCTerms, PROV and schema.org literal this specification emits takes form (c) — schema:license and schema:usageInfo among them (AGSC-05-26) — except dcterms:created/dcterms:modified, which take form (b) with the xsd:dateTime the AGSC-05-26 table names for date/modified — and MUST be written without an explicit ^^xsd:string in Turtle and with ^^<http://www.w3.org/2001/XMLSchema#string> in N-Quads, per the RDF 1.1 rule that a plain literal is an xsd:string. A producer MUST NOT invent a datatype, MUST NOT emit rdf:langString explicitly, and MUST NOT emit an empty language tag. Booleans are xsd:boolean true/false; integers are xsd:integer with no leading +, no leading zeros and no exponent; instants are xsd:dateTime rendered by AGSC-04-10. (Amended 2026-10-10 for 1.0.0: the default language tag is i18n.default, else en, as AGSC-01-13 and the reference engine already had it) [AGSC-10-12]
  • AGSC-05-32 N-Quads escaping. In graph.nq a literal's lexical form is written with exactly these escapes and no others: \\ for U+005C, \" for U+0022, \n for U+000A, \r for U+000D, \t for U+0009, and \u00XX (four lowercase hex digits) for every other character below U+0020. Every character at or above U+0020, other than " and \, is written as itself in UTF-8 — \uXXXX and \UXXXXXXXX MUST NOT be used for characters a producer could write directly, so that two producers emit the same bytes. IRIs are written between < and > with the same control-character escaping and no percent-re-encoding (AGSC-11-12). Lines end with . and a single LF and are sorted by their serialized bytes (AGSC-04-13). graph.ttl uses the same lexical forms inside its own syntax. Vector graph-0012. [design]

5.9 Readings, questions, suggestions, views and consequences

  • AGSC-05-33 A pure function derives readings of the Link graph and never stores them. A reading is {source, key, target, because}, and because is a non-empty list of steps {rule, from}, where rule is exactly one of inverse, symmetric, transitive or closure and from is a list of the edges [source, key, target] the step used. The function covers four kinds: (a) the computed inverse of each authored edge (rule inverse, one edge in from); (b) the other direction of each authored edge of related, excludes or contradicts (symmetric, one edge); (c) for each key whose Transitive reading cell in AGSC-03-01 is yes, except requires, and for its computed inverse, each pair (a, c) of two different items joined by a chain of two or more edges of that one key (transitive, the chain in from, in order); (d) the same for requires and its inverse (closure). The chain of (c) and (d) is the first one a breadth-first walk from a meets, expanding each frontier in code-point slug order, as AGSC-07-04 does, and keeping for each item the predecessor from which the walk first reached it, so it is a shortest chain and the same in every implementation. A reading from (c) or (d) has exactly one step in because, whose from is the chain. A pair that already holds an edge of the key, authored or computed, is not a reading. Readings are ordered by source, then key, then target, by code point. The edges of (a) and (b) are materialized in the graph files as AGSC-05-23 requires and are unchanged; nothing of (c) or (d) is written to graph.jsonld, graph.nq, graph.ttl or pages/<slug>.jsonld, and no reading changes a composition (AGSC-03-18, AGSC-07-10). No reasoner runs (AGSC-05-23). (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: so that every relation the Link graph holds without being authored can be explained) [AGSC-03-01]

Every list is sorted by code point and has no repeats; a subject is never in its own answer (for the questions whose answer is a list of slugs). It writes dist/suggestions.json, JCS-canonical (AGSC-04-04) followed by one LF, an object with bundle_version (the content version, AGSC-04-25) and suggestions, an array sorted by source, target (a null target first), key and generator by code point, each entry {evidence, generator, key, source, target}; the file is local, is never a route and never in build.out. Five generators exist, and a suggestion is made only for a pair of two different items with no Link between its items in either direction, authored or computed, and, for the related of G1, G2 and G3, neither of which is a cluster (AGSC-05-20, AGSC-03-25): G1 an inline link in the body of source to target (an asc:mentions edge, AGSC-03-11) suggests related, evidence [{"kind": "mention"}]; G2 two items citing two or more of the same sources[].resource strings, compared exactly, suggest related from the earlier slug to the later, evidence [{"kind": "shared-source", "resource": ...}] for each such resource in code-point order; G3 the title or an alias of target, of at least four code points and not of kind term, found in the body of source as a whole phrase, that is, compared after NFC, then upper-casing, then lower-casing (as AGSC-01-40 (b)) and not preceded or followed by a code point of Unicode general category L or N, outside code spans and fenced blocks, suggests related, evidence [{"kind": "phrase", "phrase": ...}]; G4 a lesson with no derived-from suggests derived-from toward each episode that has any Link or mention edge to or from it, and when there is none one entry whose target is null, evidence [{"kind": "episode"}] or [{"kind": "none"}]; G5 the same phrase match as G3 against an item of kind term suggests uses, evidence as for G3. 5.10 The domain layer: a site's own vocabulary, warrants, invariants and questions

A Bundle with no domain object (AGSC-01-41) whose items state no domain key (AGSC-02-25, AGSC-03-27) is a Bundle of 1.0, and every file this chapter describes is byte-identical to the one 1.0 writes for it. The rules below name the files that change when the layer is used. (Amended 2026-11-10 for 1.1.0: "and no domain key" added, because a warrant adds its two triples on any node (AGSC-05-40, graph-0045); domain_role and domain_context add theirs whenever the domain object exists (AGSC-05-39).)

  • AGSC-05-38 A node MAY ship one site vocabulary, a Turtle file at the path of domain.vocabulary (AGSC-01-41), and the file MUST (a) be UTF-8, LF, NFC and blank-node-free (AGSC-05-08), and declare exactly one owl:Ontology, whose IRI, which MUST NOT end in # or /, followed by # is the site namespace; (b) put every class and every property it defines in the site namespace or in the namespace of a context that domain.contexts declares (AGSC-08-32), and none of them is the namespace of AGSC-05-02, OWL, RDF, RDFS, SKOS, DCTerms, PROV-O or XSD; (c) use only these predicates — rdf:type, rdfs:label, rdfs:comment, rdfs:seeAlso, rdfs:isDefinedBy, rdfs:subClassOf, rdfs:subPropertyOf, owl:deprecated, owl:disjointWith, owl:equivalentClass, owl:equivalentProperty, owl:imports, owl:inverseOf, owl:propertyDisjointWith, owl:versionIRI, owl:versionInfo, dcterms:title, dcterms:description, dcterms:created, dcterms:modified, dcterms:issued, dcterms:creator, dcterms:publisher, dcterms:license, dcterms:isReplacedBy, vann:preferredNamespacePrefix, vann:preferredNamespaceUri and skos:definition — and these rdf:type objects — owl:Class, owl:ObjectProperty, owl:Ontology, owl:AnnotationProperty and the property characteristics owl:SymmetricProperty, owl:AsymmetricProperty, owl:IrreflexiveProperty, owl:TransitiveProperty, owl:FunctionalProperty and owl:InverseFunctionalProperty (the sets that tools/validate-ontology applies to ontology/agsc.ttl, AGSC-05-22, less rdfs:domain, rdfs:range and owl:DatatypeProperty, which (f) and (g) exclude), with the declarations of AGSC-05-25 for the classes of other vocabularies it names, and stay inside OWL 2 RL as AGSC-05-37 lists it; (d) give every term it defines an rdfs:label; (e) make each class it defines a subclass, by rdfs:subClassOf directly or through other classes of the file, of exactly one of the six item classes asc:Concept, asc:Lesson, asc:Episode, asc:Procedure, asc:Cluster, asc:Gate (two item classes would entail the contradiction of AGSC-05-26a), and state no class it defines owl:equivalentClass to an item class; (f) make each property it defines an owl:ObjectProperty that is a sub-property, by rdfs:subPropertyOf directly or through other properties of the file, of at least one of the fourteen link properties of AGSC-03-01 (skos:related, skos:broader, skos:narrower, asc:uses, dcterms:requires, asc:excludes, prov:wasDerivedFrom, asc:contradicts, dcterms:replaces, asc:implements, asc:verifies, asc:covers, asc:blockedBy, asc:decidedBy), give it no super-property that is neither one of these nor an object property the file defines, state it owl:equivalentProperty to none of asc:uses, asc:excludes and asc:contradicts, and name on both sides of each owl:inverseOf statement an object property it defines; in (e) and (f) an owl:equivalentClass or owl:equivalentProperty statement counts as rdfs:subClassOf or rdfs:subPropertyOf in both directions; and (g) declare no rdfs:domain and no rdfs:range for a property (a constraint on where a property may be used is an invariant, AGSC-05-41). A violation of (a) to (g) is the error AGSC-E420, reported by lint and by tools/validate-ontology run on the file. The file is published: every triple of it is a triple of graph.nq, graph.ttl and graph.jsonld in the Bundle's named graph and is in no pages/<slug>.jsonld, so a reader that knows only the item classes still sees each site class as a subclass of one and each site property as a sub-property of one link property (graph-0044); in graph.ttl the terms of OWL are written as full IRIs in angle brackets, because the prefix block of AGSC-05-10 (a) is not changed. The skos:definition of a term is its meaning for people, and the vocabulary explorer of the query page shows it. (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: for the optional domain layer) (Amended 2026-11-03 for 1.1.0: (f) names both sides of owl:inverseOf, because the inverse edge of a domain link is materialised (AGSC-03-27) and any other term there, such as rdf:type or a link property, would be written into the graph as a predicate) (Amended 2026-11-10 for 1.1.0: equivalence counts in (e) and (f) as OWL 2 RL entails it (scm-eqc1, scm-eqp1), so a class stated equivalent to a class under another item class has two item classes; a class equivalent to an item class itself would make every item of that class an instance of it, and a property equivalent to asc:uses, asc:excludes or asc:contradicts would give that property the super-property AGSC-05-26a forbids; and a super-property outside the link properties and the file, such as rdf:type, would be stated by prp-spo1 in export --closure and in the data graph of verify (AGSC-05-37). The engine and tools/validate-ontology report each as AGSC-E420; a site vocabulary is new in 1.1.0, so no 1.0 input is refused.) (Amended 2026-11-11 for 1.1.0: in (c) the explicit lists govern where they and the parenthesis differ: the sets of tools/validate-ontology also hold voaf:Vocabulary, which that tool accepts for ontology/agsc.ttl only and which the list of types does not name, so a site vocabulary does not use it.   • AGSC-05-39 An item that states a domain type, a role, a context or domain links (AGSC-02-25, AGSC-03-27) adds exactly these triples to the four views of AGSC-05-06 and to its own pages/<slug>.jsonld, and no others: domain_type a second rdf:type, the class of the vocabulary that the key names (the item keeps its item class); domain_role one schema:additionalType whose object is the role as an xsd:string; domain_context one dcterms:isPartOf to the IRI of the cluster that declares the context (AGSC-08-32); each member of domain_links, <item> <property IRI> <target IRI>, and the inverse or symmetric edge the vocabulary declares for it (AGSC-03-27). Under AGSC-05-26a and AGSC-05-20 a site property that specialises skos:related, skos:broader or skos:narrower is refused on a cluster (AGSC-03-27). graph-0044 states a complete file. (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: for the optional domain layer) (Amended 2026-11-02 for 1.1.0: the discovery document and the NOW page named among the files that change, since they carry the digests and the fingerprint of the graph files) (Amended 2026-11-10 for 1.1.0: one condition for the keys: role and context are written whenever the domain object exists, as the rule reads without a condition; the engine wrote them only with a vocabulary file.   • AGSC-05-40 A warrant states why a term belongs to the vocabulary: what grounds it and the kind of ground. The key warrant of AGSC-02-25 is an object with the members source, a non-empty single-line string, and type, exactly one of literary, user and organisational. These are the three warrants that ANSI/NISO Z39.19-2005 (R2010) names for the choice of terms: a literary warrant is use of the term in the published literature of the field, a user warrant is use of the term by the people who search for or ask about the subject, and an organisational warrant is the requirement of the organisation that keeps the vocabulary. The standard names the three kinds of warrant; the token organisational is the British spelling of its "organizational warrant" and is this specification's spelling, so there is no fourth kind. A warrant without a source, or without a type, or with another type, is the error AGSC-E512. An item that carries a valid warrant adds two triples on the item: <item> dcterms:source "<source>" and <item> asc:warrant "<type>", both xsd:string. asc:warrant is a datatype property of the vocabulary file from 1.1.0 (AGSC-05-25, AGSC-05-26) and the only term that the domain layer adds to it; graph-0045 states a complete file. A warrant is not an entry of sources[], evidence (AGSC-02-12) or a review, and it changes none of them. (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: the key warrant is new in 1.1.0 and optional) (Amended 2026-11-11 for 1.1.0: the trace bracket names PRD-076, the requirement of the domain layer.) [design, PRD-076]
  • AGSC-05-41 A node MAY state invariants and competency questions of its own, in the files at domain.shapes and domain.questions (AGSC-01-41), and verify and ci check them (AGSC-09-20). Both are evaluated over one data graph, the published projection (AGSC-06-30) as graph.nq holds it together with the closure of AGSC-05-37. Invariants are SHACL (SHACL 1.0, W3C Recommendation, 20 July 2017, https://www.w3.org/TR/shacl/, read 29 October 2026), not a language of this specification, and the engine evaluates exactly this SHACL Core subset and nothing else: the classes sh:NodeShape and sh:PropertyShape, the property sh:path, the severities sh:Violation, sh:Warning and sh:Info and the node kinds sh:IRI, sh:Literal, sh:BlankNode and their unions; node shapes named by IRI, and property shapes that are the object of sh:property and MAY be blank nodes (an RDF list that is the value of sh:in is not a shape); the targets sh:targetClass, sh:targetNode, sh:targetSubjectsOf and sh:targetObjectsOf; a property path that is a predicate IRI or sh:inversePath of one; and the constraint components sh:class, sh:datatype, sh:nodeKind, sh:minCount, sh:maxCount, sh:hasValue, sh:in, sh:pattern (without sh:flags), sh:minLength, sh:maxLength, sh:node and sh:property, with sh:severity and sh:message. A shapes file that uses any other term of the sh: namespace, or names a node shape by a blank node, is the error AGSC-E420. Each result of the validation is one finding AGSC-E421, an error where the severity is sh:Violation and a warning for sh:Warning and sh:Info, naming the focus node, the source shape and the message; the findings are ordered by focus node, source shape and path by code point. A competency question is an object of the JSON array in domain.questions with the members expected, id (a slug), query and question (the sentence for people). query is SPARQL 1.1 Query (W3C Recommendation, 21 March 2013, https://www.w3.org/TR/sparql11-query/, read 29 October 2026) of the form SELECT or ASK, limited to this subset: basic graph patterns; the property-path operators /, ^, + and *; FILTER with comparison, &&, ||, ! and NOT EXISTS; DISTINCT, ORDER BY and LIMIT, where the ORDER BY of a SELECT names every projected variable (for SELECT *, every variable of its triple patterns) and a SELECT has LIMIT only with such an ORDER BY; a query outside it is AGSC-E420. expected is for ASK a boolean and for SELECT an object {"rows": [[...]]} whose cells are the terms in N-Triples form (an unbound variable is the JSON null), rows in the order of ORDER BY where the query has one and otherwise sorted cell by cell, each cell as its N-Triples string, by code point. A questions file that is not a JSON array of such objects, or that repeats an id, is AGSC-E420. An answer that differs is the error AGSC-E422, naming the id. The ten questions of AGSC-05-34 are the engine's and are not in this file. A node that declares neither file runs neither check. (Amended 2026-10-29 for 1.1.0: rule added for 1.1.0: for the optional domain layer) (Amended 2026-11-03 for 1.1.0: ORDER BY names every projected variable and LIMIT needs it, because SPARQL leaves the order of tied or unordered rows to the engine, so the rows a LIMIT keeps and the order an expected states would otherwise depend on the engine and on the order of the data) (Amended 2026-11-11 for 1.1.0: readings of the engine, recorded so that a second implementation agrees; no result changes. (1) AGSC-E420 is also the error for a shapes file that stays inside the terms of the subset and is ill formed: a parameter whose value is of the wrong kind, a parameter stated twice, a sh:path that is a list, an sh:pattern that does not compile, a property shape without exactly one sh:path; and for a query that the SPARQL parser accepts and the subset refuses, such as a FILTER other than a comparison, &&, ||, ! or NOT EXISTS, or an ORDER BY of anything but a variable. (2) The comparisons of a FILTER are =, !=, <, >, <= and >=. (3) The columns of a SELECT * are the variables of its triple patterns in code-point order of their names. (4) A SELECT without ORDER BY is compared as two sorted lists: the rows of the answer and the rows of expected are both sorted cell by cell before they are compared. (5) A cell that is a plain string is written without ^^xsd:string. (6) The pattern of sh:pattern is read in the syntax that JavaScript and Python's re share, because SHACL names the XPath syntax and neither engine runs it. (7) A finding names a property shape that is a blank node as <parent shape> > <path>.) (Amended 2026-11-11 for 1.1.0: the trace bracket names PRD-076, the requirement of the domain layer.) [design, PRD-076]
