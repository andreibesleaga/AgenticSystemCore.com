AGSC-00 — Overview, terms, conformance model

SummaryWhat the specification covers, the words it uses, what it means to conform, and how versions change.

Status of this document

Specification 1.1.0, released and tagged on 2026-11-13. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

Part 2 of 2, 0.5 to 0.7. This section is published in two parts so that each page stays within the budget of AGSC-06-21; a rule's link names the part that carries it. Part 1 carries 0.1 to 0.4.

In plain language

What it is. AgenticSystemCore is a file format plus a few fixed outputs. You write knowledge as Markdown files with a small YAML header, keep them in one directory with one configuration file, and a conforming tool turns that directory into a website, a graph, a search index, an agent-facing text file, a chunk export and a discovery document — the same bytes every time, on any machine.

What conformance means. A tool is a reader, a writer or a full engine; a published site is a node at Level 0 to 3. A claim names the class or Level, the spec_version and the test vectors passed. There is no badge and no registry — the vectors are the proof.

Terms you will meet. A Bundle is the directory. An Item is one file; its type is one of concept, episode, procedure, lesson, cluster or gate. NOW is a generated summary page. Words like card, deck or page are never types.

How versions move. The spec_version is MAJOR.MINOR.PATCH. A MINOR adds and never removes; a reader must ignore what it does not know and must not fail on a higher MINOR. Only a MAJOR may break.

Where requirements live. Every product requirement that is served by the shape of the artefacts rather than one sentence is cited in §0.5, so a validator can check the citation.

Two terms complete the language for Mode 5 — an agent lane (a declared, budgeted agent that proposes, never writes) and the live board — and one rule names the whole declared scope of the specification with the version at which each part becomes normative.

One section states what readers and writers must do across versions — ignore and keep what they do not know, carry it through a round trip, never emit for a version they do not claim — closes the list of plugin kinds at eight, and reserves names for version 1.1.

This box explains; the rules below decide. New to the notation? See how to read the specification.

0.5 Requirement traceability for artefact-level requirements

  • AGSC-00-18 Seven product requirements are served by the shape of the artefacts rather than by a single rule sentence, so they are cited here and a validator checks the citation exists (AGSC-09-91's trace-tag check). NFR-01 (maintained libraries at exact pins, no network and no clock at run time) is served by AGSC-06-16, whose prebuilt inverted index is required to need no runtime dependency, and by AGSC-05-23, which forbids a build-time reasoner. NFR-09 (unattended operation) is served by AGSC-04-03, which removes every interactive and ambient input from a build, and by AGSC-08-20, whose ledger is derived rather than maintained. NFR-13 (offline and cross-platform) is served by AGSC-04-01 (byte-identical on every operating system and runtime), AGSC-04-24 (which artefacts that covers) and AGSC-10-12 (a peer check that MUST accept two local files). PRD-008 (version and changelog agreement) is served by AGSC-00-17, which requires spec_version in both the Bundle root document and the configuration, and an item's MAJOR to match the configuration's. PRD-009 (scaffold on initialisation) is served by AGSC-02-94, which requires init to synthesize files that validate against their own schemas — in part only: the example Concepts, type folders and forge workflow that PRD-009 also names are planned for a later MINOR as capabilities of the reference distribution (AGSC-00-20), and ci passes only after the publisher's steps that AGSC-02-94 names. PRD-012 (fully functional with no model key) is served by AGSC-07-01, which forbids a composition from requiring a network, a key or a server, and by AGSC-08-27, which makes the review lane lint-only with any model review opt-in and non-gating. PRD-016 (failure knowledge as items, not an error-book file) is served by the lesson item type of AGSC-00-05 and its heading contract in AGSC-02-21; no rule emits an error-book artefact and none may be added at 1.x. A clarification: no tool behaviour changes.) (Amended 2026-10-10 for 1.0.0: the example content, type folders and workflow were said to be in no version's scope; they are planned for 1.1. 0.6 Compatibility, extension points and reserved names

This section is the one place a reader and a writer are told what to do with something this specification does not define. It grants no tolerance that §0.4 and the chapters did not already grant: it states the whole of it once, names the rule that owns each clause, and answers three questions no other section answers — what survives a round trip, what a tool may never originate, and which extension points exist at all.

  • AGSC-00-21 Ignore and preserve: reading a document of another version. A tool whose spec_version MAJOR equals the document's (AGSC-00-15) MUST NOT fail on a construct it does not know, in a document it did not author — a received discovery document, a peer board, a file under import or --peer, an item written by another node.   • AGSC-00-22 Round trip. Everything AGSC-00-21 preserves MUST survive a round trip unchanged — the same member name and the same value, in the same file. lint --fix MUST NOT add, remove or infer a key and MUST reproduce every preserved member (AGSC-04-19, AGSC-04-20); export --markdown and export --okf MUST carry every authored frontmatter key, the preserved and the vendor ones included (AGSC-01-26); a memory adapter MUST be lossless in both directions for every key it claims and MUST carry the rest through unread (AGSC-01-26a); and import MUST write what it read (AGSC-01-22, AGSC-01-23). The only normalisation admitted anywhere on this path is the encoding and key-ordering profile of AGSC-04-19, which moves a key and never changes a value. A tool that cannot preserve a member MUST refuse the operation rather than drop it, because a silent drop is the one failure a consumer of a round trip cannot detect. Vector lint-0027. [PRD-026, NFR-02, AGSC-04-19]
  • AGSC-00-23 A tool originates only what its declared version specifies. A tool MUST NOT emit, and MUST NOT write into a Bundle it authors, a key, value, relation, surface, route, attribute or file that this specification reserves to a later version (AGSC-00-20, AGSC-00-25); carrying one through that arrived from elsewhere under AGSC-00-21 and AGSC-00-22 is not originating it. The fault takes the code its construct already carries and no code is minted for it: in agsc.config.json it is AGSC-E004, fatal, because configuration is closed and is the node's own declaration (AGSC-01-18); in item frontmatter it is the warning AGSC-E207, or AGSC-E304 for a link-shaped key, and the member is preserved, because an item may have been authored on another node and this specification never destroys an author's bytes; in a value of a closed operator list — an export --steer target (AGSC-01-28), a compose --emit target (AGSC-07-18), a run.allow[] program (AGSC-09-94) — it is AGSC-E203; and where a node's own published bytes carry a member of a version its discovery document does not declare, validate-wellknown reports AGSC-E210, which already names emitted bytes that disagree with their declaration (AGSC-11-19, AGSC-09-93). [PRD-010, AGSC-00-20, AGSC-09-15]

  • AGSC-00-24 Extension points: the closed list of plugin kinds. Everything this specification admits as a replaceable part is one of the eight kinds below, and no other extension point exists at 1.x: a capability that is none of them is a change to this specification, not a plugin. Three obligations bind every kind, whatever else its own rule says. (i) A plugin reaches the network only where its kind's row grants it, and no row grants it during build, lint, verify or ci (AGSC-04-03, AGSC-08-30). (ii) A plugin writes only the outputs its row names, never inside content/ (AGSC-08-02), never outside the Bundle root and never through a link (AGSC-01-16, AGSC-01-35). (iii) A plugin never changes the canonical bytes of a 1.0 surface: the artefacts of AGSC-04-24 and the route set of AGSC-06-01 are fixed by this specification and are not a plugin's to alter.

  • AGSC-00-25 Reserved names. Three names are reserved now, so that a 1.0 tool meets one without failing or guessing and a later MINOR may give it meaning; AGSC-00-20 names that MINOR for each of the three. A 1.1 tool treats the three exactly as a 1.0 tool does.

    • weights — an item frontmatter key, reserved to a later MINOR for weighted Links: an object whose member names are Link keys and whose values map a target slug to a number. It is reserved as a sibling key and not as a member inside a Link value, because AGSC-03-02 fixes a Link value to a slug string, so a 1.0 reader meeting an object there would have to fail where this section requires it to ignore. At 1.x it is preserved verbatim and reported as the unknown-key warning AGSC-E207 (AGSC-02-05, AGSC-00-21), and a 1.0 tool MUST NOT originate it (AGSC-00-23).
    • routing — a configuration name, reserved to a later MINOR for model-routing declarations, both at the top level of agsc.config.json and inside each agents[] entry. Configuration is closed, so a 1.0 tool MUST recognise the name and reject it with AGSC-E004, exactly as it rejects build.rdfxml and build.feed (AGSC-01-18, AGSC-00-20): a 1.1 configuration then fails loudly instead of routing silently to nothing.
    • executable — a compose --emit target name, reserved to a later MINOR for an executable Harness, together with the optimisation step that produces it, which will run after Step 5 of AGSC-07-08 and be verdict-neutral as Step 5 is. At 1.x the emitter registry of AGSC-07-18 is closed and the step set of AGSC-07-08 is exactly five, so compose --emit executable is AGSC-E203 and no sixth step runs.

    A reserved name is not an x-<vendor>-<key>: the vendor namespace is open, never interpreted and never given a meaning by this specification (AGSC-02-05a), while a reserved name is this specification's own and will acquire one. Reserving a further name is a MINOR with a registry row and a vector, exactly as a new Link key is (docs/SPEC.md §8). Vectors lint-0027, bundle-0006, cli-0016 (Amended 2026-10-07 for 1.0.0: cli-0009 is withdrawn and cli-0016 replaces it). (Amended 2026-10-29 for 1.1.0: the three names move from 1.1 to a later MINOR; behaviour is unchanged, a 1.1 tool treats them as a 1.0 tool does) [PRD-010, AGSC-00-20, AGSC-03-01]

0.7 Normative references

The rules cite the documents below normatively: a rule that names one requires what the named part of it says, in the edition given here. A document that a rule names only for background is informative and is not listed — among them RDF Dataset Canonicalization (RDFC-1.0), which AGSC-04-16 names to say how graph.nq differs from it; the related discovery documents and systems of AGSC-06-35; the formats of the composition files of AGSC-07-12, whose bytes the composition cases fix; and RFC 4151, RFC 6892, RFC 7284, RFC 7595, RFC 8141 and RFC 9727; and, from 1.1, the proposals and drafts a rule names without requiring them (the Agentic Resource Discovery proposal, the AI Catalog draft, FAIR Signposting, the llms.txt proposal, Eric Evans, "Domain-Driven Design", Addison-Wesley, 2003, whose context-map relationships AGSC-11-24 borrows).
