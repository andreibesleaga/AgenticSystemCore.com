AGSC-01 — Bundle: files, folders, encoding, configuration

SummaryThe directory that holds a node's knowledge: its layout, slugs, encoding, the one configuration file, the optional agent-lane declarations, and how foreign content comes in and goes out.

Status of this document

Specification 1.0.0-rc.7, a release candidate tagged on 2026-10-08. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

In plain language

The directory. content/ holds the items in type folders, content/attachments/<slug>/ holds media, and agsc.config.json is the single configuration file. Nothing else is required.

Names. Every item has a slug: lowercase letters, digits and single hyphens, 1–64 characters, unique in the Bundle. The slug is the file name and the last part of the item's web address.

The configuration file. It is closed: a key the specification does not name is an error, except vendor keys that start with x-. It carries the site base URL, licences, tag lists, release switches, peers, channels and the boundary parameters (federation, chunks, contribute, visibility, attachments), each with a default and a maximum.

Import. A folder of bare Markdown can be adopted with one command; unknown frontmatter keys are kept and reported as warnings, never errors.

Export. Markdown, JSON-LD and JSONL exports are lossless round trips; the prose exports carry the Content Use Terms, or the prose licence the node names in their place.

Channels. Messages from a mailbox or a chat can become proposals, under guards: a sender list, a rate, a cap on open proposals, injection checks.

Paths. A relative path never contains .., . segments, a leading slash, a backslash or a NUL, and always resolves inside the Bundle.

Agent lanes. The configuration may declare agents: a name, a kind (model or program), the forge identity and the accountable person, the model, what it may do, which item types it may touch, the channel its proposals go through, a schedule, a monthly budget, how many items one proposal may create (default twenty) and how many tasks it may hold at once (default one). Disabled unless switched on. The whole node has one cap on model spend of every kind, ten dollars a month unless changed, and the agents' budgets may not add up to more. Anything host-specific or secret — the cap, an agent's switch or budget, the model key — can be set in a .env file in the Bundle root that is never committed; init lists the recognised names in .env.example.

This box explains; the rules below decide. New to the notation? See how to read the specification.

1.1 Layout

  • AGSC-01-01 A Bundle MUST be a directory tree containing content/ and exactly one agsc.config.json at its root. One repository is one Bundle. An input file a verb requires and cannot open is AGSC-E901. [design]
  • AGSC-01-02 Items MUST live at content/<type-plural>/<slug>.md where <type-plural> ∈ concepts, episodes, procedures, lessons, clusters, gates. [design]
  • AGSC-01-03 The type key in frontmatter is authoritative and MUST match the containing folder; a mismatch is an error (AGSC-E205). [design]
  • AGSC-01-04 content/index.md is the Bundle root document. It MUST carry spec_version, okf_version, title, description and base (the IRI base of every item, AGSC-05-01; it MUST equal site.base; a mismatch is AGSC-E204), and it MUST NOT carry type; it is not an item and does not enter the graph as an item. A type key on the Bundle root is AGSC-E205 — a file-placement violation, because the root is not an item — and bundle.schema.json refuses it. [OKF v0.2]
  • AGSC-01-05 index.md MAY exist in any folder (OKF reserved). _index.md and README.md MUST NOT be used as items. A reader MUST NOT read a README.md or _index.md in any folder under content/ as an item, and SHOULD report each one it skips as the warning AGSC-E506. [design]
  • AGSC-01-06 Non-knowledge site pages live in site/*.md, outside content/. They are rendered but MUST NOT appear in the graph, in search.json or in llms.txt item lists. [design]
  • AGSC-01-07 Diagram sources live at content/diagrams/<slug>.diagram. A compiled .svg MUST NOT be committed; it is produced into the build output as part of the item's page and not as a route of its own (AGSC-02-13) — .svg names the compiled artefact, never a URL, so AGSC-06-01's "exactly this route set" stays exact. The .diagram source grammar, and the compiler that reads it, are implementation-defined at 1.x: no rule of this specification pins a compiled byte, two conforming writers MAY draw the same source differently, and a conformance claim MUST NOT assert cross-implementation byte-identity for a compiled diagram (AGSC-04-24 already excludes generated HTML on the same ground). A picture whose bytes must be portable is an SVG attachment under AGSC-02-98, which is authored, hashed and served as itself. Pinning the grammar is a 1.1 candidate (AGSC-00-20). A .svg under content/diagrams/ is AGSC-E205, a file-placement violation. [design]
  • AGSC-01-08 www/ (build output) and dist/ (proposals, harnesses, gate verdicts and the forge enforcement artefacts of AGSC-08-12) are generated. An implementation MUST NOT read them as input to a build. [design]
  • AGSC-01-09 (reserved: stated by AGSC-07-12, whose only legal location is dist/harness/, together with AGSC-01-08; the id is never reused, AGSC-00-16.)

1.2 Slugs and identity

  • AGSC-01-10 A slug MUST match ^[a-z0-9]+(?:-[a-z0-9]+)*$ and be 1–64 Unicode code points long (minLength/maxLength in the schemas, AGSC-02-24) — a grammar that forbids a leading, trailing or doubled - by construction and compiles in RE2, Go and Rust. It is equivalent to ^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$ plus "MUST NOT contain --". [Agent Skills name rule]
  • AGSC-01-11 The slug is the file stem, the value of id when present, and the last path segment of the item IRI. Slugs MUST be unique across the whole Bundle regardless of folder (AGSC-E206). [design]
  • AGSC-01-12 A slug is permanent. A renamed or superseded item keeps its slug; the new item gets a new slug and the relationship is expressed with supersedes (§03). Reuse of a retired slug is an error, AGSC-E206 — the slug's second use in the Bundle, since the retired item is still present (AGSC-11-22); a writer that has the git-log file of AGSC-08-20b SHOULD also report a slug that an earlier commit deleted, which is invisible without history. [PRD-018]
  • AGSC-01-13 Language variants are <slug>.<lang>.md with lang a BCP 47 tag — compared case-insensitively, the file suffix and every emitted tag being the lower-cased form (AGSC-05-31) — equal to the file's lang key, and they are reserved to 1.1 (AGSC-00-20). At 1.0 a file named <slug>.<lang>.md is a second use of its primary's slug, AGSC-E206, and no variant route is emitted; the 1.1 MINOR adds the route, the tags and the vectors and removes nothing. What follows is the 1.1 definition. The unsuffixed file is the primary and owns the slug, the item IRI (AGSC-05-01) and the graph node; a variant shares that slug, is published at the route /<type-plural>/<slug>/<lang>/ (AGSC-06-01) and is emitted in RDF as the language-tagged literals of AGSC-05-17, never as a second item. A variant whose primary is missing is AGSC-E208; a variant whose suffix and lang key disagree, is AGSC-E205, while a lang that is not a well-formed BCP 47 tag is a schema pattern violation and takes AGSC-E204 (precedence, §9.4) — case is not part of well-formedness: a tag is compared case-insensitively and emitted lower-cased, so en-GB is valid input and en-gb is what is emitted. i18n.default in agsc.config.json names the primary's language (default en). [design]
  • AGSC-01-13a (qualifies AGSC-01-13) A variant MUST share its primary's Link keys and clusters[]; divergence is warning AGSC-E410. The primary's page MUST carry hreflang alternates for every variant. Everything else about variants is AGSC-01-13, and this rule is reserved to 1.1 with it. [PRD-055]

1.3 Encoding

  • AGSC-01-14 Every .md, .json, .ttl and .diagram file MUST be UTF-8 without BOM, MUST use LF line endings, MUST be NFC-normalized, and MUST end with exactly one LF (AGSC-E108); a .md file MUST NOT contain U+0000 or any other C0 control character except U+0009 and U+000A, anywhere including the body, which is also AGSC-E108 (Rationale: an HTML renderer replaces a NUL in a body while /chunks.jsonl carries it to every agent, so two writers could differ). A frontmatter or configuration string — a value or a member name — that is not a sequence of Unicode scalar values (a lone surrogate, which a UTF-8 file can hold only as a YAML or JSON escape such as \uD800) is also AGSC-E108, reported by lint, build and ci with its file and key: no JSON artefact can carry it (AGSC-04-05), and a build that meets one writes nothing. (Amended 2026-10-06 for 1.0.0: until 1.0.0-rc.6 such a string passed lint and failed build with AGSC-E601 naming no file.) [design]
  • AGSC-01-15 File discovery order MUST be a code-point sort of the repository-relative path, with / as the path separator in the sort key on every platform (a native \ separator MUST be converted before comparison). Locale collation MUST NOT be used. [design]
  • AGSC-01-16 An input file larger than its applicable cap MUST be refused with AGSC-E904 — attachments{max_bytes} for a file under content/attachments/ (AGSC-01-34; default 1 MiB, maximum 10 MiB), 1 MiB for every other input file. Archives MUST be refused entirely (AGSC-E903), and any path escaping the Bundle root MUST be refused with AGSC-E902. [design]

1.4 Configuration

  • AGSC-01-17 A Bundle MUST have exactly one configuration file, agsc.config.json, validated against schema/config.schema.json. A second configuration file MUST NOT be introduced. [PRD-006]
  • AGSC-01-18 Its keys are spec_version, site{base,title,tagline,author,analytics_token,tdm_crawlers[]}, bundle{id,license_prose,license_schema,operator}, ns{base,version}, releases{}, tags{allowed[]}, build{out} (rdfxml reserved; feed reserved — no 1.0 rule pins the bytes of /feed.xml, so the switch has nothing to switch on: both names are recognised and rejected with AGSC-E004 per AGSC-00-20), i18n{default}, lint{injection_patterns[]}, peers[], run{enabled,allow[]}, channels[]{name,adapter,author,owner,publish,allow[],rate{per_hour}}, budget{usd_month} (AGSC-01-38), and — under AGSC-11-01 and AGSC-01-34 — federation{hop_limit,fan_out,max_requests,redirect_limit,timeout_ms,max_bytes} (amended 2026-10-07 for 1.0.0: max_bytes, the per-response cap of the bound table of AGSC-11-01, was missing from this list), chunks{max_bytes}, contribute[]{mode,target,channel}, visibility, attachments{max_bytes}, surfaces[]{surface,target,version,access} (AGSC-11-16, declaration-only surfaces) and related[]{rel,href,type,profile,title} (AGSC-06-35, related-system links). channels[].author is a forge login: 1–64 characters from [A-Za-z0-9._-], beginning with a letter or digit (stated here once, because AGSC-01-36 refers to "the same grammar as channels[].author"; a forge with a narrower grammar is free to reject a wider value, and this specification encodes no one forge's rule). channels[].allow[] is an OPTIONAL array of strings naming the sender identities an adapter accepts (an empty or absent array accepts every sender) and channels[].rate{per_hour} an OPTIONAL integer bounding the messages one channel may ingest per hour, both required by AGSC-01-30's ingest guard; agents[] (AGSC-01-36) is a key as well; the environment file of AGSC-01-37 adds no key, it overrides them. site.tdm_crawlers[] is an OPTIONAL array of RFC 9309 product tokens, each matching ^[A-Za-z_-]+$ and compared case-insensitively, naming the crawlers whose operators state that they collect content in order to train a machine-learning model; AGSC-06-18 says what a writer does with it and when leaving it empty is a fault. site.analytics_token is an edge-analytics token consumed only by the hosting platform; a build MUST NOT emit it into any artefact and MUST NOT load a third-party script for it (AGSC-06-05). bundle.license_prose and bundle.license_schema are SPDX or LicenseRef- identifiers, defaulting to LicenseRef-AgenticSystemCore-Content-Use-1.0 and CC0-1.0; they supply the licence identifiers of AGSC-06-15, AGSC-01-26 and AGSC-07-16. i18n.default is OPTIONAL and defaults to en (AGSC-01-13/01-13a); peers[] is required by AGSC-10-12 (each entry a peer node's canonical well-known URL) and run{enabled,allow[]} is required by AGSC-09-94 (enabled default false). There is no build.search toggle: search.json is required unconditionally by AGSC-06-16, and a switch that could turn off a MUST would make the two rules unsatisfiable together. Configuration is closed: an unknown key is AGSC-E004. The single exception is the x-<vendor>-<key> namespace of docs/SPEC.md §8(2) — matching ^x-[a-z0-9]+(-[a-z0-9]+)+$, admitted by config.schema.json's patternProperties at the top level and on each channels[] entry while additionalProperties stays false — which every conforming tool preserves verbatim, never interprets and never reports as AGSC-E004 (the frontmatter twin is AGSC-02-05a). ns{base,version} is present for forward compatibility only: AGSC-05-02 makes the vocabulary IRI a constant of this specification, so no conforming tool reads a value other than the default and a Bundle that omits the object is identical to one that spells it out. A Bundle that omits bundle.license_prose or bundle.license_schema takes LicenseRef-AgenticSystemCore-Content-Use-1.0 and CC0-1.0; the values are echoed verbatim into /legal/, content/index.md license and every JSON-LD schema:license, and nothing else reads them. [PRD-006]
  • AGSC-01-19 build.out MUST default to www, MUST be a relative path under the grammar of AGSC-01-35 (never ., .. or absolute), and MUST NOT name content/, which a build never writes (AGSC-08-02), or dist/, which is generated (AGSC-01-08), or a path under either — its first segment compared ASCII case-insensitively, because on a case-insensitive file system Content is content/ — and a value that does is AGSC-E204 (Amended 2026-10-06 for 1.0.0: the grammar alone admitted content and dist, and a build with "out": "content" wrote the whole site into the source tree); a trailing / is accepted and stripped. site.base MUST be an absolute https: URL that is an origin — scheme, host and optional port, with no path — with or without a trailing slash (a trailing slash is stripped before IRIs are formed), and is the IRI base of every item (§05). (Amended 2026-10-02 for 1.0.0: the rule admitted a path prefix "so that a node may be published under a sub-path"; but the well-known address, robots.txt, security.txt and tdmrep.json have their meaning only at the root of an origin (RFC 8615 §3, RFC 9309 §2.3, RFC 9116 §3), and no build with a path prefix could succeed. At 1.0 a node occupies a whole origin; a path prefix is reserved to a later version, and the schema refuses one.) It MUST carry no query and no fragment, and no path segment may be . or .. (each of those breaks AGSC-05-01's IRI construction, and the schema refuses them). The single exception is the development placeholder http://localhost or http://localhost:<port> (optionally with a trailing slash), which adoption writes (AGSC-02-94) and which lint MUST report as AGSC-E506 — "set site.base before publishing" — until the owner replaces it. [design]
  • AGSC-01-20 releases is a boolean switchboard: an item carrying release: <key> is published only when releases[<key>] is true. An item with no release is always published. [PRD-021]
  • AGSC-01-21 tags.allowed is the closed tag vocabulary; a tag outside it MUST be reported (AGSC-E203). When tags is absent from agsc.config.json there is no closed vocabulary and AGSC-E203 is not raised for a tag; the 2–5 count of the §2.2 table is the warning AGSC-E213 — a tags array with fewer than 2 or more than 5 values (the schema carries no minItems/maxItems for it, because the bound is a warning and not an error). [design]
  • AGSC-01-25 bundle.operator is OPTIONAL and, when present, MUST be a human:<id> actor string (AGSC-02-07). It is the accountable operator of this Bundle and is the first source of prov.operator at adoption (AGSC-02-90). No other configuration key supplies an actor. [PRD-053]

1.5 Import tolerance

  • AGSC-01-22 Import of a foreign OKF v0.2 bundle MUST accept unknown type values (mapped to concept with a warning), unknown keys, missing optional fields, missing index.md and broken links. A broken internal link is a Gate failure for the Bundle's own build but MUST NOT reject an import. Tolerance has one limit and one record. The limit: a source whose declared spec_version has a MAJOR the tool does not implement MUST be refused with AGSC-E004, before any file is written, unless the adapter offers its own --allow-newer flag and the caller passes it (AGSC-01-26a, AGSC-09-09) — reading another MAJOR is a guess, so the choice is the operator's and never the tool's, and the default is to stop. A source of the tool's MAJOR and a newer MINOR MUST be imported, with the warning AGSC-E506 naming the newer version, and every construct the tool does not know is handled as AGSC-00-21 lists. The record: every item an import writes MUST carry prov.source_version (the source's content version) and prov.source_hash (the source's bundle hash), each omitted when the source publishes neither, so that an imported item names the exact state it was taken from (AGSC-08-01, AGSC-04-25). An import MUST NOT write executable content (AGSC-07-15) into the Bundle: a foreign record's scripts, executables, symlinks and tool pre-approvals (allowed-tools) MUST be dropped, and each dropped file or key MUST be reported as the warning AGSC-E407. A foreign record whose licence the importer cannot establish as permitting publication MUST be written with status: draft, so that it is never published (AGSC-06-30), and reported as the warning AGSC-E506. A peer's record that a local item must link to — a task on another node's board that a local task is blocked-by, for example — is imported as a read-only draft copy that names the peer IRI in an x-<vendor>-<key> member (AGSC-02-05a), and the local Link names the copy: a Link target is a local slug at 1.x (AGSC-03-02), and an IRI Link target is a 1.1 item (AGSC-00-20). An item mapped to concept that declares no kind is written with kind: explainer, the adoption default of AGSC-02-90, and the mapping is part of the AGSC-E506 warning (Rationale: a concept must carry kind, AGSC-02-12). [design]
  • AGSC-01-23 Import MUST be deterministic and idempotent: re-running it over unchanged input MUST produce byte-identical output and MUST NOT create duplicate items. Colliding slugs MUST be suffixed -2, -3, … in discovery order. A collision with an item the target Bundle already holds is not a slug collision and MUST NOT be suffixed — suffixing it would break this rule's own idempotence, because the second run would see both <slug> and <slug>-2 taken and write <slug>-3. An import MUST NOT replace an existing item unless the operator asked for it: where any planned path exists with different content, the import MUST write nothing at all, MUST report AGSC-E206 for every such path, and MUST exit non-zero; --dry-run reports the same. An adapter MAY offer an explicit flag of its own (AGSC-01-26a) that permits replacement, in which case every replaced path MUST be reported; a write is never permitted outside the Bundle root or through a link (AGSC-01-16, AGSC-01-35). A planned path whose bytes are already exactly what the import would write is unchanged, and is not a collision. (The suffix clause is about the incoming set — a foreign corpus with two files that slugify alike.) [PRD-021]
  • AGSC-01-24 (reserved: stated by the first conjunct of AGSC-08-17, with the same code; the id is never reused, AGSC-00-16.)

1.6 Export

  • AGSC-01-26 export --markdown and export --okf MUST emit the lint-normalized Bundle itself — one .md file per published item (AGSC-06-30), so that a byte-preserving export carries exactly what the node publishes, frontmatter first, body bytes unchanged (every other surface of this format applies AGSC-06-30's projection too, so no surface lets a draft item leave a node) — and MUST be lossless: every authored frontmatter key, including unknown keys preserved under AGSC-02-05, MUST appear in the output. The result MUST open as a plain folder of Markdown in any editor or vault tool without a plugin. Both flags write the export's Bundle root document content/index.md (AGSC-01-04), which carries bundle_version — the content version of AGSC-04-25 — beside spec_version: it is the one derived key of an otherwise byte-preserving export, and it is where a consumer of a saved folder reads which version of the node they saved, since AGSC-01-29 forbids prefixing the item files themselves. --okf additionally writes okf_version into that document and the OKF-reserved content/log.md (OKF v0.2 §9 permits log.md at any level of the hierarchy, and it is AGSC-01-04 that makes content/ the OKF bundle root of an export), whose content is one line - <slug>: <modified, else date, else the empty string> per item in slug order (an empty file when the Bundle has no item). That is deliberately not OKF v0.2 §9's date-grouped prose log: a steer- and build-stable export cannot depend on authored history, this form is a pure function of the item set, and a consumer that needs the OKF form derives it from the items' modified values. Because these outputs are byte-preserving, the Content Use Terms travel beside them, not inside them: index.md carries license and the export root carries a LICENSE-CONTENT file (AGSC-01-29). [PRD-026]
  • AGSC-01-26a Beyond the five flags of AGSC-01-26…01-28 an implementation MAY ship memory adapters selected by export --to <adapter> / import --from <adapter> (the Basic Memory and GABBE-memory both-ways adapters among them; Obsidian needs none, since AGSC-01-26's vault-openability clause already covers it). An adapter MUST be a single module discovered by directory convention (in the reference implementation, src/interchange/adapters/; informative) and never by a configuration key; MUST be lossless in both directions for every key it claims, with AGSC-01-23's idempotence applying to a round trip; MUST carry AGSC-01-29's header and terms on every prose-carrying output; MUST NOT emit an executable, a symlink or an allowed-tools declaration (AGSC-07-15); and MUST be listed with its claimed key set in the distribution's implementer documentation. A name that no shipped adapter and no installed plugin answers is AGSC-E203 — a value outside a closed operator list — and exit 1, for export --to and import --from alike. Adapters are never required for conformance at any Level (AGSC-10-04). (Amended 2026-10-07 for 1.0.0: the opening cross-reference named two of the three rules that define the five flags.) [PRD-026]
  • AGSC-01-27 export --jsonld output MUST be byte-identical to the graph.jsonld of the same build (AGSC-05-06, AGSC-04-04); export --jsonl MUST emit one JCS-canonical JSON object per LF-terminated line, one line per item, items in slug order, each line being exactly the per-item JSON-LD node of pages/<slug>.jsonld. Neither MAY invent a member that the graph does not carry; the licence travels as the JSON-LD schema:license/schema:usageInfo members the graph already carries, never as a text header. [PRD-026, PRD-022]

  • AGSC-01-28 export --steer [--target <name>[,<name>…]] — one comma-separated list of registry names, never a repeated flag (to agree with AGSC-09-09, which types every verb flag as taking one value) — MUST emit steer bundles derived only from NOW state and from concept, procedure, gate and lesson items — never from an Episode, a Proposal or the git log — so that the same Bundle always yields the same bytes (AGSC-04-01). <name> is drawn from this closed registry, and each target writes exactly the one path named here and nothing outside it:

    targetpath
    agentsAGENTS.md
    claudeCLAUDE.md
    cursor.cursor/rules/agsc.mdc
    copilot.github/copilot-instructions.md
    geminiGEMINI.md
    codexAGENTS.override.md
    gabbeGABBE/agents/AGENTS.md
    kiro.kiro/steering/agsc.md
    windsurf.windsurf/rules/agsc.md
    cline.clinerules/agsc.md
    aiderCONVENTIONS.md

    The default is agents,claude. (OpenAI's documentation for Codex, https://learn.chatgpt.com/docs/agent-configuration/agents-md, read 2026-09-23, says that Codex looks for AGENTS.override.md first and AGENTS.md second at each level, and that any other name has to be named by the reader's own project_doc_fallback_filenames setting; it also states that Codex "concatenates files from the root down, joining them with blank lines" and "stops adding files once the combined size reaches the limit defined by project_doc_max_bytes (32 KiB by default)". The codex row is AGENTS.override.md and not AGENTS.md, because the agents target already writes AGENTS.md and no target may write another's path.) Every target derives from the same source set, is byte-stable (AGSC-04-01) and carries AGSC-01-29's header and terms; no target writes outside its named path and no twelfth target exists at 1.x — a new one is a MINOR bump with a registry row and a vector, exactly as a new Link key is (SPEC §8). What is normative about a steer bundle is the eleven target paths, the closed source set above and AGSC-01-29's obligations; the layout of the emitted text is implementation-defined at 1.0 and no rule pins a byte of it, so a conformance claim MUST NOT assert cross-implementation byte-identity for a steer bundle (AGSC-04-24) and the export vector area stays empty of one (Rationale: pinning a layout at 1.0 would freeze a document meant to be read by tools that change every quarter). An item whose most recent content-branch commit carries a Channel-Auto: trailer MUST be excluded from every target's output until a human verified[] entry is added to it; that exclusion is what lets AGSC-08-26(b) admit concept, episode and lesson into the auto lane at all. [PRD-029]

  • AGSC-01-29 Every agent-facing digest — export --steer (AGSC-01-28), AGENTS.md and every SKILL.md of a Harness (AGSC-07-12), and any other export that re-narrates item prose rather than copying it — MUST carry the fixed provenance header of AGSC-06-15, MUST fence quoted item prose as ```text agsc-content, and MUST embed the Content Use Terms identifier (or, on a node that has not adopted them, the prose licence in its place, AGSC-06-18); a build that omits them MUST fail. The byte-preserving exports of AGSC-01-26/27 MUST NOT be fenced or prefixed — that would break their losslessness and their byte-identity with graph.jsonld — and carry the terms as AGSC-01-26/27 state (a LICENSE-CONTENT file plus index.md license; the JSON-LD licence members). Steer bundles are governed exactly like llms.txt (AGSC-06-15) and the Harness files (AGSC-07-12). [NFR-07, PRD-019, ADR-001]

1.7 Channel ingest

  • AGSC-01-30 A Channel adapter (channels/<name>/) MUST expose pull(since) → messages[] and render(message) → { path, frontmatter, body } producing a conforming item (AGSC-02) under content/<type-plural>/; it MUST NOT write to the content branch directly — ingestion always yields a Proposal (AGSC-08-01..). The CI ingest job pushes the Proposal branch and opens the pull request with the ingest credential CHANNEL_TOKEN_<name>, a fine-grained token scoped to the content repository with contents: write and pull-requests: write, never GITHUB_TOKEN and never in a fork context. Forge fine-grained tokens are not ref-scoped — their permissions are repository-wide — so the branch ruleset, never the token, is what prevents a direct push to the content branch, and the ingest identity MUST NOT appear as a bypass actor on that ruleset (AGSC-08-26(f) gives the separate merge credential that MAY). propose itself still performs no network write (AGSC-08-04). The job MUST reject a message whose sender is absent from a non-empty channels[].allow[], and MUST stop for the current hour once channels[].rate{per_hour} messages have been ingested (AGSC-01-18), recording the skipped messages by sources[].id for the next run. render MUST redact e-mail addresses and telephone numbers from the body (AGSC-08-16) and record the sender only in sources[0]. A channel MUST NOT have more than five open Proposals at once; the ingest job MUST stop opening pull requests at that bound and record the skipped messages by sources[].id for the next run (idempotence, AGSC-01-33). [PRD-043, PRD-056]
  • AGSC-01-31 Each channel declares publish: auto | hitl (default hitl) in agsc.config.json (channels[]). In hitl the Proposal waits for the author's verified[]; in auto it MAY be merged only under AGSC-08-26, whose guard is verified against configuration and forge identity, never against self-declared frontmatter: the pull-request author MUST equal channels[].author, prov.operator MUST equal channels[].owner, and every ingested item MUST carry prov.agent (the adapter id) with prov.origin: imported — so the agent-safety lints of AGSC-08-13 run at error severity (AGSC-08-13) instead of warning. [PRD-056, AGSC-08-05, AGSC-08-26]
  • AGSC-01-32 Optional AI correction in auto mode is limited to formatting/frontmatter/typo repair; it MUST NOT add claims, links or Sources, MUST run under the configured spend cap (NFR-11) and MUST record its spend by adding to the same Proposal one episode item carrying usage{model, tokens_in, tokens_out, cost_usd, estimate} (AGSC-02-14) and prov.agent = the adapter id — the same mechanism AGSC-09-14a requires of an LLM responder, and the only one AGSC-08-25's monthly rollup can see, since a Proposal has no file (AGSC-00-06) and the ledger has no proposal kind at 1.0 (AGSC-08-21). A correction whose spend cannot be recorded MUST NOT run. Without a key the adapter still works (lint-only). [PRD-056]
  • AGSC-01-33 Ingested messages MUST be de-duplicated by a stable source_id kept in sources[].id (a member of the source object, AGSC-02-10); re-ingesting is a no-op (idempotent), and the original channel/message reference is the item's first Source. A channel message that has no web URL uses the resource form urn:agsc:channel:<name>:<source_id>, which the schema admits alongside https?://. [PRD-056]
  • AGSC-01-34 Attachments live under content/attachments/<slug>/ and nowhere else; a file there that no item's attachments[] names is an orphan warning (AGSC-E414); an attachments[] entry whose file is absent, or whose bytes do not match the SHA-256 recorded for it, is AGSC-E413 at build; the byte comparison — the served file against the SHA-256 in the served pages/<slug>.jsonld (AGSC-05-29) — is a verify check over a published node and reports AGSC-E413 there. agsc.config.json gains the OPTIONAL attachments{max_bytes} (default 1048576, maximum 10485760, x- admitted, AGSC-11-01); a larger file is AGSC-E904. [AGSC-01-16]
  • AGSC-01-35 Every relative path a Bundle carries as the value of a key — attachments[].file, diagram.file, build.out — MUST be a sequence of /-separated segments in which no segment is .. or ., which does not begin with /, does not contain a \ or a U+0000, and which resolves inside the Bundle root; a violation is AGSC-E902. An inline Markdown link or image target in a body is held to the same rule except that it MAY contain .. segments, because an item under content/<type-plural>/ cannot otherwise reach content/assets/ at all (AGSC-02-95, AGSC-03-11): it MUST not begin with /, MUST NOT contain a \ or a U+0000, and the path it resolves to — relative to the file that carries it — MUST lie inside the Bundle root. For a body reference the escape test wins over the segment test. A body target that escapes the Bundle root is AGSC-E902; a body target inside the Bundle root that resolves to no item, asset or anchor is AGSC-E310 (AGSC-03-11), never AGSC-E902. The schemas check only the cheap syntactic part (no leading /, no \, no NUL anywhere), because the segment rule cannot be expressed as a portable regular expression: a lookahead is valid in ECMAScript but uncompilable in RE2, Go and Rust, and the vectors promise ports in any language. This rule is the normative form of that segment test. [AGSC-01-16]

1.8 Agent lane configuration

  • AGSC-01-36 agents[] is an OPTIONAL array of agent-lane declarations, each {name, kind, author, operator, model, tasks[], types[], channel, schedule, budget_usd_month, max_new_items, max_claims, enabled}: name a slug unique within the array; kind ∈ llm|process; author the forge identity under which the lane's Proposals are opened (the same grammar as channels[].author); operator the accountable human, human:<id> (AGSC-02-07); model a non-empty string, REQUIRED when kind is llm, absent otherwise; tasks[] a non-empty subset of create, edit, update, review, summarize, translate, refresh, plan, claim, work; types[] a non-empty subset of concept, episode, lesson (default all three — a procedure, gate, cluster, configuration, workflow or schema is never in an agent lane, AGSC-08-26(b)); channel the name of a channels[] entry whose author equals the agent's author and whose publish choice and guards therefore govern the lane's Proposals (AGSC-01-31, AGSC-08-26); schedule an OPTIONAL string the host's scheduler interprets and this specification does not; budget_usd_month an integer ≥ 0, REQUIRED when kind is llm, and the sum of budget_usd_month over the entries with enabled: true MUST NOT exceed the node's budget.usd_month (AGSC-01-38) — a configuration that does is invalid with AGSC-E212; max_new_items an integer ≥ 1, default 20, the greatest number of items one Proposal of the lane may create (the bound on a runaway planner, AGSC-08-28(c)); max_claims an integer ≥ 1, default 1, the greatest number of tasks the lane may hold in TASK_STATE_WORKING at once (the work-in-progress limit of AGSC-10-17); enabled a boolean, default false. Each object admits x-<vendor>-<key> keys; any other unknown key is AGSC-E004; an enum violation is AGSC-E203. The object declares the lane; its behaviour is AGSC-08-28…30. [PRD-063]
  • AGSC-01-37 The environment file. Every value of agsc.config.json that is a secret or host-specific is configurable from the environment, and the environment is configurable from a file: a conforming tool MUST read, before anything else, an OPTIONAL .env file in the Bundle root — UTF-8, one NAME=value per line, # comments, no quoting or interpolation, a later line winning over an earlier one — and MUST take from it only names matching ^AGSC_[A-Z0-9_]+$, ignoring every other line; AGSC_FEATURE_LLM_REVIEW is read from the process environment only and never from .env, because no Bundle file may enable the review lane (AGSC-08-27) (amended 2026-10-02 for 1.0.0: the exception was not stated); a name already present in the process environment keeps its process value (the precedence of AGSC-09-09 becomes flags > process environment > .env > project configuration > user configuration). Every scalar key of AGSC-01-18 is addressable as AGSC_ followed by its path in upper case with _ between segments (AGSC_BUDGET_USD_MONTH, AGSC_BUILD_OUT, AGSC_SITE_BASE), and the named entries of agents[] and channels[] as AGSC_AGENT_<NAME>_<KEY> and AGSC_CHANNEL_<NAME>_<KEY> with the slug in upper case and - as _ (AGSC_AGENT_EDITOR_ENABLED=true, AGSC_AGENT_EDITOR_BUDGET_USD_MONTH=3); a value is parsed by the schema type of the key it overrides (true/false, an integer, else a string) and a value that fails the schema is AGSC-E201…E204 as if written in the file. Model credentials are environment-only — AGSC_MODEL_API_KEY and, for an OpenAI-compatible endpoint, AGSC_MODEL_BASE_URL — and MUST NOT be configuration keys, so that no Bundle file ever holds a secret (AGSC-08-15). init MUST write .env into .gitignore and MUST write .env.example listing every recognised name with an empty value; a tracked .env — one present in the content branch — is AGSC-E403 (the secrets lint of AGSC-08-15) whatever it holds. The configuration input of the build function (AGSC-04-01) is the configuration as resolved after these overrides, and ci MUST print the names — never the values — of the overrides in effect, so that a reproduction can be set up from the log. [PRD-065, AGSC-09-09, NFR-11]
  • AGSC-01-38 The node-wide spend cap. budget{usd_month} is an integer ≥ 0, default 10, the most a node may spend on model calls of every kind in one calendar month — agent lanes (AGSC-08-28), the review lane (AGSC-08-27), automatic correction (AGSC-01-32), a narrating responder (AGSC-09-14a) and anything else that records usage — summed over every Episode of the month (AGSC-08-25); the sum of the enabled agents' budget_usd_month MUST NOT exceed it (AGSC-01-36, AGSC-E212); when it is reached every model-calling path MUST stop for the month with the warning AGSC-E510, and a tool that cannot compute the month's spend MUST NOT call a model (the rule of AGSC-01-32). The reference node keeps the default (NFR-11); AGSC_BUDGET_USD_MONTH overrides it per AGSC-01-37. [PRD-065, NFR-11]
