Query

SummaryAsk the published graph of this node a question in SPARQL, in this page: no server takes part, and nothing is sent or stored.

Write a query in SPARQL 1.1 and run it against the published graph of this node, /graph.nq. The query runs in this page, in your browser: no server takes part, nothing you write is sent anywhere and nothing is stored, not even the last query.

This page needs JavaScript to run a query. Without it, the examples and the vocabulary below still read, and every query gives the same answer in a SPARQL 1.1 store loaded with /graph.nq that reads the union of its graphs as the default graph (every statement of /graph.nq is in this node's named graph).

Ask the graph

The page answers SELECT, ASK, CONSTRUCT and DESCRIBE. It refuses an update (INSERT, DELETE, LOAD and the others) and a SERVICE clause before anything runs, because it changes nothing and asks no other server. A query runs over every statement of the node, the union of the graphs of /graph.nq, unless it names its own dataset with FROM.

Ctrl+Enter (Cmd+Enter on a Mac) runs the query; Tab leaves the editor. Stop ends a long query.

Link to this query

The link holds the query after the # of its address, a part no browser sends to a server. Opening it puts the query into the editor; it runs only when you select Run.

Result

Download the result as CSV Download the result as JSON A yes-or-no answer has no CSV form; the JSON file holds it.

The files follow the W3C Recommendations “SPARQL 1.1 Query Results CSV and TSV Formats” and “SPARQL 1.1 Query Results JSON Format”. A CONSTRUCT or DESCRIBE result is given as its triples, one row each, in the columns subject, predicate and object. The CSV file holds each value as the query gave it: a spreadsheet may run a value that starts with =, +, - or @ as a formula, so import the file with its columns as text.

Examples: the ten questions of the graph

The specification names ten questions that the graph of every node must answer. Each comes with the query that defines it, in which ?x stands for the item you ask about, <S...> for a selection of items and "T" for an instant. Here they are filled in from this node, and the sentence under each query says with what: put your own in their place to ask about something else.

  1. 1. If I choose X, what else must I take?

    PREFIX asc: <https://w3id.org/agentic-system-core/ns#>
PREFIX dcterms: <http://purl.org/dc/terms/>

PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT DISTINCT ?item WHERE { <https://agenticsystemcore.com/concepts/bundle/> dcterms:requires+ ?item } ORDER BY ?item

Relations

The 14 relations an item may name, in the order of the specification.
KeyPropertyMeaning
relatedskos:relatedThe two items are connected in meaning, and neither depends on the other.
broaderskos:broaderThe target is a wider subject that this item falls under.
narrowerskos:narrowerThe target is a more specific subject that falls under this item.
usesasc:usesThis item draws on the target and can still be used when the target is absent.
requiresdcterms:requiresThis item cannot be used without the target, so choosing this item also takes the target.
excludesasc:excludesThis item and the target cannot be used together.
derived-fromprov:wasDerivedFromThis item was produced from the target, which is its origin.
contradictsasc:contradictsThis item and the target make claims that cannot both be true.
supersedesdcterms:replacesThis item replaces the target, which stays published but is no longer the one to use.
implementsasc:implementsThis item puts the target into practice, as code or a procedure puts a specification into practice.
verifiesasc:verifiesThis item checks that the target holds.
coversasc:coversThis item covers the target, as a test or a document covers a requirement.
blocked-byasc:blockedByThis item cannot go ahead until the target is resolved.
decided-byasc:decidedByThe target is the decision record that settled this item.
