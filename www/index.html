AgenticSystemCore

SummaryAn open format and a set of rules that turn a folder of Markdown text files into a wiki, a graph, an agent memory, a skills library, starting architectures and a shared live board for agents and people, published here as a node of itself.

AgenticSystemCore turns a folder of plain text notes (Markdown text files) into a website, a knowledge graph and a set of tools for AI assistants, all at once. Every link says what kind of link it is, every published file carries a fingerprint (a digest) that anyone can check, and every change is approved by a person or by a rule that person wrote down. People, search engines and AI agents read the same checked knowledge, and no server, database or language model is needed to build, check or publish it.

  • Start here: one reading path for each kind of reader.
  • Try it in five minutes: install the package and run each mode from an empty folder.
  • Use it on your own files: seven short guides, one per mode and one for publishing, every command with the lines it prints.
  • The six ways to use it: one folder of files, six modes.
  • Read the introduction: what it is, what it is for and how it works, in plain words; how it works shows how nodes find and read each other.
  • Compose a starting harness: tick the concepts you need and get seven starting files, computed in your browser.
  • Read the specification: the rules, the schemas and the test cases.

AgenticSystemCore is an open specification, with a free reference implementation, for knowledge that people and software agents can both read, check and build on: a shared memory that gives the same result on every build, keeps a record of every change, and follows published rules rather than habit.

What is different, and how it compares

Other systems have some of these parts. To the author's knowledge none has them together: knowledge that a machine finds through registered web addresses, a digest on every file the node publishes, a graph whose links have published meanings, output pinned by test cases, a person on every merge (directly, or through a standing rule that person recorded), and a starting harness built from the same files, with no server. These are claims about the specification and its test cases, not about speed. What it shares with others' work, and how it differs:

  • LLM wikis (Andrej Karpathy's idea, the Decoding AI workshop): the same aim — pages of Markdown text, sources kept apart, knowledge prepared in advance. There a model writes pages and a link's kind lives in prose; here links are typed, deterministic checks find orphans and stale links, and a model proposes but never merges.
  • The Ontology Pipeline (Jessica Talisman): six stages from controlled vocabulary to knowledge graph. Version 1.1 has a part for each stage; which part does what. No compatibility is claimed.
  • Google's Open Knowledge Format: also Markdown with a header, but link kinds stay in prose; no discovery layer or digests.
  • llms.txt: a node publishes one, with a fixed grammar, beside a discovery document giving each artefact's digest.
  • Agent discovery (IETF survey) finds who can act; this finds what is known. RFC 9727 (api-catalog) is the design precedent.
  • Wikibase and Wikidata: a typed graph in a served wiki with live writes; here, static files under version control.

The dated comparison is in the related work, the details in the paper; the source is on GitHub.

Six ways to use it

  • Auto-wikiPlain text notes (Markdown) in, a checked and linked website out; no model needed.
  • Distributed agentic memoryAgents read, cite and propose; people ratify; nodes peer with each other.
  • Live specificationsA project's decisions, specs, tasks and gates as one governed memory.
  • Evolving skillsEach cluster becomes a skill pack of its published items; improved skills come back as Procedures.
  • Runnable knowledgeSelect Concepts, get a starting Harness: seven kinds of file an architect or a runtime starts from.
  • The live boardAgents and people pull, claim and finish a project's tasks on one shared board until it is done.

A distributed brain, with no server

Each node is a folder of files published as a static site. Nodes find and read each other through registered web mechanisms, every file they point at carries its digest, and they share one vocabulary. A node names its peers; a reader walks from one to the next. No node calls another, and no server sits in between. This node's peer is a second node, AgenticSystemCore Graph at patterns.agenticsystemcore.com, run by the same reference engine: short cards on well-known agent-system designs, each written from the public sources it cites.

Get started

Install the command line (Node.js 22.13 or later, git), then, in a folder of notes written as Markdown text files:

npm install --global agentic-system-core   # puts agsc on the PATH
agsc init     # each note gets a type, a title and its provenance
mkdir -p .well-known && printf 'Contact: mailto:you@example.org\n' > .well-known/security.txt
git init -q && git add -A && git commit -q -m 'my notes'   # the build takes its instant from this commit
agsc ci       # lint, build twice, compare the bytes, verify
agsc build    # the site, the graph and the agent files in www/
agsc mcp      # give an assistant ten tools over the same folder

Without the security contact, agsc ci stops with AGSC-E901; without a commit (or SOURCE_DATE_EPOCH), with AGSC-E204. The Mode 0 guide walks through it with the lines each command prints, and the guides do the same for every mode. The demos run each mode from an empty folder; the assistant setup guide and the start page for each kind of reader go further.
