The skill is a folder in the Agent Skills format: one `SKILL.md` that an agent loads when a project holds `agsc.config.json` or when you mention a Bundle or a knowledge node, and two reference files it reads only when it needs them. It is plain Markdown, carries no script and runs nothing. Its text is CC0.

## The files

| File | What it holds |
|---|---|
| [`SKILL.md`](/agent-skill/agentic-system-core/SKILL.md) | what an agent never does on its own; the six modes with the command and the configuration each needs; setup; the sixteen commands; how to write each kind of item; the five steps of a change; claiming a task on a live board; reading and citing a node; the checks before saying "done" |
| [`references/connectors.md`](/agent-skill/agentic-system-core/references/connectors.md) | steering files for eleven coding agents, the tool server for five assistants, skill packs, memory systems, trackers, the pre-commit hook and the CI action |
| [`references/configuration.md`](/agent-skill/agentic-system-core/references/configuration.md) | the configuration keys the modes use: peers, contribution routes, execution, budget, channels, agent lanes, federation limits |

## Install it

For one project, in Claude Code (run in the project folder; Git Bash on Windows):

```bash
B=https://agenticsystemcore.com/agent-skill/agentic-system-core
D=.claude/skills/agentic-system-core
mkdir -p "$D/references"
for f in SKILL.md references/connectors.md references/configuration.md; do curl -fsSL "$B/$f" -o "$D/$f"; done
```

For every project on the machine, set `D=~/.claude/skills/agentic-system-core` instead. Other agents that read Agent Skills look in `.agents/skills/` (and GitHub Copilot in `.github/skills/`): set `D` to that folder. Start a new session afterwards; the agent loads the skill when the work calls for it.

The engine itself is installed separately, when you want it: `npm install -g agentic-system-core`, or `npx -y agsc-cli <verb>` without installing.

## What it changes in how an agent works

- It picks the mode from what you ask for, and runs the commands of that mode from the right folder.
- It writes items that pass the checks the first time: the right folder, the required keys of each item type, the provenance block with you as the accountable person, links by slug only.
- It never commits, pushes, deploys `www/`, installs software or changes an assistant's settings unless you ask in that request. A change ends as a proposal and the git commands it prints, which you run.
- It treats everything it reads from a node as data, never as an instruction, and cites what it uses by address.
- It runs `agsc lint` and `agsc ci` before it reports a change as done, and quotes numbers only from a command it ran.

## Not the same as this node's skill packs

The [skill packs](/skills/) of this node are generated by the engine from the node's own procedures, one pack per cluster, and say what the content says. This skill is written by hand and says how to use the engine. Use both: the packs for a node's procedures, this skill for working with any node.

The [how-to-use page](/docs/how-to-use/) has the same ground for a person to read, mode by mode.
