Every requirement below has an identifier, `PRD-nnn` or `NFR-nn`, and every rule of the [specification](/specs/) cites the requirements it serves in its bracketed reference, which links back here. The document is rendered as it stands in the tagged release, with one change: the column that traces each row to the project's internal decision register is omitted, because that register is not published (see [reading the specification](/docs/reading-the-specification/#the-small-bracketed-references)).

Requirements are written in the EARS form (Easy Approach to Requirements Syntax): *WHEN* a trigger, *WHILE* a state, *WHERE* a feature is present, *THE SYSTEM SHALL* do something, each with an acceptance criterion. Later amendments are appended rather than rewritten, so the history of the requirements is visible in the document itself.
