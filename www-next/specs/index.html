Specification

SummaryThe twelve sections of the specification, the discovery profile and what a conformance claim is.

Status of this document

Specification 1.0.0-rc.4, a release candidate tagged on 2026-09-18. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no body has endorsed it. Released sections are immutable; a correction ships as a new version.

New to the notation? Read how to read the specification first: it explains the rule identifiers, the key words and the small bracketed references. Each section below opens with a summary, a plain-language box and a diagram before the normative text.

Sections

  1. Overview, terms, conformance model AGSC-00
    What the specification covers, the words it uses, what it means to conform, and how versions change.
  2. Bundle: files, folders, encoding, configuration AGSC-01
    The directory that holds a node's knowledge: its layout, slugs, encoding, the one configuration file, the optional agent-lane declarations, and how foreign content comes in and goes out.
  3. Item: frontmatter contract per type AGSC-02
    One Markdown file with a small YAML header: the keys every item has, what each of the six types adds, the body rules, and the rc.3 additions for ports, architectures, attachments and tasks.
  4. Links: the fourteen keys, inverses, combiner semantics AGSC-03
    The fourteen typed links between items, the inverses the build computes, the integrity checks, and which links the combiner reads.
  5. Canonicalization and determinism AGSC-04
    Why two builds anywhere give the same bytes: canonical JSON, NFC text, one time format, fixed sort orders and SHA-256.
  6. Graph: IRIs, RDF views, SKOS, PROV AGSC-05
    How items become a graph with web addresses, the three RDF views, the ontology and its alignment to SKOS, PROV-O and Dublin Core, and the byte-level pins.
  7. Published surfaces: routes, discovery files, llms.txt AGSC-06
    Everything a node publishes: the fixed route set, the discovery document, llms.txt, the chunk export, the JSON-LD context, headers and budgets.
  8. Composition: the closure algebra and the Harness AGSC-07
    How a selection of items becomes a verdict and a Harness: the five steps in their fixed order, the seven Harness files, skill packs, ports and saved architectures.
  9. Governance: provenance, gates, lints, ledger AGSC-08
    Who made what and who approved it: provenance, sign-off trailers, gates, the four agent-safety lints, the optional agent lane and the ledger derived from git history.
  10. Conformance: classes, vectors, error codes, CLI contract AGSC-09
    How a claim is made and checked: classes and Levels, the vector format, the command-line contract, the error-code registry and the independent validators.
  11. Implementation profiles (conformance Levels 0–3) AGSC-10
    The four Levels of conformance, how an existing wiki or CMS becomes a node, how two nodes check each other, project mode with tasks and boards, and the live board.
  12. The node boundary: cross-origin access, federation, contribution, surfaces, visibility, retirement AGSC-11
    Where a node meets the outside: cross-origin access, the nine parts of federation, the plugin contract for every agent surface, visibility, retirement and tombstones.

Discovery profile

The knowledge link set profile documents the discovery document that every node serves at /.well-known/knowledge-linkset.

Conformance

A claim names exactly one Level, the spec_version and the vector set it passed (AGSC-00-12, AGSC-10-01). This site claims Level 0 against 1.0.0-rc.4.
