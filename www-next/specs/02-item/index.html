AGSC-02 — Item: frontmatter contract per type

SummaryOne Markdown file with a small YAML header: the keys every item has, what each of the six types adds, the body rules, and the rc.3 additions for ports, architectures, attachments and tasks.

Status of this document

Specification 1.0.0-rc.6, a draft release candidate, not yet tagged. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

In plain language

One file. An item is a Markdown file that starts with a YAML block between --- lines. The YAML is a small, safe subset: no anchors, no aliases, no custom tags.

Common keys. type, title, description, tags, clusters, status, date, modified, sources, verified, prov (who or what made it), and the typed link keys. Lengths are counted in Unicode code points.

Six types. Concept (with a kind: pattern, taxonomy, explainer, principle, decision, spec, task, term, or a saved architecture), Episode (something that happened), Procedure (steps a reader can run; exports as a skill), Lesson (distilled from episodes, with a severity), Cluster (a navigational grouping), Gate (checks a change must pass).

Status. draft, stable, deprecated, and since rc.3 retired — retired items keep their page and address but leave every export.

Body. CommonMark. Fenced code stays code. Headings become anchors and, for the chunk export, cut points.

Since rc.3. Items may declare ports (produces/consumes type names) that the combiner wires; a concept of kind architecture stores a selection the combiner can re-run; items may carry attachments (on a pattern, images must be SVG under a safety allow-list); a task may carry an Agent2Agent task_state.

This box explains; the rules below decide. New to the notation? See how to read the specification.

2.1 Frontmatter syntax

  • AGSC-02-01 A file MUST begin on line 1 with ---, contain YAML, and close with a line ---. A file with no such opening line is AGSC-E101; an opening line whose block is never closed by a later --- is AGSC-E102 (both codes were registered against this rule and raised by no sentence until rc.5). No ... terminator and no second document (AGSC-E107). [design]
  • AGSC-02-02 The YAML subset is: block mappings, block sequences, flow sequences of scalars, single/double-quoted and plain scalars, | and > block scalars. Anchors, aliases, tags, merge keys, complex keys, flow mappings and duplicate keys MUST be rejected, each under its own code: an anchor or an alias is AGSC-E103, a tag or a merge key is AGSC-E104, a flow mapping or a complex key is AGSC-E105, and a duplicate key is AGSC-E106 (the four were written as the range AGSC-E103…AGSC-E106 until rc.6, 2026-09-22: two of the codes were then named by no rule sentence anywhere, so a port reading the rules alone could not learn which construct takes which). [design]
  • AGSC-02-03 A reader MUST parse with the YAML failsafe schema — every scalar is a string — and MUST apply types from schema/item.schema.json. yes, no, on, off, ~, 1e3, 0x1F and bare dates are strings. [design]
  • AGSC-02-04 Booleans MUST be written true/false; numbers MUST be plain decimal; dates and instants MUST be quoted strings. [design]
  • AGSC-02-05 Key names MUST match ^[a-z][a-z0-9_-]*$. Unknown keys MUST be preserved and reported as warnings (AGSC-E207), never as errors. A key name that does not match this pattern is AGSC-E204 (a pattern violation), distinct from an unknown but well-formed key, which is the AGSC-E207 warning; the schema does not enforce the pattern, because propertyNames would turn the warning into an error. [OKF]
  • AGSC-02-05a A key matching ^x-[a-z0-9]+(-[a-z0-9]+)+$ is a reserved vendor extension (the x- namespace of docs/SPEC.md §8(2)). A conforming tool MUST preserve it verbatim in every lossless export (AGSC-01-26), MUST NOT interpret it, MUST NOT normalise it beyond the key ordering of AGSC-04-19, and MUST NOT report AGSC-E207 for it. Every other unknown key still warns under AGSC-02-05. The same namespace is admitted in agsc.config.json by AGSC-01-18. [design]
  • AGSC-02-06 Dates use YYYY-MM-DD. Instants (stale_after, generated.at, verified[].at, started, ended) MUST be YYYY-MM-DDTHH:MM:SSZ — a datetime with an explicit UTC offset, seconds precision, never a bare date. [OKF 2026-08-21]

Absence of prov is error AGSC-E501. [PRD-042]
  • AGSC-02-08 (retired at rc.3, 2026-09-17: the same proposition in reversed order — merged into AGSC-08-02; the id is reserved under AGSC-00-16 and never reused.)
  • AGSC-02-09 Actor strings MUST be human:<id>, process:<id> or <producer>/<version>. [OKF]

  • AGSC-02-11 An item is stale when stale_after is earlier than the build instant (§04). Staleness MUST be computed by comparison only — no decay function, no activation score, no access log. [PRD-017]

2.3 Type-specific keys

  • AGSC-02-12 concept MUST carry kind ∈ pattern|taxonomy|explainer|principle|decision|spec|task|term|architecture (architecture added at rc.3; folded into this rule in place at rc.5, so that the chapter has one amendment style — status gained retired the same way in AGSC-02-23). Optional facets: evidence (explicit|structural|single-source), maturity (established|emerging|research), mapping (explicit|author), signature (boolean), signature_elements[], owasp_ids[], domains[], modality[], deployment[], implementations[]{label,url}, diagram{file*,alt*,caption}. [PRD-028, design]
  • AGSC-02-13 (amended at rc.5) diagram.file MUST be <slug>.svg, compiled from content/diagrams/<slug>.diagram (AGSC-01-07); diagram.alt is REQUIRED. A writer MUST place the compiled SVG inline in that item's page, as an <svg> element whose accessible name is diagram.alt (AGSC-06-20), and MUST NOT emit it at a route: the value is a file name, not a URL, and AGSC-06-01's route set carries no diagram route. The inlined element MUST satisfy every SVG constraint AGSC-02-98 places on an SVG attachment — no DOCTYPE or entity declaration, no embedded raster, none of the forbidden elements, no on* or style attribute, no processing instruction, and only same-document-fragment references — and its bytes count towards the 100 KB page budget of AGSC-06-21. diagram.caption, where present, is the figure's visible caption and never a substitute for alt. (Before rc.5 no rule said where the compiled picture appears: AGSC-01-07 said "into the build output", AGSC-06-01 emits "exactly this route set" and no route in it carries a compiled diagram, so the two readings — a route or an inline element — were both defensible and neither was testable.) [PRD-013]
  • AGSC-02-14 episode MUST carry started, actor and outcome ∈ success|partial|failure; MAY carry ended, refs[] and usage{model, tokens_in, tokens_out, cost_usd, estimate} (the optional token accounting rolled up by AGSC-08-25). [NFR-11]
  • AGSC-02-15 procedure MAY carry when (one line, ≤1024 characters, saying when the procedure applies; a skills import fills it from a foreign skill's description, AGSC-01-22) and inputs[] (amended 2026-09-24: the key was said to "become the exported SKILL.md description", while the 1.0 packs are one per cluster (AGSC-07-19) and take the cluster's description). [PRD-032]
  • AGSC-02-16 lesson MUST carry severity ∈ info|warn|block and SHOULD carry derived-from naming an Episode. [design]
  • AGSC-02-17 cluster MAY carry broader (at most one cluster slug), order (integer) and family (free text). ordered is not defined at 1.x. [design]
  • AGSC-02-18 gate MUST carry level ∈ L1|L2; checks[], when present, MUST equal the set level implies under AGSC-08-09 (L1 → schema, links; L2 adds provenance, determinism, review) and a disagreement is AGSC-E203; enforce[] ⊆ status-check|hook|codeowner|ruleset, each compiled per AGSC-08-12. [design]
  • AGSC-02-19 Cluster membership MUST be authored on the item (clusters[]), never on the cluster file. [design]

2.4 Body

  • AGSC-02-20 The body MUST be CommonMark 0.31.2 plus GFM tables. Footnotes, raw HTML and unescaped {/< outside code SHOULD NOT be used; an unsupported construct MUST be a lint finding (AGSC-E109), never a silent rendering difference. The unsupported constructs are raw HTML blocks and inline HTML, footnote references and definitions, and every GFM extension other than tables (task-list markers, strikethrough, autolink literals); each occurrence outside a code span or a fenced block is one AGSC-E109 warning (the list stated 2026-09-24: the rule named the code and no construct, so no lint lane could raise it). [design]
  • AGSC-02-21 Body sections are not schema-enforced. A lint MUST warn (AGSC-E406) when kind: pattern lacks ## Intent, ## Context & Forces, ## Structure, ## Consequences & Trade-offs, ## Related Patterns; procedure uses ## When, ## Steps, ## Checks; episode uses ## What happened, ## Outcome, ## Next; lesson uses ## Lesson, ## Evidence, ## Check before. A concept or cluster carrying no description is likewise a warning, AGSC-E408, never an error, because the schema leaves description optional so that an adopted file validates (AGSC-02-92). (amended at rc.5: the clause "taxonomy and explainer keep their four headings" was removed. It named no heading, so no lint could raise it and no port could implement it; the kinds this rule enumerates are the whole of the check, and a heading set for taxonomy and explainer is a 1.1 addition if one is wanted.) [design]
  • AGSC-02-22 Fenced blocks with info string turtle, jsonld, sparql, shacl, mermaid, structurizr, gherkin or diagram are rendering hints only at 1.x; the word export on such a block is RESERVED — extraction into the graph (subjects, vocabulary, blank nodes, merge order, a vector) is specified by a future MINOR, and at 1.x a block carrying export MUST NOT be extracted and is the lint warning AGSC-E415 (it was the only unpinned input to graph.nq and bundle.hash). run and expect are the only executable info strings; they are permitted on procedure items only and have effect only under the opt-in run verb of AGSC-09-94. [design]

2.5 Status transitions and length units

  • AGSC-02-23 An item with no status starts stable (the default of the §2.2 common-key table), and every transition between draft, stable, deprecated and (rc.3) retired (AGSC-11-22) is legal in both directions — including deprecated → stable (un-deprecation) and retired → any state (un-retirement), which a lint MUST report as a warning (AGSC-E409) and MUST NOT reject. supersedes/superseded-by is orthogonal to status and changes neither. [PRD-018]
  • AGSC-02-24 (amended at rc.3; amended at rc.5) Every length bound in this specification — title 3–120, description 40–200, when ≤1024, alt ≥1 (diagram.alt and attachments[].alt alike), port names ≤64 — counts Unicode code points, which is how JSON Schema 2020-12 defines minLength/maxLength (the length of a string instance is the number of its characters as defined by RFC 8259) and how every language counts a decoded string. No bound counts UTF-16 code units, grapheme clusters or bytes. The schemas enforce these bounds with minLength/maxLength and never with a regular-expression quantifier, whose unit depends on whether the engine is in Unicode mode; the port-name grammar of AGSC-02-96 additionally bounds its own length by construction, and the normative bound there is the maxLength: 64 the schema carries beside the pattern, never the pattern's quantifier. The JSON-Schema keyword subset the three item-facing schemas use is fixed here and nowhere else: $schema, $id, $ref, $defs, title, description, type, enum, const, properties, required, additionalProperties, patternProperties, items, oneOf, not, pattern, minLength, maxLength, minItems, maxItems, uniqueItems, default — and no other, so that AGSC-08-01 can reason about what a schema cannot express (a conditional such as "agent is REQUIRED when origin is ai-*" is outside it and is therefore a lint check). schema/config.schema.json MAY use more — if, then, allOf, minimum, maximum and format (annotation only) among them — because the engine validates it and no Bundle reader ever reads it. This is deliberately different from AGSC-04-05's UTF-16 rule, which governs JSON member-name ordering only and comes from RFC 8785; ordering and length are separate questions with separate units. Authored single-line strings (added 2026-09-21 at rc.5): every authored string a writer interpolates into a line-oriented text surface — title, description, each aliases[] and tags[] value, when, family, inputs[], signature_elements[], domains[], modality[], deployment[], implementations[].label, diagram.alt, diagram.caption, attachments[].alt, attachments[].license, sources[].id, sources[].title, sources[].author, prov.agent, prov.model, prov.agreement, usage.model, the Bundle root's title and license (AGSC-01-04) and the configuration's site.title, site.tagline, site.author, bundle.license_prose and bundle.license_schema (AGSC-01-18) — MUST NOT contain a C0 control (U+0000–U+001F), U+007F, U+0085, U+2028 or U+2029. A violation is AGSC-E204, which §9.4's precedence paragraph already assigns to every pattern violation; no new code is minted. The reason is structural: /llms.txt, /llms-full.txt, /now.md, /pages/<slug>.md, the Harness files of AGSC-07-12 including SKILL.md, an additive memory export such as llms-ctx.txt (AGSC-01-26a), robots.txt, /.well-known/security.txt and the deployment-profile files _headers and _redirects are line-oriented dialects in which a line break inside an interpolated value creates a NEW line — a forged ## heading, a forged link entry, a forged response header — and AGSC-01-29 fences the item BODY as data but never fenced the title that the layout of AGSC-06-13a puts on a line of its own. The Bundle root's description is deliberately exempt: AGSC-06-13a block (3) emits it with newlines replaced by one space, so a multi-line value there is conforming. The schemas enforce the bound with a pattern on each member — one negated character class, no lookahead, no back-reference and no quantifier-based bound, so it is the ECMA-262 dialect JSON Schema 2020-12 names and transliterates mechanically to the \x{…} escape form of RE2, Go and Rust (the portability bar of AGSC-01-10 and AGSC-01-35). A writer MUST also neutralise these code points when it interpolates any such string into a line-oriented surface, replacing each one with a single U+0020: validation is not always in the path — an imported Bundle (AGSC-01-22, which AGSC-08-11 requires be accepted), a channel contribution (AGSC-01-30…33) and an agent-lane Proposal (AGSC-08-28) all reach a writer from outside — and the neutralisation is the identity on every conforming string, so no emitted byte of a conforming Bundle moves. Vector fm-0010. [PRD-002, AGSC-04-05]

2.9 Adoption of bare Markdown (added 2026-09-02; rewritten 2026-09-02)

  • AGSC-02-90 init MUST adopt a .md file that carries no frontmatter block by prepending, in the schema order of AGSC-04-19 (top-level properties order, then the matching oneOf branch's properties order — so kind comes last), exactly type: concept, title, aliases (whenever AGSC-02-93 moved or renamed the file — which is every file adopted from outside content/), prov: {origin: human, operator: …} and kind: explainer — nothing else, in that order. The body MUST be byte-identical after adoption. The two derived values are total functions, so adoption never errors:

    • operator — the first source that exists: (1) bundle.operator in agsc.config.json (AGSC-01-25); (2) the local part of git user.email, NFC-normalized, ASCII-lower-cased, every character outside [a-z0-9._-] replaced by -, runs of - collapsed, leading and trailing - trimmed, then leading characters outside [a-z0-9] trimmed, prefixed human:, and rejected in favour of the next source if nothing remains; (3) the literal human:unknown. Sources (2) and (3) MUST emit warning AGSC-E506.
    • title — the text of the first ATX # heading if the file has one, else the filename stem; NFC-normalized and trimmed. Longer than 120 Unicode code points it MUST be clipped to 120 code points (warning AGSC-E506); shorter than 3 it MUST be replaced by the item slug, and if that is still shorter than 3 by note-<slug>.

    README.md, index.md and _index.md MUST NOT be adopted (AGSC-01-05): they are skipped with warning AGSC-E506, not turned into items, however common they are in a bare folder. [PRD-053]

  • AGSC-02-91 Adoption MUST be idempotent: it MUST NOT modify a file that already carries a closed frontmatter block (a --- first line whose block is terminated by a later --- line, AGSC-02-01); a file merely beginning with a thematic break is adopted like any other bare file. The slug is the slugified filename stem — NFC, ASCII-lower-cased, characters outside [a-z0-9] replaced by -, runs collapsed, leading and trailing - trimmed, clipped to 64 and any resulting trailing - trimmed, empty result becoming note — and the file MUST be renamed to <slug>.md under content/concepts/; when the slug differs from the original stem a warning AGSC-E506 MUST be emitted. The original repository-relative path is recorded in aliases[] by AGSC-02-93 — one alias rule, not two. A slug already taken MUST be suffixed -2, -3, … in discovery order, the convention of AGSC-01-23 (the anchor suffixes of AGSC-03-13 govern anchors only), re-checking after each suffix. Headings never determine a slug. [PRD-053, AGSC-01-23]
  • AGSC-02-92 Adopted items pass lint with warnings (no description — AGSC-E408 by AGSC-02-21 — no sources[], plus any AGSC-E506 above) but MUST NOT error: the drop-in path is a first-class conformance scenario (class: full engine). Totality is complete, not partial: AGSC-02-90 and AGSC-02-91 are total functions, description is schema-optional in every branch, and AGSC-02-93 puts the file where AGSC-01-02/03 require it — so no adopted file can produce AGSC-E201, AGSC-E202, AGSC-E204, AGSC-E205 or AGSC-E206, and ci on a folder of bare notes passes offline once the publisher has added the two things only a publisher can state — the security contact of AGSC-06-36 and, where the Content Use Terms are adopted, site.tdm_crawlers (AGSC-06-18); init prints both as its "before you build" steps (amended 2026-09-24: the sentence promised a green ci with no step at all, which AGSC-06-36 and AGSC-06-18 make impossible). [PRD-053]
  • AGSC-02-93 init in adoption mode MUST create content/concepts/ and MOVE each adopted file to content/concepts/<slug>.md, preserving body bytes; the original repository-relative path MUST be recorded in aliases[]; a file already under content/<type-plural>/ MUST NOT be moved. Nested source directories are flattened (notes/agents.md → content/concepts/agents.md); collisions follow AGSC-01-23. Without this move a build discovers nothing under content/** or reports AGSC-E205, and the three-command promise of PRD-053 does not close. [PRD-053, AGSC-01-01/02]
  • AGSC-02-94 In adoption mode init MUST also synthesize, when absent, files that validate against their own schemas, so that ci exits 0 immediately after init (the P0 flow): (a) agsc.config.json with spec_version (current), site.base = "http://localhost/" — the development placeholder AGSC-01-19 admits, warned as AGSC-E506 — site.title = the title of (b), bundle.id = the directory name through the slug rule of AGSC-02-91, bundle.operator = the resolved actor (AGSC-02-90), build.out = "www/"; (b) content/index.md with spec_version (current), okf_version: "0.2", title = the directory name through the title rule of AGSC-02-90 (so the 3–120 bound always holds), description = "Adopted from <n> Markdown files by agsc init on <SOURCE_DATE_EPOCH date>." (≥40 Unicode code points by construction) and base = site.base. Existing files are never overwritten, and every synthesized value is schema-valid by construction — adopt-0004 proves init → ci exits 0 on a bare folder. [PRD-053, AGSC-01-04, AGSC-01-19]
  • AGSC-02-95 After the relocation of AGSC-02-93, init, when it adopts (AGSC-02-90), MUST report every relative Markdown link or image reference in an adopted body that no longer resolves from content/concepts/ as warning AGSC-E507, naming the original path, the new path and the reference; and it MUST copy each referenced local file whose path resolves under the adoption root to content/assets/<original-relative-path>, byte for byte. Body bytes MUST NOT be rewritten — AGSC-02-90's byte-identity guarantee is absolute, so the warning and the copied asset, never a rewritten reference, are what close the gap the flattening opens. A reference that is an absolute URL, a fragment-only target, a mailto: or a path resolving outside the adoption root is left alone and MUST NOT be reported. AGSC-E507 is a warning; the unresolved reference it names is also AGSC-E310 (AGSC-03-11) until the publisher repairs it, so an adopted Bundle with broken references does not pass ci (amended 2026-09-24: the sentence said it still passed, which contradicted AGSC-03-11). (Amended at rc.6, 2026-09-24: the rule named a flag, init --adopt, that no engine needs, since adoption happens whenever init meets plain Markdown.) [PRD-053, AGSC-02-90/02]

rc.3 amendment (2026-09-16, folded into AGSC-02-23 and the kind list on 2026-09-16): status gains the value retired (AGSC-11-22); concept.kind gains architecture — a saved composition, its body listing the selection, re-executable by §07. Both are MINOR additions under AGSC-00-14.

2.10 Ports, architectures, attachments, task state (added at rc.3, 2026-09-16)

  • AGSC-02-96 A concept MAY carry produces[] and consumes[]: arrays of port type names matching ^[a-z][a-z0-9-]{0,63}$, unique within each array, retained in author order in the file and sorted by code point in derived artefacts (AGSC-04-14). Port names are free strings at 1.x, matched by exact equality in §07 Step 5; they are NOT Link keys and the fourteen-key list is unchanged (AGSC-03-01). A lint MUST warn (AGSC-E804) when, over the whole Bundle, a consumes name has no producer or a produces name has no consumer. [PRD-057]
  • AGSC-02-97 A concept with kind: architecture is a saved composition. Its body MUST contain exactly one fenced block with info string yaml agsc-selection whose content is a YAML block sequence of slugs (the selection, in author order) in the same failsafe subset as frontmatter (AGSC-02-02/02-03); a second such block is the schema-class error AGSC-E201; the block MUST be extracted by compose --from <slug> (AGSC-07-24) and MUST NOT be rendered as prose. The item MAY carry verdict_digest — the SHA-256 of the JCS verdict last computed; when present and stale, lint warns AGSC-E805. On a concept whose kind is not architecture, an agsc-selection block and a verdict_digest key are the warning AGSC-E207 and are ignored by every derived artefact (added at rc.5: the schema puts both in the concept branch with nothing tying them to the kind, so an implementer had to guess). Every slug in the block MUST resolve (AGSC-E301 otherwise). The architecture item's own Links follow the ordinary rules. [design]
  • AGSC-02-98 Any item MAY carry attachments[], each {file, media_type, alt, license}: file a path relative to content/attachments/<slug>/ (no parent-directory segment, no leading slash, AGSC-01-35), media_type an RFC 6838 type, alt REQUIRED non-empty text, license OPTIONAL — an SPDX or LicenseRef- identifier defaulting to bundle.license_prose. For a concept of kind: pattern an image attachment MUST be image/svg+xml; any other image/* on a pattern is AGSC-E412 (error). Every SVG attachment MUST be well-formed XML with no DOCTYPE and no entity declaration, MUST NOT embed raster data (data: URIs of any kind), MUST NOT contain a script, foreignObject, use, a, animate, animateColor, animateMotion, animateTransform, set, discard, handler, style, cursor, color-profile, font-face, font-face-format, font-face-name, font-face-src, font-face-uri, missing-glyph, hatch, hatchpath, mesh, meshgradient, meshpatch, meshrow, solidcolor or unknown element (the DOMPurify svgDisallowed set as read on 2026-09-17, plus a, animate*, handler and style, which this specification bans deliberately), MUST NOT carry any attribute whose name begins with on, MUST NOT carry a style attribute or any processing instruction, and every href/xlink:href it carries MUST be a same-document fragment (#id) or a relative path inside the same attachments directory (AGSC-01-35) — never an absolute URL, a javascript: or data: value; a violation is AGSC-E412. A writer MUST NOT emit an attachment, or a page naming it, that fails this rule or the path grammar of AGSC-01-35 (AGSC-E902): build reports the code and emits nothing (AGSC-09-08), whether or not lint ran first (added at rc.6, 2026-09-24: the rule was a content MUST checked by the lint lane alone, so build without lint published an SVG attachment carrying a script). Attachment text is an injection-scan input (AGSC-08-13) because it enters the chunk export verbatim (AGSC-06-30). diagram (AGSC-02-13) is unchanged and is SVG by construction; at rc.5 that rule subjects the inlined compiled SVG to the constraints of this one, so one allow-list governs every SVG a page carries. [PRD-059]
  • AGSC-02-99 A concept with kind: task MAY carry task_state, one of the nine Agent2Agent 1.0 task states verbatim: TASK_STATE_UNSPECIFIED (default), TASK_STATE_SUBMITTED, TASK_STATE_WORKING, TASK_STATE_INPUT_REQUIRED, TASK_STATE_AUTH_REQUIRED, TASK_STATE_COMPLETED, TASK_STATE_FAILED, TASK_STATE_CANCELED, TASK_STATE_REJECTED; in a board a reader did not author, an unknown value is read as TASK_STATE_UNSPECIFIED (AGSC-11-02); in the node's own frontmatter an unknown value is AGSC-E203. status is orthogonal: it governs publication, task_state governs the board (AGSC-10-13). On a concept whose kind is not task, task_state is the warning AGSC-E207 and is ignored by every derived artefact — it is not a board entry and does not make its cluster a board (added at rc.5). [design]
