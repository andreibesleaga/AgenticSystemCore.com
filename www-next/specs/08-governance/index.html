AGSC-08 — Governance: provenance, gates, lints, ledger

SummaryWho made what and who approved it: provenance, sign-off trailers, gates, the four agent-safety lints, the optional agent lane and the ledger derived from git history.

Status of this document

Specification 1.0.0-rc.4, a release candidate tagged on 2026-09-18. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no body has endorsed it. Released sections are immutable; a correction ships as a new version.

In plain language

Provenance on everything. Every item says how it came to be — human, ai-assisted, ai-generated or imported — with the operator accountable for it and, when a model wrote it, which model.

Changes are proposals. Nobody writes to the published branch directly, agents included. A change is a pull request with a DCO-Plus trailer; gates run as CI checks; a human ratifies. One narrow, configured, revocable exception exists for a trusted automatic channel.

Agent safety. Four lints run on every build: an injection scan over bodies, frontmatter at any depth, attachment text and every prose export; a clean-room check; a check that skills stay inert; and a staleness check. Every text handed to a model is marked untrusted.

The ledger. A hash chain derived from git history — never appended by hand — whose head is pinned in the discovery file. It proves the published history was not altered; it does not prove who the author was.

The agent lane (rc.4). A node may declare an agent — a model or a program, with a budget — that creates, edits, reviews and updates items on its own. It never writes: everything it does is a proposal through a channel, every run is recorded as an episode with its cost, it may only touch concepts, episodes and lessons, it creates at most a set number of items per proposal, and it stops for the month at its own budget or at the node's. refresh --agent <name> --dry-run shows the proposal it would open without opening it. If the channel's publish choice is auto, the node is self-driving; the human's ratification is that one configured choice, and procedures, gates and configuration still wait for a person.

This box explains; the rules below decide. New to the notation? See how to read the specification.

8.1 Provenance contract

  • AGSC-08-01 Every item MUST carry prov{origin, operator}; agent and model MUST be present when origin is ai-assisted or ai-generated. A missing prov is AGSC-E501; a missing operator is AGSC-E503. A missing agent or model under an ai-* origin is AGSC-E202 (a lint check, since the schema keyword subset cannot express the conditional). [PRD-042 ← D07, Art. XIII]
  • AGSC-08-02 prov.commit and prov.reviewer MUST be derived at build — commit from a supplied git-log file, reviewer from verified[] — and MUST NOT be written into a content file; a build MUST NOT write into content/ at all (formerly AGSC-02-08). Continuous integration MUST NOT commit to the content branch — with the single exception of the channel:auto merge of AGSC-08-26, which is performed with the channel owner's own credential (CHANNEL_TOKEN_<name>), never with the CI token, and which is a merge of a Proposal the owner's registered publish: auto choice already ratified. [PRD-042 ← G35, D27, D52(4)]
  • AGSC-08-03 A Review is evidenced by a verified[] entry {by, at} added by a human; the verdict lives in the forge. (Approval is human-only: AGSC-08-08 — M8.) [audit/D §1.1, PRD-041]
  • AGSC-08-04 propose MUST write dist/proposal/<n>.patch and dist/proposal/<n>.md, print the commands a human must run, and MUST NOT perform any network write. [PRD-039 ← D13, D27]
  • AGSC-08-05 The pull-request body MUST contain the marker <!-- agsc:proposal v1 --> followed by rationale, affected slugs and prov.origin. [audit/D §3(b)]

8.2 DCO-Plus trailer grammar

  • AGSC-08-06 An accepted contribution MUST carry a trailer block matching:
trailer-block = signoff *( LF assisted )
signoff       = "Signed-off-by:" SP name SP "<" email ">" SP "(" agreement ")"
assisted      = "Assisted-by:" SP producer "/" version SP "(operator:" SP actor ")"
agreement     = "CA-v1"
actor         = "human:" idstart *idchar
idstart       = lcalpha / DIGIT
idchar        = lcalpha / DIGIT / "." / "_" / "-"
lcalpha       = %x61-7A                       ; a-z
name          = nchar *( nchar / SP )         ; MUST NOT end with SP
nchar         = %x21-3B / %x3D / %x3F-7E      ; visible ASCII except "<" and ">"
email         = local "@" domain
local         = 1*( ALPHA / DIGIT / "." / "!" / "#" / "$" / "%" / "&" / "'" /
                    "*" / "+" / "-" / "/" / "=" / "?" / "^" / "_" / "`" /
                    "{" / "|" / "}" / "~" )   ; RFC 5322 dot-atom subset
domain        = label *( "." label )
label         = ( ALPHA / DIGIT ) [ *( ALPHA / DIGIT / "-" ) ( ALPHA / DIGIT ) ]
producer      = 1*( ALPHA / DIGIT / "-" / "_" / "." )
version       = 1*( ALPHA / DIGIT / "." / "-" / "+" )

name is disambiguated greedily: the last SP "<" on the line starts the email, everything before it is the name. actor is exactly the human:<id> form that AGSC-02-07 requires of prov.operator, so a valid trailer exists for every valid item. A missing or malformed trailer is AGSC-E504. [PRD-040 ← D07, D37, D48(5)]

  • AGSC-08-07 When prov.origin is ai-assisted or ai-generated, an Assisted-by: line naming the operator is REQUIRED in addition to the Signed-off-by: line, and the operator MUST match prov.operator (AGSC-E505). [PRD-040, PLAN §12 T2]
  • AGSC-08-08 Approval is human-only. An agent MUST NOT be recorded as an approver. The channel owner's registered publish: auto choice (AGSC-01-31) is that human's standing approval for exactly the pull requests that satisfy every condition of AGSC-08-26 — a narrower, configured, revocable act, not an agent approving; nothing else may merge without a fresh verified[] entry. [D13, PRD-041, D52(4)]

8.3 Gates

  • AGSC-08-09 A gate item's checks[] MUST compile to named required status checks, one per value; level: L1 covers schema and links, level: L2 adds provenance, determinism and review. [PRD-031 ← D44(b), research/12 §P rule 29]
  • AGSC-08-10 A gate verdict MUST be written to dist/gate.json as a JCS-canonical object {gate, level, checks:[{name, status, findings}], status} where status ∈ pass|fail. [PRD-031, AGSC-04-04]
  • AGSC-08-11 A broken internal link MUST fail the Bundle's own gate; it MUST NOT reject an imported foreign bundle. The links gate value compiles to exactly two checks — AGSC-E301 on the fourteen frontmatter Link keys (AGSC-03-02) and AGSC-E310 on unresolved relative body references (AGSC-03-11) — and to nothing else. [research/12 §P rule 30, AGSC-01-22 ← V5-3 S3-02]
  • AGSC-08-12 enforce[] values are status-check, hook, codeowner and ruleset. A writer MUST compile each value deterministically and idempotently — status-check to a named required check, hook to a pre-commit hook file, codeowner to CODEOWNERS entries, ruleset to a forge ruleset JSON — MUST report drift against the repository rather than overwriting silently, and MUST NOT emit an executable beyond the hook file itself (AGSC-07-15). [audit/D §1.2, D53, G34 lifted]

8.4 The four agent-safety lints

  • AGSC-08-13 injection-scan MUST detect, over item bodies, every string at any depth of item frontmatter (vendor x- keys included, AGSC-02-05a), the text of every text-media attachment (AGSC-02-98), and every exported prose surface: agent-directed imperatives; hidden text (HTML comments, zero-width characters, U+E0000–U+E007F tags, variation selectors U+FE00–U+FE0F and U+E0100–U+E01EF outside an emoji sequence — Unicode 18.0 names them as an AI-prompt smuggling channel, AR2-24 — bidirectional overrides); long base64 or hex blobs; links whose scheme is neither http nor https. Codes: AGSC-E401 (imperatives, blobs, schemes), AGSC-E402 (hidden text). Severity MUST be warn for human-authored items and error when prov.agent is set; patterns come from lint.injection_patterns[] as literal alternations — never a user-supplied regular expression — over input capped at 1 MiB. (AGSC-08-14 merged here at rc.3, M5.) [NFR-07 ← N9, ADR-001]
  • AGSC-08-14 (retired at rc.3, 2026-09-17, V6-B minimality pass confirmed by D81: severity and pattern source of the scan AGSC-08-13 defines (M5) — merged into AGSC-08-13; the id is reserved under AGSC-00-16 and never reused.)
  • AGSC-08-15 no-secrets MUST reject credential-shaped strings — private-key blocks, provider token prefixes, password:/api_key: assignments (AGSC-E403). [PRD-046, D40(7)]
  • AGSC-08-16 no-pii MUST reject e-mail addresses and telephone numbers outside prov and sources[] (AGSC-E404). [NFR-07, PLAN §12 T8]
  • AGSC-08-17 clean-room MUST refuse a non-empty bookRef on import, exclude endorsements.json, book.md and start-here.json, reject book or "companion" framing and any reading-order construct, and forbid a whole-corpus PDF or EPUB emitter (AGSC-E405). [NFR-12 ← D08, W1–W12, Art. XIII]
  • AGSC-08-18 Tools MUST take item ids only — or, for ask and remember alone (AGSC-09-14a/14b), plain text that is treated strictly as data: never executed, never interpolated into a path, URL or shell string, and never resolved as an identifier. No signature may accept a path, URL or shell string. Every tool result MUST be JSON carrying source, trust, license, type and body, with trust fixed at untrusted. [NFR-07 ← N9, PRD-023]
  • AGSC-08-19 These lints prove neither safety nor the absence of novel injection; hashes and attestations prove only that an artefact is what was published. An implementation MUST NOT claim more. [ADR-001 honest limit]

8.5 The ledger

  • AGSC-08-20 ledger.jsonl is a derived artefact, not a stored one: build and ci MUST recompute the whole file deterministically from the git history of the content branch exactly as AGSC-08-20a derives it (M14), and MUST write it only into the build output (build.out, default www/) and the release assets. It is one JCS-canonical object per LF-terminated line, hash-chained by AGSC-08-22, never hand-written, never committed to content/ and never committed by CI (AGSC-08-02). Two builds of the same history therefore produce the same file — there is no append race, no partial-write recovery and no writer to serialize. [PRD-005 ← D44(h) as amended by D48(1), Art. XII]

  • AGSC-08-20a Derivation (normative, byte-reproducible). The input is the git-log file of AGSC-08-02, a JCS-canonical JSON array [{sha, committed_at, parents[], tag?, trailers{}}] listing the first-parent commit chain of the content branch from the root commit to HEAD, oldest first; a shallow clone MUST fetch the full history or exit 2 with AGSC-E703. The ledger is then exactly one entry per element, in that order, followed by exactly one trailing entry, and nothing else:

    • per commit — ts = committed_at (an AGSC-04-10 instant string, YYYY-MM-DDTHH:MM:SSZ, so ts = committed_at verbatim; a producer converting from git's epoch-plus-offset form MUST convert to UTC first), rendered per AGSC-04-10 as YYYY-MM-DDTHH:MM:SSZ, ref = the full 40-hex sha, actor = the Signed-off-by local part normalized to human:<id> per AGSC-02-90(2) (else human:unknown), kind = release when a v* tag points at the commit, else merge when it has ≥2 parents or a Proposal: trailer, else commit; mode: "auto" is added when and only when the commit carries the Channel-Auto: <name> trailer written by the auto lane (AGSC-08-26).
    • one trailing build entry — ts = SOURCE_DATE_EPOCH, kind = build, ref = the git tree hash of content/, actor = process:agsc/<version>. It is the only entry that depends on the run, and it depends on nothing about who ran it, so owner and CI builds of one history agree byte for byte. An empty history yields the trailing build entry alone. No other kind is emitted at 1.0: proposal, review and refresh are reserved for 1.x. [PRD-005 ← D52(2), V3-02]
  • AGSC-08-20b Production of the git-log file (normative). AGSC-08-20a pins how the array is consumed; this rule pins how it is produced, so that two conforming ports derive one ledger and one agsc-ledger-head from one history. The array is the first-parent chain of the content branch, oldest first, from the root commit to HEAD. trailers{} is the trailer block as git interpret-trailers defines it — the last contiguous run of Key: value lines at the end of the commit message, continuation lines unfolded into one value, keys compared ASCII-case-insensitively and reported in their authored spelling; where a key occurs more than once only the last occurrence is used. committed_at is the committer timestamp in whole UTC seconds rendered per AGSC-04-10. tag is the lexicographically greatest v* tag pointing at the commit by code-point order, or absent when none does. parents[] lists every parent sha in git's own order. The reference production is git log --first-parent --reverse on the content branch; any producer yielding the same JCS array conforms, and no other git invocation, environment variable or locale may change the result. [PRD-005 ← D52(2), V5-3 S3-03]
  • AGSC-08-21 A 1.0 entry has exactly actor, hash, kind, prev, ref, ts, plus OPTIONAL mode, whose only 1.0 value is auto, on a kind: merge entry — or on a kind: release entry when the tagged commit is itself a channel-auto merge, since AGSC-08-20a gives release precedence (V6-B U6; derived from the commit's trailer, never from forge metadata). Token accounting lives on episode items (AGSC-02-14) and reaches the NOW rollup from there (AGSC-08-25), never through the ledger. kind ∈ build|commit|merge|release at 1.0, with proposal|review|refresh reserved; a reserved kind introduced by a future MINOR MAY add members, and a 1.x reader MUST tolerate them when recomputing the chain, since AGSC-08-22 hashes whatever the entry carries. ref and ts are fixed by AGSC-08-20a and never read a wall clock (AGSC-04-11). [D44(h), D48(1), D52(2), V3-37]
  • AGSC-08-22 hash MUST be the lowercase hex SHA-256 over the 64 US-ASCII bytes of the lowercase-hex prev string immediately followed by the UTF-8 bytes of the JCS serialization of the entry excluding its own hash. The first entry's prev is 64 0 characters (the all-zero SHA-256 in lowercase hex), which makes the genesis link the same fixed width as every other and removes the empty-string special case. [D44(h), D52(2)]
  • AGSC-08-23 verify --ledger MUST recompute the chain offline — from the local git history for a clone, or over the published file for a downloaded one — and fail with AGSC-E701 at the first mismatching hash or prev. It MUST additionally compare the recomputed chain head to the agsc-ledger-head target attribute of the …/rel#ledger link in the local well-known file (§06); a mismatch is AGSC-E701 even when every line links correctly, which is what detects a truncated tail. A published file whose lines differ from the recomputation of the same history is AGSC-E702, and a history too shallow to recompute is AGSC-E703 with exit 2. [PRD-005, D48(1), D52(2)]
  • AGSC-08-24 The chain head MUST be published as the agsc-ledger-head target attribute of the …/rel#ledger link in the well-known file (§06) and attested at release. [PRD-024, D44(h), D55]
  • AGSC-08-25 Monthly usage.cost_usd MUST be rolled up on the NOW page as a visible spend line (the launch-lane prohibition and its enforcement are AGSC-08-27's — R16); at rc.4 the rollup is also the meter of the node-wide cap budget.usd_month (AGSC-01-38): it MUST count every Episode of the calendar month whose usage carries cost_usd — merged ones, those in open Proposals of the node's own lanes, and those printed by a dry run (AGSC-08-28(f)) — and every model-calling path MUST stop for the month when the cap is reached (AGSC-E510). [NFR-11 ← D14, Art. XV, D88]

  • AGSC-08-26 (auto channel merges, added 2026-09-03 as a duplicate AGSC-08-25, renumbered by D52(4)) A merge without a fresh human verified[] entry is permitted ONLY when all of these hold, every one checked by CI against configuration or forge identity and none against self-declared frontmatter: (a) the pull request carries the label channel:auto; (b) the diff is confined to content/** items of type ∈ concept|episode|lesson — a procedure is excluded outright as a conservative choice (its prose reaches the per-Cluster skill packs of AGSC-07-19 and the Harness files of AGSC-07-12, both agent-facing), and config, workflows, schemas, Gates and every other path always fall back to hitl (D51-c). concept and lesson are admitted because AGSC-01-28 withholds any item whose latest content-branch commit carries a Channel-Auto: trailer from every --steer target until a human verified[] entry ratifies it; episode is admitted because AGSC-01-28 never sources a steer bundle from an Episode at all, so an auto-merged Episode reaches no agent-facing digest before review (V5-3 S3-12; rationale corrected at rc.3, V6-B U4/U5); (c) the pull-request author equals the channel's registered forge identity channels[].author, and the head commit carries the trailer Ingested-by: <channel>; (d) each changed item's prov.operator equals channels[].owner from agsc.config.json, and carries prov.agent (the adapter or client id) with prov.origin = imported (ingest) or ai-generated (remember) — never human, so AGSC-08-13 runs the N9 lints at error severity; (e) lint reports no error, the injection, secrets and PII lints included; (f) the merge is performed by a separate credential CHANNEL_MERGE_TOKEN_<name> in the auto-merge job of review.yml — held by the channel owner, the only identity on the branch ruleset's bypass list, used by no other job, and inaccessible to the ingest job, which holds only CHANNEL_TOKEN_<name> (AGSC-01-30). Neither is GITHUB_TOKEN. Separating the two credentials is what keeps token scope and branch protection in different hands: forge fine-grained tokens are not ref-scoped, so an ingest identity that also held the bypass could push directly to the content branch. The secret inventory is therefore two per registered channel, both deploy-job-only, both under the ≤90-day TTL of the secret inventory in docs/PLAN.md §7. (g) every commit on the content branch MUST be a merge commit reachable from a merged pull request and MUST carry either a Signed-off-by trailer from a human (AGSC-08-06), a Proposal: trailer, or a Channel-Auto: <name> trailer. verify and ci MUST report as AGSC-E706 (error at 1.0) any commit on the content branch that is not such a merge commit, or that carries none of the three trailers, or whose author is the ingest identity of (f), naming the sha. The same code is reported when the ingest identity CHANNEL_TOKEN_<name> is found on the ruleset bypass list, which AGSC-01-30 forbids. Promoted from a 1.0 warning by D61(2): the bypass of (f) is the widest privilege path in the system and a warning is not a control. The channel-auto lane is OPTIONAL: a Bundle with no channels[] entry whose publish is auto satisfies this rule vacuously, and a Level-3 claim does not require it. Conditions (a) and (f) name the GitHub realization; on another forge they are satisfied by that forge's equivalents — a labelled or otherwise machine-marked proposal, and a merge performed with the channel owner's own scoped credential rather than the CI token. Conditions (b)–(e) and (g) are forge-independent and MUST hold on every forge.

    The merge commit MUST carry Channel-Auto: <name>, which is what puts mode: "auto" on the derived ledger entry (AGSC-08-20a). This is the single exception admitted by AGSC-08-02 and AGSC-08-08. [PRD-056, D51-c ← D52(4), AGSC-01-31, N9, V3-28, V3-29, V3-30]

  • AGSC-08-27 (LLM review lane, added 2026-09-04 by D61(4)) An LLM review lane is OPTIONAL and is controlled by a single environment feature flag: it MUST be off unless the environment variable AGSC_FEATURE_LLM_REVIEW is set to 1 (any other value, or its absence, means off), and no Bundle file, configuration key or PR content may enable it. When the flag is unset the lane MUST NOT be reachable at all; it MUST NOT run in any lane that gates a merge or a deploy; it MUST add only a label and a non-blocking comment and MUST NOT set, require or influence a status check, a verified[] entry or an approval (AGSC-08-08); it MUST run under the spend cap of AGSC-08-25; and it MUST record its spend as an episode item carrying usage (AGSC-02-14, the mechanism of AGSC-01-32 and AGSC-09-14a), so the monthly rollup on the NOW page sees it. The launch pipeline — the ci and review lanes and everything they call — MUST contain no model call, and the build MUST fail if a model call is reachable from either, which is the grep-asserted proving lane of NFR-11. A Bundle that never enables the lane satisfies this rule vacuously, and no conformance Level requires it (AGSC-10-04). [PRD-041, NFR-11, D53 §G ← D61(4), owner 2026-09-04 ← D62(1), V5-3 S3-27]

8.6 The agent lane — optional, configured, non-deterministic only in what it proposes (added at rc.4, 2026-09-17 — D87, R66)

  • AGSC-08-28 DECLARE and RUN. An agent lane exists only as an agents[] entry (AGSC-01-36) with enabled: true, and runs either as refresh --agent <name> — the verb that MAY read a real clock and the network (AGSC-04-11, AGSC-09-07 unchanged: no verb is added) — or as a client of the tool server or the page tools (AGSC-09-13, AGSC-09-16) whose prov.agent equals the entry's name. Every run MUST: (a) read only the Bundle files and the published surfaces (graph, chunks, llms.txt, boards, NOW), fencing every Bundle prose it hands to a model as data (AGSC-08-18, AGSC-01-29); (b) write nothing to the content branch — every output is a Proposal opened through the entry's channel (AGSC-01-30, AGSC-01-31) whose items carry prov{origin: ai-generated, agent: <name>, model: <entry.model>, operator: <entry.operator>}; (c) touch only items whose type is in the entry's types[] and only through the entry's tasks[] — a Proposal that touches anything else, or that comes from an undeclared or disabled agent, is rejected with AGSC-E509 before any lint runs — and create at most the entry's max_new_items items in one Proposal, a Proposal that creates more being rejected with AGSC-E511 in the same place; (d) add to the same Proposal one episode item recording the run — actor the agent name, outcome, usage{model, tokens_in, tokens_out, cost_usd, estimate} (AGSC-02-14), and sources[0] the SHA-256 (urn:agsc:prompt:sha256:<hex>) of the instruction bundle it ran with — so that AGSC-08-25's monthly rollup and the NOW page see it; (e) stop for the calendar month once the entry's budget_usd_month, or the node's budget.usd_month (AGSC-01-38), is reached — the month's spend being the count of AGSC-08-25 — recording the skipped run as the warning AGSC-E510 in the NOW page; (f) honour --dry-run: refresh --agent <name> --dry-run MUST do everything up to the opening of the Proposal, then write it as propose does (dist/proposal/<n>.patch and .md, AGSC-08-04), the Episode of (d) included, print the commands a person may run, and open nothing through the channel — a dry run spends, so its Episode counts under (e) and AGSC-08-25 like any other, and no other verb gains the flag (AGSC-09-09 unchanged). A run that cannot record its spend MUST NOT call a model (the rule of AGSC-01-32). [R66, D87, D88, PRD-063, PRD-065, N9, NFR-11]
  • AGSC-08-29 SELF-DRIVING nodes. A node whose agent-lane channel has publish: auto is self-driving: items are created, edited, reviewed and updated without a fresh human decision per change, under every condition of AGSC-08-26 — the type set of (b), the lints at error severity of (d)–(e), the separate merge credential of (f), the trailers of (g) — and under the budget of AGSC-08-28(e). The human ratification of such a node is the operator's configured publish: auto choice, recorded once and revocable by editing one key (AGSC-01-31); AGSC-08-08 is satisfied by that standing ratification and by nothing else — an agent MUST NOT be recorded as an approver, and an agent whose tasks[] contains review acts exactly as the AGSC-08-27 lane does: a label and a non-blocking comment, never a verified[] entry, never a status check. Procedures, gates, clusters, configuration, workflows and schemas stay in the human lane in every self-driving node (AGSC-08-26(b), T9), and every merge the lane produces carries mode: "auto" in the derived ledger (AGSC-08-20a), which is what makes an autonomous history auditable after the fact. [R66, D87, PRD-063, ADR-001, D13]
  • AGSC-08-30 The determinism boundary. Model calls occur only inside refresh --agent and inside clients of the declared surfaces; lint, build, verify and ci stay model-free (the grep-asserted lane of AGSC-08-27), so non-determinism is confined to the content of Proposals and never reaches the build, the digests, the ledger derivation or any vector. An agent-lane run is reproducible in its record (the Episode of AGSC-08-28(d): model, prompt digest, tokens, cost, outcome), not in its output; its outputs are untrusted text (AGSC-08-18) until merged, and after merge they are ordinary items whose provenance says a model wrote them. A Level-3 claim does not require an agent lane; a Bundle with no agents[] entry satisfies §8.6 vacuously. [R66, D87, AGSC-04-01, NFR-05]
