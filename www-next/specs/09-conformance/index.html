AGSC-09 — Conformance: classes, vectors, error codes, CLI contract

SummaryHow a claim is made and checked: classes and Levels, the vector format, the command-line contract, the error-code registry and the independent validators.

Status of this document

Specification 1.0.0-rc.6, a draft release candidate, not yet tagged. It is an independent specification: it is not a standard of the IETF, the W3C or any other body, and no standards body has reviewed or adopted it. Released sections are immutable; a correction ships as a new version.

In plain language

Classes and claims. Reader, writer, full engine; a claim names the class, the version and the vectors passed.

Vectors. One JSON file per test case under tests/vectors/<area>/, with an input, an expected result and the rule it proves. Twenty-five areas exist; a required vector that is skipped counts as a failure. Withdrawn vectors are kept for history and never run.

The CLI. Sixteen verbs, a JSON envelope on every result, exit codes with fixed meaning, no stray output on the tool channel. The local tool server exposes exactly seven tools.

Error codes. AGSC-E<nnn> in blocks by area (0xx CLI, 1xx parse, 2xx schema and boundary configuration, 3xx links, 4xx lint, 5xx provenance and adoption, 6xx canonicalization and determinism, 7xx ledger, 8xx composition, 9xx I/O and federation), registered once each; every code used has a registry row that names the rule that raises it.

Validators. A reference distribution ships standalone validators for the spec text, schemas, ontology, vectors, discovery file, features and diagrams, plus two generators — nine command contracts in all (AGSC-09-90) — so that an independent party can check every normative artefact.

This box explains; the rules below decide. New to the notation? See how to read the specification.

9.1 Classes and claims

  • AGSC-09-01 A claim MUST name its Level — AGSC-10-01 is the single statement of the class-to-Level mapping and AGSC-10-15 of the vector set a Level runs — the spec_version MAJOR.MINOR and the vector set passed; the class names of AGSC-00-09…11 are the Levels' names and nothing more (rc.3). [PRD-010]
  • AGSC-09-02 A conformance run MUST execute every required vector of the declared areas and MUST report pass, fail or skip per vector id. A skip counts as a failure for a required vector. [design]
  • AGSC-09-03 A conformance-report.json MUST be producible by agsc conform as {impl, version, spec_version, class, results:[{id, status, got?}], summary}, and a node MAY publish it at /conformance/ together with a table of third-party claims. A published claim is the claimant's own assertion; this specification defines no arbitration. A claimant MAY additionally publish a rule-coverage matrix: for every rule id of this specification, the machine verifications that cite it — a vector's rule, a test, an acceptance scenario, a checker — or a stated reason why the rule is verified by review alone. The reference distribution MUST publish one, so that a reader can see which of this specification's rules are proved by the suite and which are not, without running it. No Level requires the matrix, and a published matrix is the claimant's own assertion, exactly as a published conformance report is. (added at rc.6, 2026-09-23: the suite proved rules without saying which, so no reader could tell a rule proved by a vector from a rule nobody checks; the obligation is named and the artefact is not, so no file name or byte is pinned.) [design]

9.2 Vector format

  • AGSC-09-04 A vector is one JSON file under tests/vectors/<area>/ containing one object with members id, area, rule, level, description, input, OPTIONAL options, OPTIONAL reason (REQUIRED when level is withdrawn: why the case was withdrawn and which vector supersedes it), OPTIONAL superseded_by (the id of the vector that supersedes a withdrawn one, so that a machine follows the chain without reading prose; carried by every vector withdrawn from 2026-09-24 on that has a successor — the earlier withdrawals name theirs in reason alone, and a released file is not edited for it), OPTIONAL note (editorial provenance of an unreleased vector; never read by a conformance run), OPTIONAL requires_surface (an array of agsc-surface names: a vector that a claimant's node does not declare any of is skipped and counts as passed, so a Level-2 writer is never held to a Level-3 surface), and expected. Areas are frontmatter/, slug/, links/, jcs/, graph/, lint/, cli/, plus bundle/, prov/, ledger/, compose/, build/, discovery/, adopt/, import/, export/, skills/, adapters/, channels/, harness/, run/, conform/, and (rc.3) boundary/, chunks/, boards/ — twenty-five, and no others. webmcp/ is not an area: AGSC-09-16 is proved by cli/cli-0003, so a permanently empty declared area would be a false promise. adapters/, channels/ and harness/ are declared here so that the milestones that populate them need no spec_version change. [design]
  • AGSC-09-05 rule MUST cite one rule id of this specification. level is required, optional or withdrawn (AGSC-00-16); a withdrawn vector MUST NOT be counted for or against any conformance claim, MUST carry reason, and MUST have expected reduced to {"withdrawn": true} so that a superseded expectation can never be read as normative. A negative vector's expected MUST carry the member error whose value is an AGSC-E<nnn> code, never a message; it MAY additionally carry severity, exit, stdout, line, cycle, chain or parents, and a vector asserting several outcomes MAY nest an error member inside a named sub-object (graph-0005) or, since rc.3, list them as AGSC-09-11 finding objects under findings[] or results[], each carrying code (the same AGSC-E<nnn> value) and severity. [design]
  • AGSC-09-06 Vector files MUST be UTF-8, LF-terminated, NFC — except an input string whose non-NFC form is the subject of the case (jcs-0005, lint-0022), which a port MUST NOT normalise on load — I-JSON, with object members in JCS order (§04); they MAY be pretty-printed for review. They MUST be consumable without executing any code from this repository, so that a port in any language can run them directly. [NFR-02]

9.3 CLI contract

  • AGSC-09-07 The verb set is exactly sixteen: init, lint, build, verify, ci, export, import, compose, propose, review, refresh, skills, mcp, run, trace, conform. run and trace MUST be opt-in and disabled by default (AGSC-01-18 run.enabled, default false); conform executes the vector set of a declared Level (AGSC-10-01) and writes the AGSC-09-03 report. Any other verb MUST exit 2 with AGSC-E001. This rule binds the command-line interface of a full engine (the class of AGSC-10-01); a distribution that is not a full engine MAY ship a command of the same name that forwards the sixteen verbs to an engine and adds the command contracts of AGSC-09-90 as further verbs, and it MUST forward every other verb or refuse it with AGSC-E001 and exit 2 (added at rc.6, 2026-09-24: a checker distribution that ships such a command read this rule as forbidding it). An implementation MAY ship further commands of other names beside the engine's command — for example one that puts a build on a host — provided none of them changes an artefact of AGSC-04-24 or a route of AGSC-06-01 (added 2026-09-24). [PRD-001]
  • AGSC-09-08 Exit codes: 0 success; 1 findings, a failed gate or a non-reproducible build; 2 usage error — an unknown verb (AGSC-E001, AGSC-09-07), an unknown flag (AGSC-E002, AGSC-09-09), a missing required argument (AGSC-E003), or invalid configuration, including a malformed SOURCE_DATE_EPOCH (AGSC-E603), which is an environment/configuration fault and never a finding (the three codes were registered against the CLI block and named by no sentence until rc.5). [PRD-007]

  • AGSC-09-09 Global flags --json, --quiet, --plain, --no-input, --version, --help MUST be honoured, as MUST NO_COLOR and AGSC_* environment variables; a flag outside this list and outside the verb flags below is AGSC-E002 with exit 2 (AGSC-09-08), and so is a positional argument a verb does not define (stated 2026-09-24: the rule closed the flags and said nothing of a stray argument, which a reference engine accepted in silence). Precedence is flags > environment > project configuration > user configuration; at rc.4 the environment includes the .env file of AGSC-01-37, read after the process environment, and every scalar configuration key has an AGSC_* name there.

    --help (added at rc.5) MUST print the verb set of AGSC-09-07 and this flag list to stdout and exit 0; with a verb, it MUST print that verb's flags. It is the one flag that is not a diagnostic, and it is a flag rather than a verb so that AGSC-09-07's sixteen stay sixteen. (Before rc.5 agsc --help was a usage error, because --help was neither a global flag nor a verb.)

    Verb flags (added at rc.5: four rules oblige lint --fix and §9.3 never named it, so a conforming engine could not discover that the flag exists and the reference engine answered AGSC-E002). lint additionally takes --fix, which applies exactly the normalisations AGSC-04-19 admits and nothing else (AGSC-04-14, AGSC-04-20, AGSC-03-12); an engine that does not implement it MUST reject the flag with AGSC-E002 rather than accept it and do nothing. The other verb flags this specification already obliges, each named by the rule beside it, are verify --ledger (AGSC-09-14), export --markdown|--okf|--jsonld|--jsonl|--steer [--target <name>[,<name>…]]|--to <adapter> — one comma-separated list of registry names, never a repeated flag (stated at rc.6, 2026-09-22: AGSC-01-28 wrote --target <name>…, which reads as repeatable, while this list types every verb flag as taking one value) (AGSC-01-26…28, AGSC-01-26a), import --from <adapter> with --dry-run, which reports the plan and writes nothing (AGSC-01-26a), compose --from <slug> and compose --emit <target> (AGSC-07-24, AGSC-07-18), compose --out <dir> — the directory the seven file kinds of AGSC-07-12 are written into, defaulting to that rule's own dist/harness/<name>/ so that a conforming invocation needs no flag, and whose value MUST NOT reach any emitted byte (AGSC-07-13) — compose --zip, skills --zip and export --zip — each writing the files that invocation produced as ONE archive, beside the directory that holds them and never inside it, so that a reader may take a multi-file result in one download; the archive's bytes are AGSC-07-13a's, and it is a packaging and never a file of the Harness (AGSC-07-12) nor an input to any build (AGSC-01-16) — refresh --agent <name> with --dry-run (AGSC-08-28(f)), refresh --task <slug>, the declared lane task to run (AGSC-08-28(c)), run --dry-run (AGSC-09-94), build --level <n> and ci --level <n>, the Level a build emits (AGSC-10-02, AGSC-10-04; default 2), conform --level <n>, the Level whose vector set runs (AGSC-10-01; default 3), and conform --to <path>, where the AGSC-09-03 report is written (default dist/conformance-report.json); and mcp takes one OPTIONAL positional <path>, the Bundle root it serves, defaulting to the working directory, so that an assistant with no working-directory setting can start it without a shell. propose --task-state <state> with --at <date>, which prepares the board move of AGSC-10-17 exactly as the propose tool does (AGSC-09-14b), is OPTIONAL: an engine that does not implement it rejects both with AGSC-E002. (init --adopt was removed and the five --level, --to and --task flags, the mcp path and the optional propose flags added at rc.6, 2026-09-24: adoption happens whenever init meets plain Markdown and needs no flag, and the reference engine implemented the others while this closed list named none of them.) (compose --out and import --dry-run were added to this list at rc.5: AGSC-07-12 fixes the only legal location, so without the flag no operator could build a Harness into a scratch directory and no test could assert the emission without writing into the Bundle, and the closed list made both AGSC-E002.) (the three --zip flags were added to this list at rc.6, 2026-09-22: a "download all" archive now sits beside the per-file links and requires the command line to produce the identical archive, and the closed list below made all three AGSC-E002. The adapter exception below could not admit them: compose and skills have no adapter selector at all, and an adapter flag belongs to one adapter, while --zip must mean the same thing for every export form — the route the rules do allow is the one taken for compose --out at rc.5.) No other flag exists at 1.0 on any verb, except that a memory adapter selected by export --to <adapter> or import --from <adapter> MAY define further flags of its own (AGSC-01-26a): they belong to that adapter's documented contract and not to this specification, they MUST NOT change the meaning of a flag named above, and an engine that does not ship the adapter rejects them with AGSC-E002 (added at rc.5: an adapter is a MAY whose flags cannot be enumerated here, and the closed list rejected them all — the reference old-site adapter takes --selection, --corrections and --attach-diagrams); --allow-newer, which AGSC-01-22 names, is one such flag (named here at rc.6, 2026-09-24, so that a reader of this rule alone can find it). --peer belongs to tools/validate-wellknown, not to a verb; --level on that tool is the tool's own (AGSC-09-93, AGSC-10-12). [PRD-007]

  • AGSC-09-10 Data goes to stdout; diagnostics go to stderr. Under --json, stdout MUST carry exactly one JCS-canonical envelope and stderr MUST carry one JSON object per line, one per finding — except where exit 2 is reached before a verb is resolved (an unknown verb or an unknown flag, AGSC-E001/AGSC-E002: there is no verb to name in verb), or where an internal fault has no registered code, in which case stdout carries nothing and the fault is reported on stderr alone (added at rc.5: both are zero-envelope cases the unconditional sentence denied, and both are the right behaviour). findings[] in the envelope, and the stderr lines, MUST be ordered by (file, line, col, code) compared code-point-wise, so that a byte comparison of the output is stable however the lint phases were scheduled. [design]
  • AGSC-09-11 The envelope shape is the JSON object below. [PRD-003, PRD-007]
{ "counts": { "error": 0, "warn": 0 },
  "findings": [],
  "schema": "agsc.diagnostics.v1",
  "spec_version": "1.0.0-rc.6",
  "status": "pass",
  "verb": "lint",
  "version": "0.1.0" }

A finding is { "code": "AGSC-E301", "col": 1, "file": "content/concepts/a.md", "line": 12, "message": "…", "severity": "error", "slug": "a" }. status ∈ pass|fail; severity ∈ error|warn — the literal is warn, never warning. [PRD-003, PRD-007]

  • AGSC-09-12 --json is REQUIRED on every verb at 1.0 and MUST emit the AGSC-09-11 envelope; the lint and ci envelopes additionally carry findings[] ordered per AGSC-09-10. [PRD-007]
  • AGSC-09-13 mcp MUST expose exactly seven tools — search, read, links, compose, propose, ask, remember (the last two per AGSC-09-14a/14b; amended 2026-09-03) — over stdio JSON-RPC, MUST NOT write non-protocol bytes to stdout, MAY log to stderr, and SHOULD exit on stdin EOF. [PRD-023]
  • AGSC-09-13a Tool error envelope. A tool that cannot fulfil a call MUST return the AGSC-08-18 envelope with type: "error", trust: "untrusted", license as usual, and body = the JSON object { "code": "AGSC-E<nnn>", "message": "…" }; source names the tool. It MUST NOT signal a domain fault as a JSON-RPC transport error — those are reserved for protocol faults (bad method, malformed params). The shape is identical on the stdio and WebMCP transports, which is what makes the byte-identity of AGSC-09-16 hold for failing calls as well as succeeding ones; A call that omits an argument the tool's inputSchema marks REQUIRED is AGSC-E003, returned in this envelope; an empty string is supplied, not missing (added at rc.5). message text is unspecified so that ports may localise it, and only code is asserted (AGSC-09-05 — corrected at rc.5: the earlier text cited AGSC-09-06, which governs vector-file encoding). cli/cli-0004 is its vector. [PRD-023, PRD-051, AGSC-08-18, AGSC-09-11]
  • AGSC-09-14 verify MUST build twice and compare bytes; verify --ledger MUST re-verify the hash chain offline. [PRD-004, PRD-005]
  • AGSC-09-14a A Channel responder (ask) answers questions using only the Bundle's published exports (a Level-1 reader over search.json/graph.jsonld/pages/*.md, or the local MCP tools search read links). Its result MUST be the AGSC-08-18 envelope — {source, trust: "untrusted", license, type, body} — with exactly one added top-level member, citations[], an array of item IRIs; body is the answer text itself, and MUST be exactly no answer in this memory when nothing matches — that is, when no published item shares a search token (AGSC-06-23) with the question other than the stop words the tokenizer drops (defined 2026-09-24). Every answer MUST cite ≥1 item IRI in citations[], and the Content Use Terms line is embedded in body. (Amended at rc.5: "with body = the answer and an added citations[]" admitted two readings — citations[] as a sixth envelope member with body a string, or citations[] inside body with body an object, in which case body can never be exactly the fixed string. The reference engine took the second reading. No vector pinned the shape, so two conforming engines could differ on a published tool contract; the first reading is now the only one, and cli-0007 pins the bytes for a matching and a non-matching question.) A responder MAY use an LLM only under the spend cap, and one that does MUST record its spend by emitting a remember(kind: episode) Proposal carrying usage — otherwise its spend never reaches the NOW rollup (AGSC-08-25) and the cap is unenforceable. Responders are plugins; none is required for conformance at any Level. [PRD-056]
  • AGSC-09-14b The tool set is AGSC-09-13's and WebMCP mirrors it under AGSC-09-16. remember({kind, title, body, at, actor?, outcome?, severity?, sources?, cluster?, about?, usage?}) MUST synthesize a conforming item (AGSC-02) — usage being the OPTIONAL {model, tokens_in, tokens_out, cost_usd, estimate} object of AGSC-02-14, REQUIRED when the caller is an LLM responder (AGSC-09-14a) or an agent lane (AGSC-08-28(d)) and carried onto the synthesized episode verbatim; added at rc.5, because AGSC-09-14a obliges a responder to record its spend through this call and the signature had no argument in which to pass it, which made AGSC-08-25's cap unenforceable for responders: type from kind; slug from the title per the AGSC-02-91 slugifier with -2, -3, … collisions; at (an instant, REQUIRED for episode) supplies started — a clock is never read (AGSC-04-11); outcome defaults to partial, and severity defaults to info for a lesson, the one kind whose schema branch carries it (corrected 2026-09-24: the sentence also named episode, whose branch has no severity, so a defaulted episode carried a key lint reports as unknown); a call that declares no at for an episode is AGSC-E003, like one that declares no actor; a concept gets kind: explainer; actor is the client's declared agent actor string (AGSC-02-09), REQUIRED when kind is episode — a call that declares none is AGSC-E003, because that item's schema branch requires it; remember accepts the kinds concept, episode, lesson, procedure and task, and refuses gate with AGSC-E203, because a Gate's Level is a governance decision that a tool call may not invent; prov.operator = the client's declared human operator, prov.agent/prov.model = the client's declared identity, and prov.origin: ai-generated unless the client asserts human. It hands the item to the Proposal path (AGSC-08) under the client's channel publish mode (AGSC-01-31, default hitl) and MUST NOT write to the content branch. The server MUST also expose every item as an MCP resource (text/markdown), graph.jsonld and llms.txt, and one prompt "answer from this memory with citations": the resource URI of an item is memory://<bundle-id>/<slug> (AGSC-05-04b) and only a published item (AGSC-06-30) is exposed; graph.jsonld is memory://<bundle-id>/graph.jsonld with application/ld+json and llms.txt is memory://<bundle-id>/llms.txt with text/plain; the list is ordered by URI in code-point order (AGSC-04-03); the prompt's name is answer-from-this-memory-with-citations, its title and description are answer from this memory with citations, and it takes exactly one REQUIRED argument, question; a resource URI or prompt name that does not exist is a JSON-RPC error, not the AGSC-09-13a envelope, which governs tools alone. propose MAY take task_state (one of the nine of AGSC-02-99) and at, and then returns the prepared board move of AGSC-10-17 — a patch that sets task_state and, when at is given, modified, and nothing else; remember MAY take kind: task (a concept of kind: task in TASK_STATE_SUBMITTED), cluster (the cluster it is filed in) and about (one related Link). (The defaults, the refusals, the resource and prompt names and the two board arguments were stated at rc.6, 2026-09-24: remember could not honour its own MUST for three of the five kinds it accepted, and two conforming servers could publish different resource URIs and prompt names on the same declared surface.) A client-supplied sources[] entry MUST be validated before the item is synthesized: resource MUST match the AGSC-02-10 grammar (https?://… or urn:agsc:channel:<name>:<source_id>) and MUST NOT carry any other scheme (AGSC-E401); every other member is truncated to its schema bound and NFC-normalized. An entry that fails MUST be dropped with AGSC-E506, never rejected as an error — remember is a total function like adoption (AGSC-02-90). [PRD-023, PRD-056]
  • AGSC-09-16 WebMCP. Where a browser exposes document.modelContext, the /compose/ and item pages MUST register the same seven tools as AGSC-09-13 through document.modelContext.registerTool(), with identical names, identical argument names and results equal as values to the local MCP server's for the same input and Bundle — the same members, in the same order, with the same contents; what crosses the browser boundary is whatever serialisation the user agent applies to that value, which this specification does not constrain (amended at rc.6, 2026-09-22: the live WebMCP draft has executeTool() resolve to the stringified result of the tool's execution, so "byte-identical" described bytes that are not this specification's to fix) — one tool contract, two transports (cli-0003 compares the two manifests). The Bundle a page serves is the published projection of AGSC-06-30: an item that is not published is not visible to a page tool, and a page tool MUST answer AGSC-E301 for it, exactly as the local server answers for a slug that does not exist (stated at rc.6, 2026-09-22: a page can read only what the node published, so on any Bundle holding a draft, a retired or a release-gated item the two transports could not agree and the rule was unsatisfiable — the reference pattern node has 47 such items). Registration MUST be feature-detected: with no document.modelContext the page MUST work unchanged in plain JavaScript, and no tool may require a network call, a key or a server. On the WebMCP transport propose and remember are local-only: they MUST return the Proposal payload to the caller and MUST NOT perform any network write, MUST NOT read or honour channels[].publish, and the auto mode of AGSC-01-31 is unavailable to this transport — a browser page holds no configuration authority and no forge identity (AGSC-08-04, AGSC-08-26(f)). Byte-identity with the stdio transport (this rule's first sentence) is asserted over the returned payload, not over any side effect. [PRD-051, AGSC-09-13]

9.4 Error-code registry

Codes are AGSC-E<nnn> and nothing else; the hundreds digit is the area (0 CLI, 1 PARSE, 2 SCHEMA, 3 LINK, 4 LINT, 5 PROV, 6 DET, 7 LEDGER, 8 COMPOSE, 9 IO). No other code format (AGSC-<AREA>-<nnn>, AGSC-DET-nnn) exists anywhere in this system; prose or a diagram using one is a defect of that document.

Precedence. Where two codes could name one fault, the more specific one wins: AGSC-E203 is reported for every enum and tags.allowed violation, AGSC-E204 for every pattern violation and every minLength/maxLength violation, and AGSC-E201 only for a schema failure that no more specific registered code, in any block, names — a maxItems violation on a cluster's broader is AGSC-E308, not AGSC-E201. Two conforming engines therefore report the same code for the same input. Applying that rule to the one pair that was left open (settled at rc.5): an out-of-range value inside federation{}, chunks{}, contribute[], visibility or related[] is AGSC-E209, never AGSC-E201, because AGSC-E209 names exactly those objects and is therefore the more specific code; an engine MUST report one code, not both (AGSC-00-09, AGSC-09-11) (the two ids were added to this paragraph at rc.6, 2026-09-22: it is the one normative sentence of spec/01–11 outside every rule block, which is exactly the fault AGSC-09-91 makes tools/validate-spec fail on, so the validator that rule demands could not pass on the specification that demands it).

9.9 Independent validation tooling (added 2026-09-02)

  • AGSC-09-90 The reference 1.0.0 distribution MUST include (authored in October 2026) the tools/ validators of PRD-054, each runnable standalone — no import from src/; a validator MAY use the same pinned libraries as the engine (amended at rc.5: the earlier "no engine import beyond stdlib" was written before the engine was allowed pinned libraries at all, and what the rule protects is independence from the engine, not abstinence from libraries) — so that every normative artifact (schemas, spec text, ontology, vectors, well-known file, features, diagrams) is checkable by an independent party; any other distribution MAY substitute its own implementation of the same nine command contracts (same names, same flags, same AGSC-09-11 envelope, same codes), and a conformance claim names which it ran. A validator's --json output MUST be the AGSC-09-11 envelope with verb set to the tool's own name (validate-spec, validate-schemas, validate-ontology, validate-vectors, validate-wellknown, validate-features, validate-diagrams, and the generators gen-spec-html and gen-ns) and version set to the tool distribution's own package version (the envelope's spec_version member already carries the version validated against, so the two never duplicate); findings use the same finding object, the same (file, line, col, code) ordering (AGSC-09-10) and the same AGSC-E<nnn> codes. Seven validators and two generators therefore speak one diagnostic language, and no tool invents a shape. No further validator may be added for a job an existing validator already carries: the federation check of AGSC-10-12 is the --peer flag of tools/validate-wellknown, never a separate binary. A validator MUST fail, with AGSC-E901, when the inputs its contract names are absent, or are present and carry nothing it can validate — no file read, no rule found, no vector found; a pass MUST mean that something was checked, and each validator's human-readable summary MUST state how many input files it read, so that a reader can tell "nothing is wrong" from "nothing was looked at" (stated at rc.6, 2026-09-22: measured before the fix, three of this distribution's own validators reported pass with no findings over a spec/ whose two largest files were empty and whose others were binary, and two did the same for a directory that does not exist — a merge gate that cannot fail protects nothing). A declared vector area with no vector file is not a failure; tools/validate-vectors MUST report it as an informational count, and only a required vector's absence for a rule that names one is a failure; the two clauses do not conflict — one is about an empty area, the other about an empty input set. [PRD-054]

  • AGSC-09-91 tools/validate-spec MUST fail on: duplicate rule id; a rule id referenced but undefined; an error code used in spec/01–11 but absent from the §9 registry; a MUST/SHOULD sentence with no rule id; a trace tag naming a nonexistent PRD/D id; a code appearing in more than one registry row; a code used in spec/01–11 whose registry row does not name the rule that raises it; a registry row naming a rule id that does not exist (grouped-fault rows such as AGSC-E108 and AGSC-E401 stay legal — the hundreds-digit block, not the row, is the unit of precision); a spec_version literal in spec/, tests/vectors/** or docs/ that differs from the spec/00 declaration; a rule id <n>a that does not immediately follow rule <n>.

    Two carve-outs, stated at rc.5 so that the validator can ship:

    (a) Historical notes. A version literal that differs from the declaration is NOT a fault when it sits on a line that is plainly a record of the past — a line carrying, before the literal, one of the words at, since, amended, added, withdrawn, before, until, from, for, against, written, re-verified as a whole word, or a full date in YYYY-MM-DD form — so that the dated rc.2/rc.3/rc.4 notes in spec/**, docs/SPEC.md §8 and tests/vectors/README.md stay as written instead of being falsified. tools/count-artifacts implements exactly this carve-out and is the reference behaviour. (The last four words and the date test were added at rc.6, 2026-09-22: six of this distribution's own informative headers read "Written 2026-09-16 for the 1.0.0-rc.3 draft … re-verified against 1.0.0-rc.4", plainly records of the past with none of the eight words before the literal, and the validator reported ten errors that were false in substance.)

    (b) Trace brackets after a block. A rule whose text includes a table, a fenced block or an ABNF block carries its trace bracket after that block rather than at the end of its first paragraph — AGSC-01-28, AGSC-07-12, AGSC-08-06 and AGSC-09-11 are the four — and the "MUST/SHOULD sentence with no rule id" and trace-bracket checks MUST treat the bracket that follows the block as that rule's. A rule with no trace bracket anywhere is still a fault. (stated at rc.6, 2026-09-23: AGSC-07-12, AGSC-08-06 and AGSC-09-11 now also carry the bracket at the end of their first paragraph, the style AGSC-05-26 already used, because a reader that takes a rule's list item alone found none; the carve-out still admits a bracket after a block.) [PRD-054, NFR-03]

  • AGSC-09-92 CI MUST run all validators on every PR; a validator failure blocks merge like any Gate. [PRD-054, PRD-049]
  • AGSC-09-93 tools/validate-wellknown <url|file> MUST check: the response media type is application/linkset+json or a Link: …; rel="profile" header names the profile URI (AGSC-06-07); linkset is the sole top-level member; every relation name is registered or an …/rel#<name> extension URI of AGSC-06-10; every target attribute value is an array of strings; at --level 0 the absence of every digest/agsc-* attribute is accepted, and at --level 2 and above their presence is REQUIRED and each digest is recomputed over the fetched target — except on a node carrying agsc-visibility: ["restricted"], where AGSC-11-20 (as amended at rc.5) requires agsc-counts, agsc-bundle-hash, agsc-bundle-version and agsc-ledger-head to be absent and a validator MUST accept their absence and report their presence as AGSC-E210. At --level 2 and above a document whose node is not restricted MUST carry the …/rel#ledger link (AGSC-10-04), and its absence is AGSC-E202 (added at rc.6, 2026-09-24). Its --peer <url|file> flag performs the mutual-conformance check of AGSC-10-12 and MUST accept two local files so the check runs with no network. Its --json output is the AGSC-09-11 envelope with verb: "validate-wellknown". [PRD-054]
  • AGSC-09-94 run and trace are the two opt-in verbs of AGSC-09-07 and have no effect unless run.enabled is true in agsc.config.json (AGSC-01-18; default false); with it false both MUST exit 2 with AGSC-E004 — a configuration the tool cannot run against, AGSC-09-08's exit-2 class — and no run block is read (amended 2026-09-24: the sentence said AGSC-E001, the code registered for an unknown verb, on a verb the engine knows). run <slug> executes the fenced blocks of a Procedure whose info string is run and compares each captured result with the immediately following expect block (the two info strings are spelled as AGSC-02-22 spells them — corrected at rc.6, 2026-09-22: this rule wrote {run} and {expect} while AGSC-02-22, the rule that owns the item, writes run and expect, so an author could not tell which fence is runnable); the executable info strings, their restriction to procedure items and the rendering-hint status of every other info string are AGSC-02-22's. Execution MUST be refused unless the command's program name is listed in run.allow[]; it MUST run with no network, no shell interpolation, a scrubbed environment and a timeout, and it MUST NOT write inside the Bundle. A command whose program name is not listed is AGSC-E203 — run.allow[] is a closed operator list of exactly the shape that code names — and a captured result that differs from its expect block is AGSC-E602, a recorded result that the run did not reproduce (both stated at rc.6, 2026-09-22: the verb's two characteristic outcomes were named by no registered row, and AGSC-09-15 forbids minting a code where one fits). --dry-run MUST print the resolved command list and execute nothing. trace <file.json> is a pure function: it maps an already-captured agent-run record to an Episode item through the AGSC-01-22/AGSC-02-14 import path and executes no process. A trace record is a JSON object carrying at least started (an instant, AGSC-02-06), and OPTIONALLY ended, actor (AGSC-02-09), title, outcome (AGSC-02-07's enum), body and usage (AGSC-02-14); every other member is preserved under the x-<vendor>-<key> namespace of AGSC-02-05a (stated at rc.6, 2026-09-22: no rule, schema or vector said what a trace record looks like, so every member name was an implementation's guess and a record written for one engine would not import into another — which is the interoperability AGSC-01-22 exists to provide). Neither verb may be required by any conformance Level (AGSC-10-01…06). [PRD-001]
